# OA 与独立智慧办案集成

实施日：2026-11-15。OA 管理身份、组织、案件、个人文件与正式附件；独立项目 `/home/ubuntu/文档/likui/智慧办案-20261114` 管理任务、隔离 Harness、知识投稿和 WeKnora 索引。普通菜单只有“智慧办案”，知识库位于子系统内部。

## 已实现接口与约束

- `/api/v1/smart-case/config|launch|exchange|me|logout`：一次性授权码、PKCE 和后端兑换；独立短期会话每次重新验证 OA 会话、账号状态与入口权限。`sc_` 凭据仅能访问必要接口。
- `/api/v1/personal-files/uploads` 及 `/:uploadId/chunk|complete`：4 MiB 分片、偏移续传、幂等完成、磁盘容量检查；无整文件 10 MB 或 200 MB 上限。旧 base64 API 仅供兼容，新 UI 不使用它上传。
- `/api/v1/personal-files/:id/versions` 与版本原文：不可变内容、SHA-256、内容版本与元数据乐观锁。替换内容不删除旧版本。
- 文件共享沿用显式 ACL；同角色/部门不自动互见。发布授权与阅读权限分离，衍生成果递归检查源版本的发布权限。
- 全员文件管理仅超级管理员只读，并记录跨用户审计；不自动开放私人会话，也不自动给 AI 全库材料。
- `/api/v1/smart-case/cases` 与详情：实时 OA 案件范围、编号、名称、状态及主办律师。任务保存固定材料版本和案件上下文，关联改变需重新启动运行上下文。
- `/api/v1/smart-case/archive`：用户复核后的指定成果版本；实时 `case.file.manage`、案件范围和状态检查，禁止向关闭/归档案件写入；幂等重试不重复附件。失败不删除私人成果。

数据库迁移 `20261115030000`—`20261115034000` 已应用：集成会话、分片与内容版本、发布授权、来源链，以及旧知识入口停用。正式案件附件容量字段改为 Float 以支持大文件。

## 部署与入口

本机 OA 前端 3000、后端 7001；新工作台静态入口 5180；后端 5181、WeKnora 8093 仅绑定回环。任务由 bubblewrap 独立进程运行，网络、材料目录和会话均隔离。生产配置不进入源码。

三个集成用户服务为 `oa-smart-workbench`、`oa-smart-case`、`oa-smart-knowledge`，已 enable；`oa-main` 接管原有 OA 后端开发启动方式。数据库和 OA 前端仍沿用原部署方式，未宣称完成全部生产加固。

公网入口尚未切换：云端 SSH 要求微信扫码登录，未覆盖现有服务。外网 OA 会明确提示新入口未配置。需网关操作者配置独立 HTTPS 域名，转发到 5180，保留 WebSocket；同步两端公开 URL 并启用 Secure cookie。

新项目 `docs/integration/DEPLOYMENT.md` 包含构建、固定上游、配置、服务、权限配置及备份恢复说明；`docs/integration/VALIDATION.md` 记录实测结果和限制。

## 验证和恢复

单点登录、多用户隔离、超过 10 MB 的分片续传、成果版本更新、案件幂等归档、审核索引发布下架、真实模型与撤权连接关闭均有可复现检查脚本。完整结果以新项目验收记录为准，不能将局部通过解释为全部回归通过。

备份位于 `/opt/oa-system/backups`，含数据库、文件、知识索引及私密配置，按敏感数据保护。恢复演练只对独立临时数据库和临时目录执行。回退源码不应直接回退已写入的不可变版本数据；需配套一致备份和停写窗口。
