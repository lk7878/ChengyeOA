# 系统管理员与超级管理员权限设计

> 2026-09-14 向前扩展：新多维工作区按 [SPEC-COLLAB-20260914](../superpowers/specs/2026-09-14-feishu-aligned-collaborative-workspace.md) §6 与 [FTN-003](../spec/foundations/FTN-003-rbac-data-scope.md) 授权。下文管理员配置与审核表适用于系统治理能力；普通个人视图及授权资源内自建表/字段/共享视图可直接保存、版本化审计。核心业务规则、权限扩大、敏感级别降低、已有值类型迁移仍适用高风险治理；资源管理权不授予敏感内容读取权。原治理实现与验收保持历史事实，新分层尚待实施。


## 1. 定位

- 系统管理员：系统配置和业务干预的最高执行角色。
- 系统超级管理员：系统治理、授权和审核的最高监督角色。

两者均不允许绕过审计或直接修改数据库。

## 2. 权限边界

| 能力 | 系统管理员 | 系统超级管理员 |
|---|---|---|
| 逻辑表格、视图、动态字段 | 配置 | 配置、审核、回滚 |
| 模板、字典、SOP、自动化 | 配置 | 配置、审核、回滚 |
| 普通角色与权限 | 配置申请 | 审核、发布 |
| 系统管理员账号 | 无权创建/授权/停用 | 管理并审核 |
| 超级管理员账号 | 无权操作 | 需另一超级管理员审核 |
| 数据干预 | 发起并执行已批准命令 | 审核、撤销、回滚监督 |
| 审计日志 | 查询 | 查询、导出、监督；均不可修改删除 |
| PostgreSQL 物理结构 | 无权 | 无权；仅代码迁移流程可变更 |

## 3. 风险分级

| 级别 | 示例 | 生效方式 |
|---|---|---|
| LOW | 文案、显示顺序、非敏感提示 | 立即生效，事后复核 |
| MEDIUM | 模板发布、普通字典、视图调整 | 可配置为事前审核 |
| HIGH | 字段停用、状态机、SOP 删除、自动化关闭 | 超级管理员事前审核 |
| CRITICAL | 权限调整、核心数据干预、敏感批量导出 | 事前审核并二次确认 |

## 4. 禁止事项

1. 管理员不得审核本人发起的操作。
2. 系统管理员不得修改本人角色或获得超级管理员角色。
3. 任何管理员不得关闭、删除或修改 AuditLog、EventLog、AdminOperationReview。
4. 任何管理员不得直接连接生产数据库修改数据或结构。
5. 超级管理员审核权限不自动授予 L4 内容查看权。

## 5. 数据干预

数据干预只能选择预置 command，例如 `reassign_owner`、`correct_status`、`repair_relation`、`recalculate_summary`。请求必须包含对象、原因、前快照、预期后快照、影响分析和回滚方式。

执行流程：草稿 → 事前审核 → 执行 → 结果校验 → 完成；失败时保留现场并允许受控回滚。

## 6. 管理员账号治理

- 至少保留一个有效超级管理员；生产建议配置两名以上。
- 管理员授权支持有效期，临时授权到期自动回收。
- 管理员登录建议启用 MFA；异常地点、设备或连续失败触发预警。
- 离职、停用或岗位变更时立即回收管理员角色和活动会话。

## 7. 审核记录

AdminOperationReview 必须记录申请人、操作类型、风险级别、目标对象、变更差异、影响范围、审核人、意见、生效方式、执行结果和回滚关系。

## 8. 验收用例

- 系统管理员提交高风险变更，审核前业务不生效。
- 系统管理员不能自审、不能给本人提权、不能授权超级管理员。
- 超级管理员拒绝操作后，配置或数据保持原状。
- 已发布配置能够回滚，前后版本和审计记录完整。
- 管理员尝试直接调用未授权干预接口时返回权限错误。
