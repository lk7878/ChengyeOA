# 数据库核心表设计草案

> 基线：承业律师事务所综合管理 OA 系统 PRD V1.0  
> 数据库：PostgreSQL  
> ORM：Prisma

## 1. 设计原则

1. 采用模块化单体、单 PostgreSQL 实例，不按分所拆库。
2. 业务表使用 UUID 主键，另设可读业务编号；外键引用 ID，不以名称关联。
3. 通用审计字段：`created_at`、`created_by`、`updated_at`、`updated_by`、`deleted_at`、`version`。
4. 金额使用 `numeric(18,2)`，时间使用 `timestamptz`，结构化扩展数据使用 `jsonb`。
5. 核心状态使用稳定英文编码，中文名称由业务字典维护。
6. 核心数据软删除；AuditLog、EventLog、审批记录、收款记录不得业务删除。
7. 多分所隔离依赖 `organization_id`、`branch_id`、`team_id` 与 DataScope，不使用数据库租户隔离。

## 2. 表域设计

| 表域 | 核心表 | 关键关系 |
|---|---|---|
| 组织权限 | Organization、ProfessionalTeam、Position、Employee、User、Role、Permission、UserRole、RolePermission、DataScope、FieldPermission | Organization 自关联；Employee 绑定 User；User 多角色 |
| 系统配置 | SystemConfig、DynamicFieldConfig、TemplateConfig、ConfigVersion、ConfigPublishRecord、AdminOperationReview、DataInterventionRequest | 配置按版本发布；管理员操作关联审核 |
| 品牌运营 | BrandChannel、Campaign、BrandContent、LawyerIpAccount | Campaign、Content 关联 Channel 和负责人 |
| 线索销转 | Lead、LeadFollow、LeadPool、LeadAssignmentRule、Appointment、Negotiation | Lead 关联来源、负责人、邀约、谈案 |
| 客户主数据 | Customer、Contact、ReferralRelation、CustomerMergeRecord | Lead 转 Customer；Customer 多联系人和合同 |
| 合同财务 | Contract、ContractTemplate、ContractNumberRule、PaymentPlan、Payment、InvoiceRequest、RefundRequest、CostEntry | Contract 多应收；Payment 核销 PaymentPlan |
| 分析交付 | AnalysisEngagement、MatterAnalysisReport、Matter、MatterMember、MatterNode、MatterTask、MatterNodeRequirement | 正式合同生成 Matter；Matter 按节点生成任务 |
| 质量知识 | QualityReview、SatisfactionSurvey、SpecialAnalysis、ReviewReport、KnowledgeAsset | Matter 关联质控、满意度、复盘、知识资产 |
| 文件 AI | FileObject、AudioRecording、TranscriptionJob、AiExtractionResult、AiProviderConfig、AiPromptTemplate | 文件关联业务对象；录音产生转写与提取版本 |
| 人事培训 | AttendanceRecord、LeaveRequest、TrainingPlan、TrainingRecord、PerformanceReview、PerformanceConfirmation、ValueAssessment、EquipmentAssignment | Employee 关联人事记录 |
| 事件审批 | EventLog、EventSubscription、EventDelivery、EventHandlerLog、ApprovalDefinition、ApprovalInstance、ApprovalTask、ApprovalCc、Notification、CallbackAction | EventLog 驱动投递、审批、通知 |
| 审计自动化 | AuditLog、AutomationRule、AutomationExecution | 所有高风险操作写 AuditLog |

## 4. 约束与索引

- 唯一约束：organization.code、employee.employee_no、user.username、lead.lead_no、customer.customer_no、contract.contract_no、matter.matter_no、event_log.event_id。
- 幂等唯一键：Payment 的外部流水号、CallbackAction 的 callback_key、AutomationExecution 的 rule_id + event_id。
- 高频索引：状态 + 负责人、分所 + 创建时间、客户 + 状态、合同 + 收款状态、案件 + 团队 + 状态。
- 模糊查询：客户姓名、联系人、案件编号可使用 `pg_trgm`；电话号码以规范化值和 Hash 精确检索。
- JSONB 索引仅用于稳定查询路径，不对所有扩展字段建立通用 GIN 索引。
- 外键删除策略默认 RESTRICT；附件关联、日志和历史快照不级联删除。

## 5. 数据一致性

1. 业务对象变更与 EventLog 使用同一事务写入。
2. 合同生效、应收计划、分析委托或案件建档使用同一事务。
3. 收款确认同步更新 Payment、PaymentPlan、Contract，统计异步刷新。
4. 配置发布同步写 ConfigPublishRecord、审核结果和 `config.published` 事件。
5. 数据干预必须保存前后快照并支持受控回滚。

## 6. Prisma 实施约束

- 核心字段写入 Prisma schema；动态字段数据存元数据表与受控 JSONB 扩展区。
- 禁止配置中心直接执行 DDL；物理结构仅通过 Prisma migration 变更。
- migration 必须包含正向脚本、数据转换、验证查询和回滚说明。
- 枚举优先使用字典表或字符串编码，避免频繁修改 PostgreSQL enum。
