# 角色权限与数据范围设计

> 2026-09-14 向前扩展：新多维工作区按 [SPEC-COLLAB-20260914](../superpowers/specs/2026-09-14-feishu-aligned-collaborative-workspace.md) §6 与 [FTN-003](../spec/foundations/FTN-003-rbac-data-scope.md) 授权。下文管理员配置与审核表适用于系统治理能力；普通个人视图及授权资源内自建表/字段/共享视图可直接保存、版本化审计。核心业务规则、权限扩大、敏感级别降低、已有值类型迁移仍适用高风险治理；资源管理权不授予敏感内容读取权。原治理实现与验收保持历史事实，新分层尚待实施。


## 1. 权限模型

采用 `RBAC + DataScope + FieldPermission + SpecialPermission + Audit`：

```text
允许访问 = 菜单可见 AND 操作允许 AND 数据范围命中 AND 字段允许 AND 特殊权限通过
```

拒绝优先于允许；L3/L4 数据必须再次校验字段权限和访问目的。

## 2. 角色层级

| 角色组 | 默认范围 | 核心能力 |
|---|---|---|
| 系统超级管理员 | 全所 | 管理员授权、高风险审核、配置回滚、全量审计监督 |
| 系统管理员 | 全所 | 配置中心、权限配置、SOP、模板、自动化、受控数据干预 |
| 管理层 | 全所或分管范围 | 驾驶舱、经营管理、重大审批、质控 |
| 中台部门 | 授权跨分所范围 | AI、知识、培训、品牌和专业支持 |
| 分所负责人 | 本分所 | 本分所人员、业务和经营数据 |
| 业务角色 | 本人/团队/分所 | 按客服、邀约、谈案、承办、财务、人事职责操作 |

## 3. 数据范围编码

| 编码 | 说明 |
|---|---|
| ALL | 全所 |
| HQ_SCOPE | 总所中台职责范围 |
| ORG | 指定组织及下级组织 |
| BRANCH | 指定分所 |
| TEAM | 指定专业团队，可跨分所 |
| SELF_AND_SUBORDINATES | 本人及下属 |
| SELF | 本人负责或参与的数据 |
| CUSTOM | 指定组织、团队、人员组合 |

数据范围在查询层强制拼接，不依赖前端传参。详情接口与导出接口必须复用同一范围校验。

## 4. 字段权限

| 访问级别 | 行为 |
|---|---|
| NONE | 不返回字段 |
| MASKED | 返回脱敏值 |
| READ | 返回原值 |
| WRITE | 可修改字段 |
| EXPORT | 可导出原值 |

L3/L4 典型字段：身份证、电话、合同金额、收款、录音、刑事材料、AI 案件事实。EXPORT 不随 READ 自动获得。

## 5. 特殊权限

| 权限编码 | 动作 | 风险级别 |
|---|---|---|
| customer.merge | 客户合并 | HIGH |
| contract.void | 合同作废 | HIGH |
| payment.confirm | 到账确认 | HIGH |
| refund.approve | 退款/减免审核 | HIGH |
| matter.intervene | 案件状态干预 | HIGH |
| file.sensitive.download | 高敏文件下载 | HIGH |
| data.bulk_export | 批量导出 | HIGH |
| config.publish | 配置发布 | MEDIUM |
| config.high_risk.change | 高风险配置变更 | CRITICAL |

## 6. 管理员职责分离

1. 系统管理员是最高执行权限，系统超级管理员是最高治理权限。
2. 系统管理员不得审核本人操作、修改本人角色、授权或停用超级管理员。
3. 高风险操作事前审核；低风险操作可立即生效，但必须事后复核。
4. 系统级治理操作写 AdminOperationReview 和 AuditLog；普通工作区资源配置按前述新分层版本化审计。
5. 超级管理员自身操作同样审计；涉及本人账号的操作由另一名超级管理员审核。
6. 紧急恢复账号只用于超级管理员全部不可用的场景，使用后强制改密并生成专项审计。

## 7. 权限判定流程

1. 验证用户和账号状态。
2. 汇总有效角色与临时授权，过滤过期授权。
3. 校验资源和动作权限。
4. 计算数据范围并注入查询条件。
5. 对响应字段执行 NONE/MASKED/READ 处理。
6. 对下载、导出、作废、干预等动作校验特殊权限和审核状态。
7. 写入访问日志或审计日志。

## 8. 验收要求

- 每个角色至少验证允许、拒绝、跨分所、跨团队、字段脱敏五类用例。
- 权限缓存变更后及时失效，禁用账号立即阻断访问。
- 用户界面隐藏按钮不能替代服务端权限校验。
- 权限追踪页面能解释权限来源、数据范围和临时授权有效期。
