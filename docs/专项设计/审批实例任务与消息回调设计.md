# 审批实例、任务与消息回调设计

## 1. 审批模型

| 对象 | 职责 |
|---|---|
| ApprovalDefinition | 定义表单、节点、审批人规则、抄送和版本 |
| ApprovalInstance | 一次具体审批及业务对象快照 |
| ApprovalTask | 节点内分配给某审批人的待办 |
| ApprovalCc | 抄送记录和已读状态 |
| CallbackAction | 消息卡片或页面操作的同步回调 |

## 2. 审批定义

审批定义包含 code、name、businessType、formSchema、nodeSchema、approverRule、ccRule、version、status。已产生实例的定义版本不得覆盖修改。

预置审批：合同作废/终止、退款/减免、客户合并、敏感批量导出、管理员高风险配置、业务数据干预、管理员授权变更。

## 3. 审批任务规则

1. 一个审批节点可配置单人、多人会签或任一人通过。
2. 审批人由指定人员、角色、上级、组织负责人或表达式规则确定。
3. 发起人不得成为本人高风险操作的最终审核人。
4. 已处理任务再次提交返回幂等结果，不重复推进实例。
5. 转交、加签、撤回和取消均记录原因和事件。

## 4. 状态

- ApprovalInstance：DRAFT、PENDING、APPROVED、REJECTED、WITHDRAWN、CANCELLED。
- ApprovalTask：PENDING、APPROVED、REJECTED、TRANSFERRED、EXPIRED、CANCELLED。
- CallbackAction：PENDING、RESPONDED、FAILED、ASYNC_PROCESSING。

## 5. 消息与待办

| 消息类型 | 内容 | 可执行动作 |
|---|---|---|
| 审批待办 | 申请人、对象、摘要、风险级别 | 同意、拒绝、查看详情 |
| 业务任务 | 客户/案件、节点、截止时间 | 开始、完成、转交 |
| AI 结果 | 录音、摘要、模型状态 | 确认、退回修改 |
| 预警 | 逾期、低满意度、事件失败 | 查看、分派、关闭 |

消息必须关联 objectType、objectId、routeUrl；支持未读、已读、待办、已办。

## 6. 同步回调

1. 回调校验登录态、签名、对象权限、动作权限、当前状态和 callbackKey。
2. 快速完成状态校验和落库，复杂处理通过事件异步执行。
3. 返回明确结果和可展示文案；失败不得静默。
4. callbackKey 唯一，重复点击返回首次结果。
5. 回调操作写 CallbackAction、AuditLog 和对应业务事件。

## 7. 超时与升级

- 审批任务支持截止时间和提醒策略。
- 超时可提醒本人和上级，不默认自动同意或拒绝。
- 管理员高风险审批超时保持未生效状态。

## 8. 管理员审核模式

- 高风险操作：事前审批，实例 APPROVED 后才执行。
- 低风险配置：先执行并创建 PENDING_POST_REVIEW 记录，超级管理员事后复核。
- 复核发现问题时，可停用配置、回滚版本并生成整改记录。

## 9. 验收

- 发起、审批、拒绝、撤回、转交、超时和重复回调均有测试。
- 禁止本人自审，禁止无权限用户处理任务。
- 审批通过与业务执行之间具备事务或事件一致性。
- 消息可从对象详情反查审批和回调记录。
