# 动态字段、表格与模板配置设计

2026-09-14 范围修订：本设计扩展到飞书式多维协作工作区。产品需求以 [MOD-002](../spec/modules/MOD-002-system-config-center.md) 为准，新工作区详细工程契约见 [SPEC-COLLAB-20260914](../superpowers/specs/2026-09-14-feishu-aligned-collaborative-workspace.md)；新增能力未实施。

## 1. 边界

工作区支持授权用户从空白创建独立数据表、配置字段和个人/共享视图；自建表为真实业务数据源，不限于给现有页面加字段。系统配置中心继续管理模板、字典、SOP 等治理配置。逻辑建表不直接执行 PostgreSQL DDL，核心字段由 Prisma schema 管理，不得普通配置改类型或业务语义。

## 2. 配置对象

| 对象 | 内容 |
|---|---|
| Workspace / Base / TableDefinition | 工作区、应用、可自建表及核心业务适配数据源 |
| ViewDefinition（承接原 TableViewConfig）/ UserViewPreference | 个人/共享视图、筛选树、排序、分组、列布局和跨设备偏好 |
| FieldDefinition（承接原 DynamicFieldConfig） | 稳定字段 ID、名称、类型、校验、默认值、选项、权限和结构版本 |
| Record / BusinessRecordExtension / RecordRelation | 自建表记录、核心记录扩展值、跨表关系 |
| RecordRevision / RecordComment | 业务变更历史和记录讨论 |
| TemplateConfig | 节点、材料、文书、审核、消息模板 |
| DictionaryConfig | 字典及选项 |
| SopConfig | 节点顺序、资料要求、默认角色、提醒 |
| AutomationRule | 事件、条件、动作、重试 |
| ConfigVersion | 版本、差异、生效范围和状态 |

## 3. 支持字段类型

TEXT、LONG_TEXT、NUMBER、CURRENCY、BOOLEAN、DATE、DATETIME、SINGLE_SELECT、MULTI_SELECT、USER、ORGANIZATION、PHONE、URL、FILE、RELATION。

受控公式、查找引用、汇总和双向关联纳入 P2，详见工程规格 §5；任意脚本和 SQL 仍不纳入。单向关联 P1 支持，目标包含授权的自建表与允许关联的核心业务表。不得以旧白名单限制阻止所有自建表间关联。

## 4. 字段属性

fieldCode 全局稳定；fieldName 可变。属性包括 required、defaultValue、validation、options、multiple、sensitivityLevel、fieldPermission、displayOrder、helpText、status。

字段产生数据后，类型变更必须预览转换结果、审核并迁移，不能直接覆盖或丢值。停用字段不再接受新值，历史值按权限保持可读和可审计。

## 5. 版本生命周期

以下草稿审核链仅用于系统级及高风险配置。普通个人视图和授权资源内自建表/字段配置保存后形成生效版本并留痕；记录、表结构和视图分别使用版本，发生冲突必须复核。

```text
DRAFT -> PENDING_REVIEW -> PUBLISHED -> DISABLED/ARCHIVED
                            -> ROLLED_BACK
```

每次修改从已发布版本复制新草稿。发布记录保存差异、影响范围、审核人、生效时间和回滚目标。

## 6. 审核规则

普通视图与授权自建表配置按 MOD-002 分层直接生效，下表适用于系统级治理；普通资源字段归档另需引用检查与审计，核心或高风险变更进入事前审核。风险取决于动作与数据，不因操作者同时具有管理员身份改变。

| 变更 | 风险 | 生效方式 |
|---|---|---|
| 文案、帮助、显示顺序 | LOW | 立即生效，事后复核 |
| 普通模板、普通字典选项 | MEDIUM | 可配置事前审核 |
| 字段停用、必填规则、数据级别 | HIGH | 超级管理员事前审核 |
| 状态机、SOP 删除、权限扩大 | CRITICAL | 事前审核、影响分析、二次确认 |

## 7. 发布流程

本节仅描述适用审核的治理配置；自助配置走版本检查、校验、保存与审计，不强制调用治理审批。

1. 系统管理员编辑草稿并执行配置校验。
2. 系统展示字段、页面、数据、权限、规则和历史案件影响。
3. 提交 AdminOperationReview。
4. 审核通过后原子发布版本并产生 `config.published` 事件。
5. 消费端按版本刷新配置缓存。
6. 异常时回滚到上一已发布版本。

## 8. 模板文件

模板保存元数据和 FileObject 引用。替换模板生成新版本，不覆盖旧文件；历史案件继续引用原版本。

## 9. 数据存储

- 核心业务字段进入物理列。
- 通用自建表 Record 与核心记录 BusinessRecordExtension 保存受控 JSONB 字段值，以稳定 fieldId 索引并记录结构/记录版本；核心字段不重复保存为通用真值。
- 高频查询的动态字段经专项评审后建立表达式索引或迁移为核心字段。

## 10. 验收

- 草稿不影响生产视图。
- 高风险配置审核前不生效。
- 已有数据字段不能物理删除或无迁移改类型。
- 发布和回滚后页面、权限、自动化与版本一致。
- 历史案件能够读取创建时的模板和 SOP 版本。
