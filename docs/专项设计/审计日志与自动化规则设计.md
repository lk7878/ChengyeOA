# 审计日志与自动化规则设计

## 1. 审计目标

审计用于回答谁在何时、以什么权限、对哪个对象、做了什么、前后发生何种变化，以及操作是否经过审核。

## 2. AuditLog 字段

| 字段 | 说明 |
|---|---|
| id | UUID |
| actorId/actorRole | 操作人及当时角色 |
| action | 稳定动作编码 |
| objectType/objectId | 目标对象 |
| organizationId | 数据归属 |
| riskLevel | LOW/MEDIUM/HIGH/CRITICAL |
| beforeSummary/afterSummary | 脱敏前后摘要 |
| reason | 操作原因 |
| approvalInstanceId | 关联审批 |
| ip/userAgent | 客户端信息 |
| requestId/traceId | 请求与链路 ID |
| createdAt | 操作时间 |

## 3. 必审计动作

- 登录、登录失败、退出、MFA 和管理员账号变更。
- 角色、权限、数据范围、字段权限和临时授权变更。
- 客户合并、合同作废、退款/减免、收款确认、案件状态干预。
- L3/L4 数据查看原值、下载、导出和外发。
- 配置草稿、审核、发布、停用、回滚和影响分析。
- AI 转写、提取、人工修订和确认。
- 事件人工重试、审批处理、回调失败处理。

AuditLog、EventLog、AdminOperationReview 不提供业务删除接口。归档后仍可按对象和 traceId 查询。

## 4. 自动化规则模型

AutomationRule 包含 code、name、eventType、filter、actions、effectiveScope、priority、status、version、retryPolicy。

允许动作白名单：创建任务、发送通知、创建审批、设置标签、分配负责人、生成材料清单、启动 AI 任务、写入统计队列。自动化规则不得直接修改合同金额、确认收款或删除数据。

## 5. 预置规则

| 规则 | 触发 | 动作 |
|---|---|---|
| 新线索分配 | lead.created | 去重、分级、分配、通知 |
| 首响提醒 | lead.assigned + 超时 | 提醒本人和主管 |
| 到访准备 | appointment.visited | 创建谈案任务和录音登记 |
| 首签生效 | contract.first_signed | 应收、材料清单、分析委托 |
| 录音转写 | audio.uploaded | 创建 TranscriptionJob |
| AI 提取 | audio.transcribed | 创建 AiExtractionResult 任务 |
| 正式签约 | contract.formal_signed | 应收、案件、SOP 任务 |
| 回款逾期 | PaymentPlan 到期 | 提醒谈案、财务、主管 |
| 低满意度 | survey.low_score | 创建专项分析和管委会通知 |
| 结案 | matter.closed | 满意度、复盘、知识资产任务 |

## 6. 执行与重试

1. AutomationExecution 以 ruleId + eventId 唯一，防止重复执行。
2. 动作按声明顺序执行，关键动作失败时停止后续动作并进入重试。
3. 重试超过上限进入人工队列，不自动回滚已完成的合法业务事务。
4. 规则测试模式只展示命中对象和拟执行动作，不产生业务写入。

## 7. 配置治理

- 规则修改通过 ConfigVersion 管理。
- 关闭核心规则、扩大数据范围或增加高风险动作必须事前审核。
- 发布前执行影响分析和样例事件测试。
- 规则发布、失败、人工重试和停用均写审计日志。

## 8. 验收

- 重复事件只执行一次。
- 无权限规则不得读取或操作范围外数据。
- 规则失败可定位到事件、规则版本、动作和错误。
- 高风险规则未经审核不能发布。
