# 个人文件回收站彻底删除

回收站每行新增“彻底删除”，显示文件名和不可恢复提示，经确认后执行。取消不会发送删除请求。只有文件所有者可以彻底删除已进入回收站的文件；共享管理者和全局审计管理员不能据此删除他人的文件。

## 删除范围与一致性

- 删除个人文件记录、全部内容版本、发布授权、对应上传会话，以及当前/历史版本的磁盘文件和上传分片。
- 单独保存的正式案件归档、知识库副本保持独立；原有审计和来源链引用不伪造、不改写。
- 先以数据库事务保存清理凭据，再移除磁盘文件。磁盘清理失败时，回收站显示“重试彻底删除”，禁止恢复，服务重启后仍可继续清理。
- 清理完成后保留最小完成凭据和操作审计，重复请求不会再次执行删除。
- 文件树锁、版本校验和上传锁共同防止恢复/更新/删除竞争；上传开始时在文件树锁内重新验证文件，避免为已删除文件创建新的上传会话。
- 若磁盘对象还被其他个人文件引用，拒绝清理，避免误删。

## 接口与数据库

`POST /api/v1/personal-files/:id/purge`，请求 `{version:number}`。

## 多选与清空回收站

回收站增加勾选、多选“彻底删除所选”和“清空回收站”。两者都显示文件数量、名称和不可恢复提醒；清空前重新读取当前回收站，提交的是用户确认的完整文件 ID / 版本列表，覆盖列表分页。确认后新移入回收站的文件不会被意外加入本次删除。

新增 `POST /api/v1/personal-files/purge`，请求 `{files:[{id,version}]}`，返回 `{count,failed}`。整批权限和版本检查、清理凭据及元数据变更在同一事务内完成；任一项验证失败则整批回滚，尚未触碰磁盘。随后逐项清理物理文件，个别清理失败不妨碍其他项，失败项仍留在回收站可重试。单文件旧接口继续兼容。
