# MOD-009 满意度、复购与转介绍模块

## 1. 需求概述

满意度、复购与转介绍模块承接「结案到满意度和复盘」与「客户复购与转介绍」两条主链路的收尾环节，负责结案后客户满意度调查、低满意度专项分析触发、转介绍意愿与转介绍关系管理、老客户复购机会运营，以及口碑案例库的授权、脱敏、入库与品牌复用，支撑品牌宣传部对客户满意度调查和口碑案例库的统一负责。

| 编号 | 功能 | 需求 | 现状 |
|---|---|---|---|
| SAT-01 | 满意度调查 | 支持客户专业能力、服务态度、沟通及时性、结果满意度评分 | 待开发 |
| SAT-02 | 低满意度触发 | 满意度低于 80 分自动进入专项分析 | 待开发 |
| SAT-03 | 转介绍意愿 | 记录客户转介绍意愿评分 | 待开发 |
| REF-01 | 转介绍管理 | 记录转介绍人、被介绍客户、签约归因 | 待开发 |

| BRAND-01 | 口碑案例 | 支持授权、脱敏、入库、品牌复用 | 待开发 |

## 3. 业务规则

PRD §8.9 未单列业务规则小节。与满意度、复购与转介绍相关的业务规则分布在 PRD 其余章节：

1. 结案后发起满意度调查。（源自 §6.3 复购转介绍流程）
2. 满意度低于 80 分，自动触发管委会专项分析流程。（源自 §6.3、§8.7 规则 4）
3. 满意度正常或高满意客户，进入转介绍意愿评估。（源自 §6.3）
4. 老客户复购机会进入客户运营池。（源自 §6.3）
5. 专项分析流程不强制固定责任人、整改期限、复查结论和复盘入库规则，只记录触发原因、分析过程、处理结论和关闭状态。（源自 §8.7 规则 5）
6. 品牌宣传部负责客户满意度调查和口碑案例库。（源自 §8.9 正文）

## 4. 数据对象

核心数据对象涉及 `SatisfactionSurvey`（客户满意度调查，见 PRD §9 数据模型）、转介绍关系、老客户复购机会、口碑案例等。本模块当前无任何模型落地，`Satisfaction`/`Review`/`Referral` 等数据对象待建。

字段定义见 FTN-001。

## 5. 状态机

PRD §8.9 未显式定义本模块状态机。低满意度触发的「专项分析」处理状态（触发—分析中—处理结论—关闭）见 FTN-002 状态机字典。

## 6. 验收要求

- 事务验收：低满意度触发必须验证一致性。（源自 §14.1.5）
- 回归验收：结案到满意度和复盘主链路必须有端到端用例。（源自 §14.1.13）
- 端到端验收：建立轻量案件，完成节点任务、质控、满意度、低满意度专项分析或复盘入库。（源自 §14.2.6）
- 品牌与转介绍指标：转介绍线索数、转介绍签约率、口碑案例入库量等指标可统计。（源自 §3.3.8 品牌与转介绍指标）
- 接口验收：参数校验、权限校验、数据范围、分页、错误码、审计记录。（源自 §14.1.2）
- 权限验收：总所、分所、专业团队、个人四类数据范围至少各测一组。（源自 §14.1.4）
