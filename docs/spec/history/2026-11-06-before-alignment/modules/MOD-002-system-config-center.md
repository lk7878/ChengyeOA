# MOD-002 多维协作工作区与配置中心

## 1. 需求概述

本模块是员工日常使用的多维协作工作区及系统配置底座。明确参考飞书的数据表、视图、字段及协作方式，允许授权用户从左下“＋”创建实际业务表，在右侧总表和个人/团队视图中直接工作。提供字段、视图、协作和关联能力，并继续承载模板、字典、状态机、SOP 与系统级治理。

2026-09-15 增加[云盘资源中心](../../../../superpowers/specs/2026-09-15-feishu-cloud-drive-resource-center.md)与[G1 技术契约](../../../../superpowers/specs/2026-09-15-cloud-drive-g1-contract.md)：打开应用前以文件夹和统一资源列表组织 Base，所有角色使用同一界面，按权限展示资源和操作。文件夹不替代工作区、Base、数据表或组织树；现有表格编辑器和业务真值保持。

2026-09-14 前的“只配置已有业务对象＋管理员统一发布”范围已扩展。普通自建表/视图与高风险系统配置分层；本需求与 [SPEC-COLLAB-20260914](../../../../superpowers/specs/2026-09-14-feishu-aligned-collaborative-workspace.md) 作为向前开发输入，已有治理实现不因此被标记为完成新需求。

2026-09-15 进一步授权[全站统一与原 OA 重构](../../../../superpowers/specs/2026-09-15-feishu-unified-oa-refactor.md)：旧菜单、页面和组件组织与飞书式协作设计冲突时，以新设计为主，允许全面重构；首批优先全局及左侧导航，再逐项整合全部业务模块。知识库与智慧办案保留现有架构，优先仅适配入口与外层。该新增范围尚未实施，不计入下面既有能力的完成状态。

## 3. 业务规则

### 3.1 数据与视图

1. 工作区内可建立多维表格应用，应用包含多张数据表；表包含字段和记录，视图只保存展示规则。
2. 每张表创建默认“总表”；总表仍只显示访问者权限范围内的记录。个人视图不等于记录私有，当前用户筛选不等于权限。
3. 在任一视图修改记录，其他相关视图读取同一条记录；新增/修改后不符合当前筛选时应明确提示。
4. 字段类型与值属于表，筛选/排序/分组/列显隐属于视图；两类修改分别提示、保存和版本化。
5. 核心业务对象保留现有唯一数据源；自建表为独立可用数据源，不限于在已有页面加扩展字段。逻辑建表不直接执行数据库 DDL。
6. 核心字段不得通过普通配置改变类型和业务语义；签约、收款、审批等动作经领域服务执行。
7. 普通表之间可按权限建立关联并计算；受控公式纳入目标，任意脚本和 SQL 不纳入。

### 3.2 配置与治理

1. 员工保存个人视图直接生效；有建表/表管理能力者可在授权资源内自建表和管理普通字段、共享视图，不要求成为系统管理员。
2. 普通配置保存产生版本和审计，不强制套用系统配置的草稿审批链；共享配置并发修改需防覆盖。按资源能力授权，不按操作者的管理员身份强制升级普通操作。
3. 系统级模板、字典、SOP、核心字段和业务规则继续按风险治理；权限扩大、降低敏感等级、已有值字段类型迁移及核心业务干预事前审核。
4. 已使用字段、表采用归档并保留历史，先展示引用影响；类型变更先预览、迁移和校验，不能静默丢值。
5. 高风险配置草稿不影响线上；发布/回滚按版本执行。视图回滚只恢复配置，不还原权限或覆盖业务数据。
6. 系统治理审核不得自审；超级管理员信任根、授权及紧急恢复仍遵循原治理契约。

### 3.3 多人协作

1. 统一云端保存，记录、结构和视图配置分别使用版本检查；并发冲突保留本地输入并提示复核，禁止静默覆盖。
2. 记录提交成功后同步到其他授权客户端；在线状态与编辑提示不替代数据一致性。
3. 断线、保存中、失败、冲突、已保存均有明确反馈；重连去重、补齐变更并重新校验权限。
4. 分享、查询、编辑、统计、导出、关联、附件和推送均遵循同一授权边界。评论和@通知绑定记录，并检查接收者权限。

### 3.4 岗位与记录权限（2026-09-15）

1. 复用组织与人员中的岗位及有效任职；普通成员默认只读写自己创建的记录，岗位负责人默认查看授权组织与业务范围的全部记录。总表、个人视图及统计遵循同一边界；筛选不是权限。
2. 工作区所有者可委派资源管理员配置成员、岗位、应用与表权限；被委派者不能修改自己的工作区成员授权或授出授权管理能力。原权限中心继续管理系统角色、业务动作及敏感字段能力。
3. 岗位/任职变更或停用后重新鉴权；原 CRM 业务范围、工作区组织范围和资源权限始终取交集。记录创建人与当前负责人是两个独立概念。
4. 线索抽屉内的跟进、分配及状态调整经原领域服务执行，满足编辑权、业务动作权、记录范围及受影响字段权限；合法业务办理不同于 CFG-11 的高风险系统数据干预。
5. 扩展字段沿用业务记录的读取与更新范围、岗位和字段授权；记录与扩展版本共同防止覆盖。扩展必填在保存扩展信息时检查，不改写原 CRM 的新建/跟进规则；首次保存应用默认值，已有空值不冒充已回填。

## 4. 数据对象

新增工作区、应用、数据表定义、字段定义、视图定义、个人偏好、通用记录、核心记录扩展值、记录关联、讨论与变更历史等需求对象；定义见 FTN-001 和工程规格。工作区、应用、表、字段、视图、通用记录及版本/事件模型已落库；评论/自动化预留结构不代表功能开放。核心线索/跟进直接适配原表；扩展值与历史以数据表和原业务记录 ID 关联存储，已完成字段配置及读写。

## 5. 状态机

系统级与高风险配置使用以下配置版本发布状态机（CFG-07/08）；普通个人视图及授权自建表配置不经过此审批链，保存后形成生效版本，记录冲突或失败不生效。表/字段另有正常与归档状态：

- 草稿 → 提交审核 → 已发布（生效）/ 审核拒绝（保持未生效）→ 停用 / 归档 → 可回滚到历史版本。
- 高风险操作：草稿提交后须事前审核通过方可生效；低风险操作立即生效后进入事后复核。

状态机正式编码待 SPEC 立项后纳入 FTN-002 状态机字典统一管理。

## 6. 验收要求

- 配置验收：适用治理的动态字段、模板、字典、SOP 和自动化规则必须验证草稿、审核、发布、停用、回滚和历史版本读取。（源自 §14.1.9）
- 管理员治理验收：高风险操作审核前不得生效；低风险操作生效后进入复核；管理员不得自审或给本人提权。（源自 §14.1.10）
- 配置闭环验收：系统管理员创建适用治理的节点资料要求或动态字段后，完成提交审核、超级管理员通过、发布生效和版本回滚全过程。（源自 §14.2.10）
- 数据干预验收：系统管理员发起合同/收款/案件状态干预后，系统在超级管理员审核通过前不得修改业务数据；通过后保留前后快照和完整审计链路。（源自 §14.2.11）
- 接口验收：参数校验、权限校验、数据范围、分页、错误码、审计记录。（源自 §14.1.2）

- 多维协作验收：[SPEC-COLLAB-20260914 §10](../../../../superpowers/specs/2026-09-14-feishu-aligned-collaborative-workspace.md) 的 AC-01～18；P1 必须从空白建表走到两账号协作，不能仅测试固定线索表或列宽。
- UI 验收：左下建表入口持续可达，右侧视图/字段配置真实生效，桌面/小窗口/手机布局和键盘操作可用。目录排序仅移动有管理权限的表，搜索时禁用；断网提示优先于历史保存状态，草稿保留与重新鉴权同步执行。
- 阶段优先级：P1 自建表＋基础字段与个人/共享视图＋同步防覆盖；P2 计算、多类型视图、讨论与自动化；P3 深业务适配与迁移。P1 首批底座已实现，余项及 P2/P3 待实施。
