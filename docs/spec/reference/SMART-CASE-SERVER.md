# 智慧办案服务器工作区规格

更新：2026-11-07。适用范围只包含智慧办案、管理员统一模型连接和管理员知识库的只读插件接入。替代历史本机目录/OPFS作为主存储及个人配置模型的规划；OA其余模块保持原有规则。

## 入口与界面

沿用OA顶栏“智慧办案”和浮动工作台的移动、缩放、最小化/最大化机制。使用上游Harness原生AppFrame、SidebarRoot、ConversationRoot、InputBar、消息Markdown、问询和审批组件，主题封装于ShadowRoot。欢迎语及左上角不再显示鲸鱼标识；侧栏收起时显示菜单图标。

用户只有一个“个人办案空间 · 服务器”，不再选择本机目录、浏览器工作区或其他重复工作空间。侧栏显示会话，支持搜索、重命名（1–100字符）、归档/取消归档和删除/恢复；归档会话可阅读但需取消归档才能继续编辑/上传。删除同时隐藏其材料和消息，不物理销毁文件；恢复后重新可读。运行中会话必须先停止任务再修改会话属性。左下角提供材料/知识库和模型设置。

## 数据位置与生命周期

存储由OA当前认证用户ID确定，不接受浏览器指定owner、服务器路径或任意workspace路径。根目录来自 `CHENGYE_INTELLIGENCE_DATA_DIR`；默认 `var/intelligence`。

| 数据 | 保存位置/行为 |
| --- | --- |
| 管理员知识库 | 既有wiki目录，管理/编译授权保持不变 |
| 会话、消息、文件目录、幂等请求 | `case-server/<账号SHA256>/workspace.sqlite`，WAL事务；旧个人模型配置不再参与调用 |
| 组织模型配置 | `case-server/model-settings.sqlite`，加密保存及记录最后修改管理员/时间；同一OA部署共享 |
| 文件原件和成果 | 同一账号目录的UUID `.bin`，原文件名只作为数据库元数据 |
| 模型加密主密钥 | `case-server/credentials.key`；仅服务端读取，必须随数据安全备份 |
| 运行引擎 | 账号目录的engine子目录，受管IPC进程，无公开Harness端口 |
| 旧浏览器资料 | 用户已确认是废弃测试数据；进入智慧办案时，持原账号锁清理当前账号的旧OPFS智慧办案目录，旧入口/worker不再发布 |

新会话和材料不使用OPFS作为存储前提，不需要浏览器持久化授权，不因换浏览器/电脑丢失。旧测试资料按用户后续明确要求清理，仅针对当前账号的 `chengye-workspace-<origin+账号哈希>` 目录；不会清空站点存储或影响知识库、其他账号、新服务器会话。被旧页面占用时提示重试；其他浏览器需登录对应账号并打开智慧办案后完成清理。

会话“…”菜单在选择操作后立即收起，点击菜单外任意位置或按Esc也会收起；重命名无需再次点击“…”关闭。

后台生成不依赖浏览器保持打开。原生PersistenceCoordinator必须等待服务器确认写入再继续，保持事件顺序与重复写入核验。服务重启后已确认的消息/材料仍存在；中断任务不会自动重放外部模型请求，显示中断并允许用户继续发送。

## 上传与解析

支持TXT、Markdown、HTML、DOCX、XLSX、PDF、PNG、JPEG、WebP。文件名最多180字符，禁止路径分隔符、控制字符、尾随点/空格。单文件大于0且不超过200MB；每账号2GB总容量，已删除但可恢复的材料仍计入容量。

客户端每次只读4MB分片，Base64传输；服务端校验总量、偏移、内容、请求归属。相同上传ID、偏移和内容重试不重复写入。完成后写入原件，异步服务器解析；未完成上传超过24小时可清除分片。上传支持取消。

解析使用独立受限进程，最多并发2个、每个512MB堆、180秒超时；PDF最多500页，表格限制工作表/行/列，最终文本上限400万字符。图片和扫描PDF需服务器PaddleOCR配置并由用户勾选启用；解析失败不删除已上传原件，界面显示失败原因类别及重试入口。不能把“200MB可上传”解释为“任何200MB文件均必然解析成功”。

下载按4MB读取当前账号的原件，下载前及交付时重新验证权限。模型只通过当前会话文件清单及最多200行/60000字符的分段文本工具读取文件；生成文书只允许TXT/Markdown、最多10万字符，需用户逐次批准并另存新名称，不覆盖已有原件。

## 管理员统一模型配置

界面标题与入口统一为“AI模型配置”。具备智慧办案访问权限的系统管理员/超级管理员可配置、测试和清除组织API Key、Base URL和模型名称。普通用户只有是否已配置状态，无密钥、Base URL或模型配置入口；后端对管理动作独立复查当前系统管理员身份，不能伪造前端admin标志。旧个人凭据不再参与调用，也不自动升级为组织凭据。

API Key服务端AES-256-GCM加密、绑定组织配置用途，不回显密钥。留空保留同地址的已配置Key；改地址必须重新输入Key。管理员保存的配置优先于部署环境默认配置；清除后恢复部署默认，否则提示联系管理员。组织模型配置变更供所有获准用户下次发送使用，不共享私有材料或会话。

连通性测试使用弹窗未保存的值，允许同地址留空引用已保存Key。发送固定测试文本及无副作用工具声明，最多32输出Token、20秒、64KB响应；检查认证、模型请求及兼容流式输出，HTTP 200空响应/HTML不视为成功。明确提示密钥、模型/接口、额度、网络/证书及超时等失败；不显示上游原始错误或密钥，不写配置或正式业务记录。每管理员同时1次测试、全局2次，测试可能产生少量供应商费用。成功不代表已验证所有法律任务及完整工具执行。

支持HTTPS OpenAI Chat Completions兼容协议，模型需要支持流式输出和工具调用。Base URL不包含 `/chat/completions`、认证信息或查询参数。保存时和实际模型连接时校验DNS地址，实际请求固定已校验解析结果，拒绝重定向。普通用户不能连接未授权的内网/回环/链路本地地址；运维可通过 `CHENGYE_MODEL_ORIGINS` 显式声明内部HTTPS网关，保留TLS证书验证。

模型配置变更对下次发送生效，当前运行任务保持开始时的连接快照。会话记录实际模型名与 `chengye-legal@2026-11-07` preset版本，技能调用结果包含版本和内容哈希。兼容性不等于适配所有厂商私有协议。

界面明确告知：对话、材料提取文本和知识库引用会按任务需要发送到配置的模型服务。服务端存储不意味着模型本地推理。Key不进入前端持久存储或Git，接口/代理日志不得记录请求正文。

## 法律助手与权限

Preset组合中文法律persona、只读知识库工具、受限材料工具、法律技能和原生用户问询/批准。专业技能包含合同审查、应诉分析、管辖分析、中国法检索；不继承旧桌面编码助手的Shell、任意文件系统或服务器技能安装权限。

`menu.smart_case`控制智慧办案。每个接口从登录身份定位私有数据；超级管理员也不通过此接口越权读取别人会话。`menu.knowledge`另行控制知识库工具，每次访问重新校验当前权限和库的启用状态。长任务工具调用、事件交付、文件下载和解析结果提交均重新检查账号/权限；撤权或账号停用停止后续访问。

管理员在OA“角色与权限”勾选“智慧办案”，再在“账号管理”把该角色分配给指定用户即可授权；需只授予个别人时可使用独立角色。撤销角色/权限后接口拒绝后续访问。本次不改变全局权限目录或专项授权规则，不把“智慧办案使用权限”等同于模型管理权。普通SYSTEM_ADMIN也必须另有智慧办案菜单权限；SYSTEM_SUPER_ADMIN按既有规则拥有权限。

知识库由管理员维护，律师只能按授权只读检索；个人材料不自动入公共知识库。工具返回文件、行号和来源用于引用；事实、陈述、推断与缺失材料区分展示。原文中的指令不能扩大权限。AI输出仅为待律师核验的草稿，不直接修改正式客户、案件、合同、审批或财务记录。

## 并发、资源与失败处理

允许多页面读取；每会话最多一个运行任务，发送需匹配当前持久化revision；冲突拒绝覆盖。创建/发送使用请求ID去重；上传使用上传ID和偏移去重。客户端断线重连读取服务器事件和状态；事件窗口丢失或服务重启则重新读取持久化状态。

每账号最多4个运行任务，全局最多16个办案引擎，闲置10分钟回收；任务15分钟超时停止。解析不在OA主请求进程执行。部署目前固定一个OA Worker，尚未提供多节点分布式任务调度或跨节点共享存储，不得宣称水平扩展已经验收。

| 位置 | 必要性 |
| --- | --- |
| intelligence controller | 把现有case/events接口接到服务器存储；注入并复查OA当前授权，未增加对业务表的读写通道 |

| 智慧办案入口适配器 | 浏览器和旧桌面宿主统一打开同一服务器工作台，避免旧本机入口再次分流 |
| intelligence独立集成 | 私有存储、上传/解析、模型连接、会话UI与法律插件；不修改云盘、案件、合同、审批、财务业务服务 |

不变更OA正式数据库schema、不放宽OA全局上传阈值、不修改任何真实账号密码或权限、不清理既有业务数据。

## 人工验收步骤

1. 管理员打开智慧办案，确认无鲸鱼Logo，只有一个服务器空间；左下角可见AI模型配置。普通获授权用户可使用工作区但看不到该配置入口。
2. 新建会话并重命名；归档后在已归档中查看/恢复；删除后在已删除中恢复。
3. 上传超过20MB但小于200MB的受支持文件，观察上传进度、解析状态及下载原件；错误文件解析失败仍可下载原件。
4. 刷新浏览器、关闭再开、换浏览器登录同一账号，核对同一会话和材料；账号B不能读取账号A的会话ID和文件。
5. 管理员输入模型参数并测试，核对错误提示、成功状态与不自动保存；保存后刷新不回显Key。普通获准用户无需填写参数即可调用同一模型，其他账号材料仍不可读。AI模型配置弹窗支持按住标题栏用鼠标左键拖动，移动范围限制在可见区域，内容独立滚动；重新打开恢复居中，也可聚焦标题栏使用方向键移动、Home居中。
6. 生成文书先查看批准面板，批准后确认成果出现在本会话服务器材料列表；拒绝不得保存，原件不得覆盖。
7. 保持两个页面，验证同会话并发发送冲突，独立会话不串材料；撤销权限后读取和工具调用被拒绝。
8. 回归OA登录、云盘、案件工作表、审批中心；模型/OCR未配置时明确显示状态，不影响这些OA基础功能。

本轮自动验收和实际执行记录见 [验证记录](../VALIDATION-2026-11-07-smart-case.md)。真实供应商推理质量、OCR精度、200MB各类型极限以及生产备份恢复需在相应部署环境继续验收。
