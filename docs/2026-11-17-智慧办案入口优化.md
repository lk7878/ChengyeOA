# 智慧办案入口优化

## 行为

OA 顶栏和案件页仍在新标签打开 `/smart-case`，该路由保留登录和 `menu.smart_case` 权限守卫，但不再渲染主侧栏、导航和业务页面，只显示简洁连接状态；失败后可重试或返回 OA。

每次进入先通过 OA 认证 API 获取当前用户标识、服务地址；服务端明确检查 `menu.smart_case`，带案件参数时同时检查 `case.read` 和记录范围。再向智慧办案 `/api/me` 核对经服务端验证的 OA 用户标识：仅同一用户的有效会话直达 `/wb/`。不存在、失效或其他账号的会话均重新执行一次性 code 与 challenge/verifier 衔接。不会凭本地用户缓存或 Cookie 是否存在决定直达。

首次登录的同源流程在当前连接页准备校验信息并申请一次性凭证，随后仅导航到回调。旧版运行服务仍支持：通过 fetch 跟随准备接口的返回地址，严格验证返回源、路径和 challenge，不挂载或执行返回的 OA HTML，从而避免第二次完整页面渲染。新版智慧办案支持 `response=json`，进一步省去该后台 HTML 请求。跨源部署继续使用原有顶层跳转，不放宽 CORS 或 Cookie 限制。

案件入口保留 caseId，原有一次性凭证、原 OA 会话撤销、账号停用、角色权限撤销、verifier 验证和白名单返回地址机制保留。所有导航使用 replace，重试不再额外打开标签。
