# SOP 与质检人工试用

范围：SPEC-SOP-QC-20260916，SQ1–SQ7。实现与自动化结果以[阶段计划](../plans/2026-09-16-sop-quality-control.md)和[规格](../specs/2026-09-16-sop-quality-control.md)为准。

## 1. 环境和账号

打开现有项目桌面端，使用原登录方式。开发库保留已有业务数据，不自动导入演示客户、案件、SOP实例或质检批次。以下新增记录请在隔离测试环境进行，统一使用“SQ人工试用”前缀，材料用虚构文本。

准备管理员、普通承办、团队负责人、独立质检员四个有效账号；员工任职及专业团队成员关系必须有效。模板发布需要两名分别获权、完成MFA的治理参与者，可以由管理员和负责人承担，但同一人不能申请并审核自己的发布。审核人不能同时担任被审核成果的提交人/本轮执行人，整改复核人也必须独立。

管理员在原组织与人员、权限中心配置岗位和数据范围。先配置菜单与动作，再配置对应资源范围；工作区授权和业务权限取交集。普通用户用SELF，本团队负责人用TEAM或明确的组织范围；确需全部组织数据的负责人再授予ALL。共享视图或“总表”本身不会扩大权限。

| 岗位 | 本轮能力 | 关键范围与依赖 |
| --- | --- | --- |
| 普通承办 | 查看/执行任务、提交成果、查看必要报告；可按岗位授权上传材料、提交整改 | sop_task的SELF或管理员明确分派的对象协作；前期材料另需sop.material.read/manage及lead.read或contract.read；案件文件另需case.file.read/manage及其范围 |
| 团队负责人 | 启用/管理实例、分派任务、查看团队共同表；按授权承担一级审核 | sop_instance/sop_task/template的TEAM或ORG；案件启用另需case.read、case.task.manage；线索启用另需lead.read/update；分析委托启用另需contract.read |
| 独立质检员 | 抽检、记录二级检查、查看问题、独立复核、分析专项 | quality.*所用case范围与case.read交集；一级审核另外使用sop_task范围、quality.review.decide及approval.process；材料读取仍单独授权 |
| 管理员 | 模板草稿、岗位授权、治理发布/停用、配置策略和排查审计 | 管理权限不免除自审回避、冻结版本或原审批要求；组织/团队/人员候选还要相应原主数据读取权限 |

任务被明确分派后，承办可查看必要任务内容；这属于管理员设置的对象协作，不代表能看到整个案件或前期材料。调岗使旧对象授权失效，负责人需重新分派。若菜单或候选为空，先在权限中心核验菜单、动作、资源范围和有效任职，不要用共享表绕过。

## 2. 建立和发布模板

1. 管理中心进入“SOP模板”（`/admin/sop-templates`）。选择医疗、执行或刑事预置，新建草稿，填写真实测试组织、专业团队、案件类型。
2. 医疗和执行各9个主节点，刑事12个。保持默认可并行、资料非强制；在一个节点显式配置必需材料和审核，另一个节点配置依赖、期限提醒，保存。
3. 申请发布，到原治理中心由另一获权人审核执行。普通承办不能发布，申请人不能自审；发布后内容不可直接覆盖。
4. 复制历史版本，修改后重新发布。已启动实例仍绑定旧版；停用阻止新启动，不修改旧实例。

通过标准：草稿、发布版本、治理记录能互相定位；重复操作不生成重复版本，旧实例节点不跟随新版本漂移。

## 3. 案件任务与同源共同表

1. 用类型、组织、团队均匹配的测试案件，在原案件详情点击“启动SOP流程”。选择已发布模板，检查本次节点及批次，确认启动。
2. 重复相同批次不重复生成任务；要另开一批须明确填写新批次。未知组织案件先走原归属补录，不会被自动归组。
3. 在“SOP任务”进入已有同源工作表；如未配置工作表，由获权管理员在工作区左下“新建”选择SOP任务业务来源。左侧是表目录，顶部是公共/个人视图及字段、筛选、分组、排序；同一行与详情使用同一个任务ID。
4. 负责人分派一项任务。普通承办打开“分派给我”个人视图并办理，负责人同时查看变化。承办不应看到其他未获权任务，打开他人直链仍应拒绝。
5. 测试开始、改期、暂停/恢复、跳过、取消及依赖。普通承办不能使用负责人管理动作；配置强制审核的节点不能直接点完成绕过。
6. 对同一任务用两个窗口保存不同版本。后保存者得到冲突并保留输入，刷新核对后再提交；断网提交失败保留输入，恢复后可重试。

通过标准：总表、个人视图、详情、统计始终服从当前权限；没有复制出另一份任务状态。撤权后页面刷新清除已失权内容。

## 4. 材料、报告和一级审核

1. 普通承办开始办理，上传测试材料，点击“提交节点成果”，填写报告、选择必需材料和独立审核人。没有合格候选时保持待分派，不能自动通过。
2. 审核人从成果详情进入原审批中心，先退回并填写依据。承办重新开始、修订并提交，第二次生成新修订；第一版报告和附件引用保留。
3. 审核人填写材料/报告检查清单并通过原审批。节点只有在业务同步成功后才完成。原审批同步失败可在原台账修复重试，不能将“审批已通过”误当“节点已完成”。
4. 查看专家指导记录：指导不能替代审核。尝试自审、删除已冻结材料、重放旧审批或读取无独立文件权限的附件，均应拒绝。
5. 若模板显式配置结案门槛，未通过节点应阻止原案件结案；没有配置门槛的旧案件保持原行为。

## 5. 真实前期来源与签约后接续

1. 在线索详情点击“启动前期SOP”，明确勾选本次适用节点。前期不能省略节点选择，勾选依赖节点时必须包含前置节点。
2. 在前期任务上传虚构材料并执行一轮退回重提。此时不应自动产生案件或合同，材料归原实例，单文件不超过10MB。
3. 沿原线索转客户、分析委托合同签署生效流程操作。到该生效合同详情点击“启动分析委托SOP”，选择分析阶段节点。
4. 沿原风险告知及正式合同流程真实建案；正式合同保留真实分析委托来源。补齐真实案件类型、组织和团队后，从案件详情启动后续节点。
5. 在前期实例的“签约前后接续”选择“关联后续流程”，选择真实同客户的获权后续实例，填写接续依据。冲突时保留依据，点击“刷新接续候选并采用最新版本”后提交。
6. 检查原前期任务ID、状态、报告修订及材料仍在原处。接续不代填完成、不复制材料；仅有后续案件文件权限的用户不能读取前期材料。
7. 医疗、执行、刑事各走一条链路，至少包含一次退回重提。刑事预置资料默认不强制，只有明确发布配置后才成为门槛。

## 6. 月度二级抽检与整改

1. 管理中心“抽检策略”（`/admin/quality-rules`）配置策略版本，指定组织、可选团队、数量/比例、是否按团队分层及检查项。在质量管理“抽检批次”选择有测试已结案件的月份建立批次；默认上月。
2. 重复相同策略、范围、月份、批次应返回同样样本。零候选显示零，候选不足取实际数量；补抽填新批次和原因，不重复已抽样本。分层配置的数量/比例分别应用于各团队。
3. 独立质检员记录检查事实，将一项标为不合格并填写依据，生成问题单。一级审核的批准事实保持不变。
4. 负责人分派整改；承办提交整改说明及获权附件；独立复核人先退回，再验收通过。历史整改版本保留。
5. 对比已结案件状态、版本及财务记录：质检和整改不应重新开启或修改原案件生命周期。

## 7. 满意度专项与提醒

1. 在案件百分制评估入口分别记录79、80、空分，填写来源、日期及证据说明。79经原事件处理生成唯一专项，80和空分不生成；旧1–5星级原值不变。
2. 专项填写分析过程和结论，申请关闭，由独立获权人到原审批中心退回；修订后再次申请并通过。更正评估保留旧版本及触发事实，不能删除历史来消除低分。
3. 给SOP节点配置提醒后改期，核验旧版本提醒不再发送；暂停、离职或撤权后不应收到敏感内容。通知是站内泛化待办，点击后定位原对象并重新鉴权。
4. 查看质量指标：仅统计当前获权业务；没有权限的指标不显示，不伪装为0。“案件SOP节点”不包含前期任务，前期范围在SOP共同表查看。

## 8. 界面与桌面保护

在1440、1024、390宽度查看表格入口和办理页，检查窄屏无页面横向溢出、按钮可操作。用Tab移动焦点、Enter打开接续和提交按钮；测试空列表、加载、失败、离线、刷新及撤权。

桌面端检查OA首页、知识库、智慧办案入口及返回导航。SOP/质检不替换原Wiki或Harness；现有智慧办案目录授权、账号边界、原生会话保留。该轮不包含MAT-04B主动归档、任意BPMN/脚本设计器、看板/甘特增强或自动对外通知。

首期候选有明确上限：审核人500、接续候选最近100、材料每页100；过多数据应按业务范围缩小或翻页。自动化的100会话负载是注明机器/CPU条件的本地通用协作结果，不代表真实多设备部署或SOP专属超大数据量容量。

问题反馈请记录账号岗位、页面、操作步骤、预期/实际结果、错误码和时间；不在反馈中粘贴真实客户材料或登录凭据。
