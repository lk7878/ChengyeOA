## 1. 最新授权与优先级

用户要求全部原 OA 功能统一到参考飞书的新设计，冲突处以新设计为主，明确允许大范围推翻和重构，尤其是 UI 左侧功能区；知识库和智慧办案尽量不大改架构。先 spec，再计划、实现、验证和本地提交。

承接已有云盘 G1/G2-A/G2-B，不重做已经验收的目录、权限、生命周期和导航能力。全站统一作为下一条主线，优先于尚未开始的上传/模板等孤立扩展。保留主会话当前变更和验收证据；若当前批次仍在收尾，先形成清晰检查点再进入本计划。

## 3. 技术选择与风险边界

- 可替换旧页面、路由结构、组件和后端实现；不把“复用现有代码”解释为不能重构。满足需求时优先利用已有云盘、网格和授权基础。
- 业务列表统一不能仅更换标题或嵌入旧页面。使用同源记录、共享配置/详情能力和一致操作反馈，专门业务动作继续经过明确校验。
- 迁移不删除真实数据、不重置数据库、不复制正式业务为第二份记录；先写兼容及回退契约，再做增量修改。
- 普通用户、负责人和管理员共用 UI；无权限内容在列表、搜索、统计、直链和接口均不可越权。不同入口可以进一步收紧权限，不得放大权限。
- 知识库与智慧办案维持现有核心架构及数据流。默认保留相邻顶栏入口，允许必要外层适配，不顺带重构 Wiki 索引/编译或 Harness 原生会话引擎。
- 不并行启动另一条代码重构线，不重复执行已通过且未受改动影响的检查。涉及协作热路径时按既有持续负载契约验证；单纯导航调整不自动触发完整负载重测。

## 4. 侧会话交付与主会话承接

侧会话修改范围：新增本规格与本计划，向需求总纲和 MOD-002 增加新基线及引用。未改动应用源代码，未运行应用测试或构建，未提交 Git。新增文档相对链接需在交接前核对。

主会话收到交接后阅读新规格，先执行 U0/U1，再推进 U2/U3 和后续业务整合；按既有用户授权完成阶段性本地 Git 提交，不自动推送或部署。不得将“已授权重构”或“文档已落盘”写为 UI 已完成。

2026-09-15 主会话完成首批全站框架。目录契约先于代码修改；U4–U7 的共同视图、记录详情及专属动作整合继续待执行。

### 实现

- App 使用一个持久 MainLayout 包含全部已登录真实路由。工作台、云盘、业务应用、数据分析、管理中心五入口共用，原业务 URL 保留；原首页仪表盘移入数据分析。兼容别名保留查询及片段，未知路由显式 404。
- navigation/catalog 统一入口、菜单/读取权限交集及路由守卫，目录和入口搜索按有效授权过滤；后台每 15 秒及焦点恢复刷新，不在成功刷新时卸载草稿，旧账号/令牌的后台响应不能写回。
- 80px 全局栏可展开；云盘与 Base 保留自身目录，不叠加业务宽侧栏；移动端使用导航抽屉。顶栏提供产品定位、入口搜索、相邻知识库/智慧办案、通知和账号。
- 知识库与智慧办案复用原组件及桌面桥，CaseWorkbench 与 DesktopKnowledgeBridge 保持原根级生命周期；没有修改 Wiki、Harness 核心、个人文件同步或桌面配置。
