# V1.3.0 阶段一：源码对齐与桌面集成技术验证

依据 [SPEC-AI-DESKTOP-20260913](../specs/2026-09-13-unified-desktop-local-harness.md)。用户授权先完成实施计划与可运行桌面基础，不把本阶段当作全部 V1.3.0 交付。

## 本阶段范围

1. 只读核对原生桌面壳、Product Profile、工作区选择、文件工具及会话持久化，形成复用清单。
2. 在 `integrations/intelligence/` 内增加桌面适配，复用导入源码，不修改原 C33，不复制实现一套聊天 UI。
3. 统一客户端打开 OA，右上角智慧办案入口打开或恢复同一本机 Harness 窗口；远端 OA 仅获得受限打开窗口能力，不能获得任意本地路径、命令、文件或凭据。
4. 使用明确的本地运行目录，通过正式 Product Profile 启动原生引擎，原生 UI 选择实际本机文件夹，验证读取、生成文件与重启恢复。
5. 记录启动、停止、重启、导航隔离及受限桌面桥接的验证结果，提供复现说明，并提交本地 Git。

## 不在本阶段实现

云端 Wiki 的新桌面连接、个人视觉 API 适配、主动归档、OA 离线草稿同步、完整安装器及无开发环境机器验收，均留待后续阶段；本阶段不移除已有浏览器数据或运行入口、不升级正式运行版本为 V1.3.0。

## 验证设计

- 启动失败、退出、异常 Host 退出、单实例与窗口恢复：验证进程清理和可见反馈，日志不泄露启动凭据。
- 安全边界：OA 页面无 Node 集成；本地桥仅允许打开智慧办案，校验调用来源；跨站导航、窗口打开不获得本机能力。
- 原生流程：工作区选择真实中文文件夹、原生会话与工具授权、读写文件、退出重启恢复会话和工作区。
- 模型验证使用明确隔离的测试模型或已配置服务，不能把脚本模型当作真实法律推理效果；材料仅使用临时测试文件。
- 构建与测试覆盖桌面适配、OA 入口和源码完整性；阶段验收不等于完整发布验收。

### 验证结果

- 桌面 esbuild 构建通过；OA 前端 TypeScript、变更文件 ESLint、生产 Vite 构建通过，生产构建保留既有大分块提示。
- OA 入口/窗口/Layout 3 文件共 13 项通过：本地桥选择、无桥时浏览器兼容、启动失败不切换存储方式、已有导航与窗口行为。
- 新增桌面策略 3 项通过：窗口/框架/来源校验、危险 URL 拒绝、云端凭据不继承及遥测关闭。
- 复用的原生桌面 4 文件共 16 项通过：Host 管理、导航策略、正式 Profile、关闭与退出生命周期。
- 真实 Electron 原生流程通过：从 OA 右上入口打开助手、Windows 原生选择中文文件夹、读取测试案情、原生模型工具生成 Markdown 并落盘；重复打开不新建窗口；退出后本机监听关闭；重新启动后从侧栏选择历史会话恢复内容，文件字节保持一致。
- 权限验证沿用原生规则：选定目录可写，目录外且不属于临时区域的测试路径被拒绝。初次拒绝测试放在系统临时目录而被原生策略允许；核对 `writableRoots` 后将拒绝目标改为非临时测试目录，未改变原生权限实现。
- 原生目录对话框由测试自动化操作真实控件，未替换目录选择 API。模型为隔离的本机脚本服务，只验证真实原生引擎读写及持久化链路，不代表真实法律推理或在线 OCR 效果。
- 最终通过的桌面截图与测试资料：`C:\Users\HW\AppData\Local\Temp\chengye-desktop-e2e-03nV2g`，包含 OA 入口、原生目录、成果和重启恢复截图；测试文件和脚本凭据不进入 Git。
- 导入快照 9267 文件及 8 个可执行位、原 C33 HEAD/状态/差异指纹校验通过；未修改原生源码或依赖清单。23 个暂存变更文件经 Gitleaks 扫描无告警；OA 数据库 schema、正式品牌版本、已有浏览器资料均未修改。

### 当前限制与下一阶段

这是依赖已构建仓库、Node 与 Electron 的桌面开发构建，不是可独立分发的安装器；尚未执行干净 Windows 机器安装验收。原生 UI 保留上游标题、标准模式和版本，OA 正式版本保持 V1.2.1。当前对话窗口关闭后驻留、完整退出后再次手动选择历史会话，未增加自动恢复最后选中会话的额外逻辑。
