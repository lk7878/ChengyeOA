## 3. P1：云端测试环境与真实权限

### 准备与交付

1. 业务/运维填写 Spec §13 决策单，确定测试预算、用户量、负载模型、域名、OS、模型/OCR方案、恢复目标及责任人。环境建立与真实服务调用属于后续授权任务，不由本次文档工作执行。
2. 基于选定 OS 形成固定依赖和构建清单：OA npm 锁文件、适配器 npm 锁文件、Harness pnpm 锁文件、Node/Electron/原生库、Python/Paddle和模型摘要。依赖安装与构建在构建环境完成；不把 Windows 的 native 模块目录直接复制到 Linux。
3. 产出单 OA 实例/单 Worker 的启动和停止配置、HTTPS/防火墙规则、全量持久目录与工作目录映射、秘密注入清单。核对 `intelligencePaths` 和当前相对路径结构，不让文件落进临时发布目录。
4. 创建与生产分离的测试数据库和账号，使用已提交迁移；按现有交互流程初始化测试环境，真实登录超级管理员、普通管理员、授权律师、无知识库权限用户及无智慧办案权限用户。不能依靠 E2E 注入身份或绕过 MFA 来宣称真实权限验证通过。
5. 编写目标环境备份/恢复与迁移/回退手册，使用脱敏数据副本演练；记录对象、路径和退出码，但不记录凭据。明确本地空表恢复示例不适用于有业务数据的目标库。
6. 制定旧浏览器办案入口/API 退役和 OPFS 保留方案；允许用户在旧来源导出数据后再切换来源。新目标浏览器入口只提供 OA/Wiki 及经实现的客户端引导。

### 可执行验收用例

每项记录操作时间、发布版本、环境、预期与实际结果、脱敏日志/截图、负责人与缺陷编号。预先填写的容量/恢复阈值不得在测试失败后静默放宽。

| 编号 | 实际操作 | 通过标准 |
|---|---|---|
| C-01 环境与网络 | 冷启动服务；公网访问 HTTPS；外部尝试直连 OA/DB/调试监听；验证证书续期演练、静态 MIME及跨源请求 | OA/Wiki经受控 HTTPS可用；私有端口不可公网直连；证书/来源校验有效；记录所选 OS及依赖加载结果 |
| C-02 真实身份权限 | 按上述五类真实账号登录；管理员维护 Wiki，律师查询；直接构造维护请求；查询中退出、撤权和切换账号 | 未登录/越权请求拒绝；助手通道即使管理员登录也只读；撤权后迟到结果不被新身份接收；日志无密钥 |
| C-03 数据持久化 | 写入有关联的测试案件/审批附件及 Wiki 原文/编译结果；记录摘要；重启进程并替换应用发布目录 | DB、全部附件、原文和编译引用保持一致；不依赖旧发布目录；用户材料未进入自动同步目录 |
| C-04 真实 Wiki/OCR | 管理员导入实际测试扫描件，运行 OCR 和编译，律师读取原文及编译出处；执行真实质量抽检 | 达到预先签定的准确率/时延标准；保留原件、出处及陈旧状态；个人视觉 API 和 Wiki OCR 可分别追踪 |
| C-05 失败与任务语义 | 在测试环境触发断线、超时、重复提交、繁忙、子进程退出、锁冲突、磁盘不足；重启后查询状态 | 不假成功、不丢原文、不产生未解释的重复发布；确认需手动重试与可恢复范围；无第二写入者；队列若未实现不宣称续跑 |
| C-06 实际灾难恢复 | 假设原测试主机/原卷不可用，在独立空环境恢复数据库、附件、Wiki和匹配秘密配置；隔离通知等副作用 | 按恢复清单验证 MFA/权限、业务关联、文件数量与摘要、Wiki全文/编译检索；实测 RPO/RTO 达标，任何缺项判失败 |
| C-07 迁移与发布回退 | 在测试副本执行迁移、切换新包、模拟失败，再按兼容性执行代码回退或完整恢复；验证事件 Worker停止/重启 | 单次迁移可追溯；无新旧 Wiki并行写入；回退后数据完整；有新增数据时已评估恢复影响，不静默覆盖 |
| C-08 负载与观测 | 按真实人数/同时操作模型运行登录、业务读写、附件、Wiki检索及 OCR/编译混合负载，模拟备份/任务失败告警 | 记录 p95、失败率、任务等待、CPU/RAM/IO/存储余量，与事先目标比较；输出资源建议及限制，不能只报“能用” |

C-01～C-08 是验收定义，当前均未执行。环境差异和性能结果必须落在独立报告中，不回填为先前开发机测试的结果。

## 4. P2：无源码 Windows 安装验收

### 准备与交付

确定 Windows 支持版本和架构、安装权限、可信安装包分发方式、签名与人工更新政策；将 Node、Electron、原生 Host和插件依赖封装到可重定位的交付布局。安装器不可继续依赖开发机 `link:`、外部 C33、全仓路径或用户的 Node/Python。构建端可使用源码，验收电脑不拥有源码和开发环境。

升级兼容表至少包含：云端 API、OA前端、preload版本、桌面版本、集成插件、Harness来源与数据格式。先实现必要的版本检测/错误提示，再测试；自动更新若选择开发，必须新增专项设计和失败测试，否则只交付明确的人工更新流程。

| 编号 | 实际操作 | 通过标准 |
|---|---|---|
| W-01 干净安装 | 无 Git/Node/pnpm/Python/数据库/源码的目标 Windows普通账号安装，在包含中文/空格的可支持路径运行 | 安装包依赖闭合且可启动；没有访问构建机路径、下载未声明依赖或要求用户搭建开发环境 |
| W-02 首次使用 | 正常登录云测试 OA、执行所需改密/MFA；打开百佑助手、选本地目录、配置个人模型，确认仅 lawyer可用 | 业务身份与个人模型配置分离；未安装时的浏览器引导真实有效；无需上传材料即可进行本地任务 |
| W-03 办案与权限 | 读取本机测试材料、生成成果、调用个人视觉模型、读取 cloud_wiki；检查权限拒绝和外发请求种类 | 成果本地落盘；无自动目录/会话上传；个人模型请求与 Wiki查询可区分；固定桥与原生工具授权生效 |
| W-04 恢复与离线 | 退出/重启客户端，恢复新 lawyer及既有内置模式会话；断开 OA 网络后打开本地目录和记录 | 原材料/历史保留；旧内置标识按规格承接；断网不假称云查询成功，也不启用本地 Wiki快照或 OA自动提交 |
| W-05 人工更新与卸载 | 保留个人设置/凭据/会话/工作区，尝试有运行任务时更新、修复安装、卸载及重装 | 有任务时可延后且无丢失；更新不重置数据；卸载默认保留用户状态；不支持格式降级时有明确恢复方案 |
| W-06 兼容与异常 | 测试新/上一承诺支持客户端与新云端组合；缺少桥方法、包损坏、断网、磁盘不足、拦截、错误 OA地址 | 不兼容有明确升级/失败提示，不扩大本机权限或损坏数据；接口兼容窗口有实测矩阵；无生产调试端口 |
| W-07 操作与支持 | 普通用户按说明独立完成安装、登录、办案和故障信息导出；运维按故障手册定位一次问题 | 用户不需工程师手工补依赖；支持包经预览脱敏，不含本机卷宗、凭据和完整会话；记录时间与处理结果 |

Windows 每个宣称支持的系统/架构均需明确覆盖；开发者电脑回归不能替代 W-01。真实个人模型效果与云端 OCR效果分别评估，勿以脚本模型结果替代。

## 6. 决策和验收记录模板

- 发布标识：Git提交、构建日期、依赖/来源指纹、产物摘要、组件与接口兼容版本。
- 环境：OS/架构、实际 CPU/RAM/磁盘、数据库方式、进程/Worker数、域名来源、持久目录、模型/OCR版本；秘密仅填引用名称。

- 结论：通过/失败/未执行；明确未支持能力和进入下一阶段的阻断项。

尚未提供的需求不填“默认通过”。资源规格在 P1负载与恢复测试后形成建议；Wiki快照离线权限另行决策，不作为本次在线只读部署的既定功能。
