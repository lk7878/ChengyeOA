# V1.3.0 阶段二：本地助手查询云端 Wiki 与个人视觉 API

依据 [SPEC-AI-DESKTOP-20260913](../specs/2026-09-13-unified-desktop-local-harness.md)。先建立本实施计划，再修改代码。本阶段覆盖云端知识库只读接入、登录/权限边界，以及原生视觉模型配置和本地材料识别链路；主动归档、离线草稿同步及独立安装器留待后续阶段。

## 实施契约

1. 本地 Harness 通过独立法律插件提供云端知识库列表、检索、分段原文/编译文档读取。复用同一云端 Wiki，普通律师无维护能力；即使 OA 登录者是管理员，助手通道也只读。
2. OA 访问令牌和 CSRF 凭据留在 OA 的现有认证机制中，不交给模型、本地 Harness 工具、进程环境或文件。桌面主进程通过受限请求/响应桥将只读查询交给 OA 页面现有认证 API 客户端处理；固定接口、固定操作和参数上限，禁止通用代理。
3. 每个请求由云端重新校验登录、智慧办案和知识库权限，只查询启用的知识库。返回来源、文档标识和行号，工具说明强调资料不是操作指令；查询结果仅进入本地办案会话，不写公共 Wiki 问答历史。
4. 本地办案会话首次使用 Wiki 时绑定当前 OA 账号；同一会话不得静默切换成其他 OA 账号查询。原生分支和子任务沿 `parentSession` 继承根会话绑定，不允许绕过绑定；换账号应新建不继承历史的会话。退出、认证清理、页面卸载、账号切换和权限撤销取消在途查询，迟到结果不得写入新身份会话。重新登录同一账号可以重新查询。具体持久化绑定使用原生持久化/存储扩展点实现，不另写未登记的会话事件。
5. IPC 仅传递白名单查询和有界结果，不传送工作目录、附件、文件内容、会话全文或凭据。云端检索可以接收用户/模型构造的必要查询文本，不能宣称任何文字都不会发往云端。取消、超时、断网、未登录和越权均给出明确错误。
6. 核对并优先使用原生模型配置、图像附件、`read_image` 和模型适配器，验证在线视觉 API 接收所选本地图片、识别结果进入本地会话并可保存；不部署本机 OCR，不调用云端 Wiki OCR。若原生能力需要补充，先在本记录明确适配范围，保持源码隔离。
7. 首期视觉验收覆盖 PNG/JPEG 等原生支持的图片；扫描 PDF 的整本批量识别不在未验证时宣称支持，应通过实际页面图片或后续明确的 PDF 分页适配处理。非视觉模型、凭据缺失、接口失败和不支持的文件类型不得假成功。

## 验证设计

单元测试覆盖桥接来源、操作/参数白名单、在途请求所有权和迟到响应；服务端测试覆盖认证、两个模块权限、管理员仍只读、禁用知识库拒绝及有界读取。原生桌面测试使用隔离数据和脚本模型，真实执行原生工具 → 桌面桥 → OA 接口 → 原生 Wiki 查询，再返回可引用结果；个人视觉链路验证实际图像请求、识别结果落盘和异常路径。真实模型/OCR 效果与脚本模型结构验证分别记录，不把后者当作真实识别准确率验收。

## 源码核对与实施结果

源码核对：原生 `wiki` 是确定性文档投影，不等于管理员调用模型生成的 `compilation.publication`。助手分别提供 `wiki` 和 `compiled` 读取，后者只返回已持久化的发布内容及来源事实，排除视觉候选、附件内部标识和运行错误。未编译或陈旧状态明确呈现，查询不触发编译或 OCR。原生 `read_image` 已有视觉路由校验及图片附件适配，沿用原生设置和界面。

### 实施结果

- 新增独立 `desktop-plugin/`，使用原生 tools、storageDomain、session.header 与持久化服务；`parentSession` 向上解析根会话，分支和子任务不能绕过绑定。原生 Profile 保持 Base → Web → Product，通过普通依赖与 patch 装载，原生 UI 无改动。
- OA 页面使用现有 Axios 认证与刷新机制；桌面主进程验证来源和主框架，固定请求由私有 Host IPC 传递。服务器仅暴露 `/api/v1/intelligence/desktop-knowledge`，请求开始及返回前重验身份和两项模块权限。不会把 OA 凭据传给 Harness。
- 工具包含列表、检索、原文分段、确定性 Wiki 投影和管理员编译成果读取。参数白名单、请求数/时间/返回大小限制和分页已落实，维护操作及其他任意 RPC 被拒绝。
- 实测修正了 patch 新条目的 `insert` 格式和原生 storageDomain 名称约束；测试图片夹具的错误字节被原生工具正确拒绝后替换成有效 PNG。没有为这些适配修改上游源码。
