## 4. 实施前必须明确的技术决策

以下是主会话应先写入规格/契约的工程事项，不是额外用户审批门槛：

1. 资源目录和 Base 的唯一身份、标题来源、创建事务及旧资源迁移落点；已有权限保持不变，迁移重入不重复创建。
2. 文件夹授权如何与工作区、应用、表权限求交；直接授权、禁止项、负责人例外、移动及回收的决策表。
3. 我的/共享入口的归类与去重规则；跨层目录发现不能泄露无权访问的父级信息。
4. 搜索、统计、预览、直链和事件的权限校验与撤权失效；目录、结构和记录的增量更新范围。
5. 前端云盘壳与现有大型 Workspaces 页的拆分边界；优先复用组件，不强制重写表格或改用另一消息协议。
6. G1/G2 功能开放清单，未实现入口的处理规则与失败/恢复行为；不得把截图中的每个按钮占位当成功能交付。

### G1 持续负载最终结果

- 结果：通过。规定 900 秒，实际测量 901.992 秒，测试总耗时 920.9 秒。
- 数据和频率：8 层文件夹、10 张表、最大表 10000 行 × 50 字段、100 个真实鉴权 HTTP/SSE 会话、20 个写入者每 5 秒保存；普通 SELF、管理 ALL 和含隐藏字段的账号组合。
- 查询 85,180 次，P95 1175ms / 最大 1689ms；保存 3600/3600，P95 1356ms / 最大 1767ms；全部提交均被观察到，协作可见 P95 1296ms / 最大 3689ms。
- 100 次令牌续期和重连，重连 P95 4622ms / 最大 4814ms；工作区撤权 55ms，随后读/写均 403；记录的请求错误为零。文件夹撤权另由浏览器流程覆盖，要求在 5 秒内清理目录、权限面板和表格。
- 环境：同机 Windows 10.0.26200、i7-12700（20 逻辑 CPU）、16GB 内存、Node 22.14.0、Docker PostgreSQL 16.14；服务与负载生成器独立进程，本机回环网络。
- 边界：100 HTTP/SSE 会话不是 100 台真实浏览器设备，也不是生产网络容量、跨区域网络、备份恢复或正式上线验收；不扩大原性能结论。
