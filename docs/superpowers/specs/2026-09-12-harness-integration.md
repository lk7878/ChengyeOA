## 实施契约

1. OA 仅新增授权入口和启动票据 API；新增独立 integrations/harness 包，拥有本机连接器、外置桥接插件及法律 Preset。OA 不导入 harness 包、不复制其源码、不修改源仓库，也不复用其既有 DSH_HOME 或密钥。
2. 用户电脑运行 Node 本机连接器，仅监听回环地址 127.0.0.1:43123。配置固定的 OA API 地址和浏览器 Origin 白名单，拒绝任意请求传入服务端地址、目录或用户 ID。端口和安装路径可由本机配置文件维护。
3. 连接器签发 60 秒随机挑战；OA 在登录和对应菜单权限校验后签发 60 秒 HS256 启动票据，使用独立 audience/type、绑定用户、当前认证会话、用途和挑战。连接器向固定 OA 验票接口核实当前会话及权限，挑战消费一次。OA 登录 Token 不传给连接器或 harness。
4. 本机以 SHA-256(OA 服务地址 + OA 用户稳定 ID) 区分账户目录；默认根为 LOCALAPPDATA/ChengyeOA/Harness。每账户独立 DSH_HOME、workspace、Profile、知识库、会话和凭据；进程锁防止同一知识库多进程写入。用户机器与 OA 服务器分离时也必须由浏览器连接本机。
5. 通过 dsh plugin 的 link 安装方式将现有 base/web/product 与外置桥接包装入专用 chengye-oa Profile，写入仅发生在新个人目录。启动 cwd 为个人 workspace，继承环境中清除模型及 OA 密钥，默认关闭遥测，使用 workspace-write + ask 权限模式。首次运行由用户在原生 Settings 配置个人模型凭据。
6. 右上“知识库”进入授权连接页并直达原生 Wiki；左栏“智慧办案”进入法律助手。开发机同站本地访问支持内嵌原生 UI；跨站或浏览器限制时提供原生新窗口入口，不改弱 harness Cookie 策略。连接器停止/缺失/启动失败有中文状态与本机启动说明。
7. 独立法律 Preset 注册阅卷、证据核对和法律文书工作方式，复用知识检索、文件操作及技能工具。默认创建个人知识库 alias chengye-personal 并绑定；法律能力后续通过外置插件/个人 Preset 升级。原文与模型指令分离，输出保留来源与待核实项，生成文书由律师确认；不声称现有空模型配置能完成推理。
8. menu.knowledge 与 menu.smart_case 分别门控入口；超级管理员按原机制拥有权限，其他用户显式授权。既有 OA 案件资料不自动发送，律师在本机明确导入。OA 登出不删除个人文件；已打开的本机应用属于个人 OS 会话，可手动停止连接器，共享电脑应使用独立 OS 账户。

## 验收与交付

- 授权票据：未授权拒绝、过期/篡改/用途或挑战不符拒绝、认证会话撤销后拒绝。
- 连接器：Host/Origin 白名单、地址固定、单次挑战、不同用户不同目录、同用户单实例、只读源项目、进程清理、启动失败不泄露令牌。
- 使用独立临时个人目录运行真实 dsh Profile，原生 Wiki 创建/导入/重开证明 raw 与确定性编译 Wiki 存于本机；原生新会话能发现法律 Preset 和知识工具。无真实模型调用，模型生成能力需要用户配置凭据。
- UI 名称/版本、顶部入口、侧栏入口、连接错误、嵌入及新窗口路径验证；相关 OA 鉴权、导航和构建检查。
- 新权限迁移先测试库，再备份并迁移开发库。只读源项目的工作区指纹前后对比；完成后仅在 OA 本地提交。
