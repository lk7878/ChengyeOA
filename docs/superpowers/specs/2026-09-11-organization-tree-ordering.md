# SPEC-003-B：组织树折叠与全局排序号

状态：已实施，本地自动化验收通过。日期：2026-09-11。验证记录见[实施与验收](../plans/2026-09-11-organization-tree-ordering.md)。

## 需求来源

用户要求组织架构左侧每个组织可独立折叠/展开下级；排序号一经组织占用，其他组织不能再选择，包括不同层级的总所和分所；所有变更先从 spec 开始。

关联 MOD-001 ORG-01/ORG-11、FTN-001 数据模型、FTN-004 事务一致性；本规格补充 SPEC-003-A，不改变其超级管理员管理门禁、组织层级、负责人及删除保护规则。

## B1 折叠展示

- 有下级的节点提供独立的展开/收起按钮，带中文可访问名称和 aria-expanded，键盘可操作；叶子不提供折叠按钮。
- 点击组织名称仍选择详情，点击折叠按钮只改变显示，不修改组织或当前详情。
- 默认展开，用户对每个节点的折叠状态在当前页面刷新数据、编辑保存后保留；离开页面不要求持久化。
- 搜索时临时展开匹配路径，清空搜索恢复用户原有折叠状态；新增/复制成功后展开新节点的祖先，保证可见。

## B2 全局唯一排序号

- 所有组织共用一套非负整数排序号（0–2147483647），包括根律所、分所、部门、小组及停用组织；不同父节点也不允许重复。
- 新增、编辑、复制表单显示可搜索的序号选择器；已占用号码显示组织名称并禁用；编辑时本组织当前号码仍可选。搜索支持直接输入较大的整数，不生成海量选项。
- 新增/复制默认推荐全局最大号码之后的空号；选择模板不会沿用已被模板占用的号码。编辑释放旧号后其他组织可使用；删除成功释放号码，停用不释放。
- 后端独立校验。冲突返回 409 / ORGANIZATION_SORT_CONFLICT，中文提示刷新后选择其他号码，保留输入。并发争抢同一号码最多一个成功。
- 创建未传 sort 时自动分配可用号码。复制的后代按原同级顺序自动分配新的唯一号码，保留其相对顺序；此规则取代 SPEC-003-A 中复制保留原排序数值的描述。
- 直接修改与管理员治理共享排序命令采用同一校验；数据库唯一约束防止漏检写入重复号码。自动默认值通过数据库函数在事务锁内分配，不使用固定 0 默认值。

## B3 现有数据兼容

已只读发现现有 15 个组织的 1–6 存在跨层级重复。增量迁移按旧 sort、level、code、id 确定稳定顺序，分配 0 起连续唯一号码，保持每组兄弟节点当前显示顺序。仅更改号码、版本及更新时间，名称、父子关系、负责人和业务关联保持不变；将实际变更的旧/新号码写入审计记录。迁移事务性执行，失败回滚。不得重置或删除开发数据。

## 验收与实施顺序

1. 先完成本规格及 MOD-001/TRACE 追溯，再修改代码。
2. 增量迁移先在独立 *_test 库核验重复数据转换和唯一约束，再用于开发库；Prisma 生成及服务重启。
3. 服务/接口回归：跨层级冲突、自身号码不冲突、治理共享入口、并发争号、默认分配、多级复制唯一且顺序正确、失败回滚。
4. 页面回归：独立折叠不选中、刷新保留、搜索临时展开、新副本可见、占用号码禁用、当前号可选、模板不覆盖号码、冲突保留输入。
5. 运行相关 TypeScript、lint、前端构建及健康检查，将实际证据写入同日期实施记录；未执行项不得记为通过。
