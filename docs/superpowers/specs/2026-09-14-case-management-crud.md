# 客户电话必填与案件维护

延续用户“任何修改先从spec开始、任务完成提交本地Git”的要求。本规格补充已实施的 SPEC-CASE-20260914，覆盖本轮新增要求。

## 行为

1. 客户管理的新建客户弹窗中，电话显示必填标识，空值、空格和无效电话阻止提交；沿用现有服务端电话必填及格式校验。案件跳转新建客户使用相同规则。
2. 案件列表展示新建案件的全部字段：原有基本字段、全部建档补充字段、三类附件、系统创建与最近修改时间。横向滚动，固定案件编号与操作列；长文本可完整查看，金额/比例显示单位，客户、律师、部门显示名称。附件遵循文件读取权限并可下载。
3. 列表保留关键词和状态查询；关键词支持编号、标题、案由、客户名称、合同编号、地区及案件类型。操作列提供查询（完整详情）、修改、删除，并保留结案和合同关联操作。原详情入口保留兼容。
4. 修改复用可拖动案件表单，回填全部可编辑建档字段和现有附件；创建/修改时间只读。可修改客户、律师、费用及全部补充字段，可新增或移除附件，取消不落库。客户与律师必填，保留版本并发冲突校验；案件已有关联合同时，客户必须与合同一致；已结案/归档案件沿用现有不可修改规则。修改过程中跳转新建客户仍保留编辑草稿及案件版本。
5. 删除使用独立 `case.delete` 权限，界面确认显示案件编号和标题，提交版本校验。未结案且没有财务合同、成本记录关联的案件可删除；已结案/归档及有财务关联的案件拒绝删除并说明原因。案件与其任务、沟通、文件记录在数据库事务内删除，保留删除审计；附件在事务成功后清理。删除失败不移除列表记录；并发更新后旧版本不可删除。此条以用户本轮明确要求替代旧规格“案件不可删除”的限制。
6. 查询与展示沿用 `case.read`、附件读取沿用 `case.file.read`；修改沿用 `case.update`，附件变更需 `case.file.manage`。新增权限通过增量迁移供给，不自动授予普通角色。系统管理员沿用现有权限机制。

## 验证

- 客户电话必填标识、空值阻止提交、有效电话成功及案件往返创建客户。
- 列表完整字段和附件用途展示、扩展查询；修改回填、金额/日期清空与保存、附件取消和保存语义。
- 接口测试覆盖更新白名单/校验、版本冲突、合同客户约束、权限拒绝、删除关联保护、事务审计失败回滚及成功删除。
- 完成相关前后端回归、lint、类型检查、构建、权限迁移及基线检查；保留项目已有约束，记录验证范围和环境限制，提交本地Git。
