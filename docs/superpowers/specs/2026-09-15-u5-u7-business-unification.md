## U5-A 数据与权限

- 新来源 CUSTOMERS、NEGOTIATIONS、CONTRACTS 直接查询正式表，通过稳定 ID 与 CollabExtension 关联；不复制核心行。空白自定义表和连接正式业务仍明确区分。
- 来源由服务端白名单描述字段、权限码、SQL 表及业务入口。前端不得提交表名/模型名/任意 SQL。未知来源/列/范围结构拒绝。
- 每种来源要求对应 read 动作；读取范围为原领域 scope ∩ 工作区组织范围 ∩ 资源 SELF/ALL。SELF 一律取正式记录 createdBy，不用创建时间或负责人反推。
- 谈案/合同组织直接取 branchId；客户通过 sourceLead.branchId 取组织。无来源线索的客户以创建账号当前有效员工任职组织匹配工作区组织子树；这仅收紧资源入口，不能扩大 CustomerService 的原客户范围。人员调动会改变这些无来源客户的资源可见范围，原客户直链仍按原业务范围授权。来源线索存在但组织不符时不得退回创建人组织绕过。
- 客户电话/微信复用 customer 字段权限、脱敏与明文读取审计；隐藏/脱敏字段不能参与查询、分组或排序推断。金额按 Decimal 原值展示和数据库数值排序，不在前端浮点核算。
- 正式字段保持受控只读；扩展字段要求资源可编辑且对应编辑动作及动作数据范围：客户 customer.update、谈案 negotiation.update、合同 contract.submit（现有权限目录无 contract.update，不虚构权限码；该授权仅允许编辑协作扩展，不触发合同提交或修改正式条款）。同一行领域版本与扩展版本共同组成乐观锁版本，事务锁固定为工作区→正式行，扩展/历史/事件/审计同事务。
- 总表/个人/共享视图、字段设置、筛选/排序/分组、冲突、撤权和附件授权复用既有工作区能力。新建、联系人、转介绍、谈案结论、合同审批/签署/生效/终止保留原领域服务校验，并从统一记录上下文办理或定位。合同生效等跨对象事务不得拆分。
- 原领域详情/命令继续采用原领域授权；资源 SELF 并非旧 API 的全局 ACL。岗位配置需同时收紧原领域范围与资源范围，不能把个人视图当作权限边界。原领域动作回表时回源读取，不声称全部旧动作已广播协作 SSE；扩展编辑继续实时广播。
- `/customers`、`/negotiations`、`/contracts` 接入业务表目录及编辑器；旧详情、新建和案件往返入口保留查询/状态/业务 ID。不能把旧整张列表嵌进新框架作为完成。

### U5-B 负载修复契约

若阶段负载暴露共用协作保存的数据库往返开销，可将同一事务内的协作失效事件、经过原 registry 校验的 EventLog 和 OperationLog 合并为一条参数化 SQL。保留事件类型、payload、orderingKey、真实操作者、审计目标、权限/工作区锁、版本及幂等语义；任一插入失败必须回滚全部记录。不能缓存授权结果、缩小负载数据或放宽阈值。先增加事务失败与重放回归，再进行短程对比和完整验收。


U6-A 金额还需统一工作表路径：CURRENCY 输入/粘贴/筛选支持 Decimal(18,2) 的 16 位整数范围；金额分组使用规范化十进制字符串，不经 Number 合并超过安全整数范围的不同金额。原 NUMBER 列范围独立保持。需覆盖大额分组、0.10/0.20 余额与接口原值往返。


浏览器验收服务器使用独立 Vite 缓存目录，避免与已启动的开发前端交叉改写依赖缓存；请求监听与触发点击必须一起 await，点击失败不得遗留未处理的等待 Promise。应用源码在一轮浏览器测试期间冻结；优化缓存隔离本身不能作为历史波动已经修复的证明。


### U6-A 案件财务上下文

旧 `/finance?caseNo=...` 先经 case.read 精确解析获权案件及其合同，提供同源收款/发票/退款与案件成本入口；未绑定合同显示待关联并返回案件办理。收款等表的限定条件为现有 contractId 字段，成本表为 caseId 字段，与选中视图的过滤器做 AND，仅作为当前页面上下文，不静默保存或改写个人/共享视图。目录选择、创建、详情和返回保留该上下文；字段不可见时不绕过列规则进行筛选。URL 参数不是授权证明，后端仍按当前单据范围与资源权限过滤。

## U6-B 实施前契约：库存、绩效与工资办理

- 原库存查询、统计、导出和详情落实范围；执行入库/领用/盘点另核验对应动作的物品范围。持久请求重试也复验当前目标授权，不得凭旧 key 绕过撤权。沿用固定数量、非负库存、事务行锁、请求摘要、前后库存、领用人和组织快照与同事务审计；通用字段写入不能直接调整库存。
- 不为不可变流水虚造可编辑领域状态；协作版本为固定领域基数加扩展版本，领域更新时间取创建时间，写入扩展另记录编辑人。需要新增读取单据 API 时保持 requestKey/requestHash 不外露。
- Performance 增量增加可空 createdBy/updatedBy 和 version；旧创建人只从唯一可靠 PERFORMANCE_CREATE 审计回填，无证据保持未知。组织由被考核员工当前有效任职定位，明确为动态业务组织，不回填猜测历史分支。SELF 仍为实际创建人；旧 ALL 授权可核对未知记录。员工可登记自己的考核，负责人按授权设置目标/评议；负责人替员工创建的考核不因此自动进入员工创建人 SELF，须配置明确获权范围。
- 目标、自评、主管评、确认经原领域动作；新增 UI 始终发送当前版本，旧缺省版本调用保持兼容状态检查。自评同时要求被考核人是当前绑定员工；不能冒充他人提交自评。新建员工候选经 employee.read 及范围，不将前 100 项当全部人员。主管评和确认保留原授权与状态规则，全部变更增加版本与审计。
