1. U5-A：扩展同源适配基础，客户、谈案、合同接入共同视图、扩展字段、关联详情与原受控动作，保留客户新建往返案件的草稿语义。
2. U5-B：案件交付工作区；先明确旧案件缺少创建人/组织列及旧接口只做动作授权的兼容策略，再接入案件、节点、材料和归档，不改 Harness。
3. U6：财务/库存/绩效/分析及其余现存模块逐项统一。金额、库存变更、审批和高风险身份验证继续通过领域命令；统计使用正式数据及原授权范围。组织、身份、系统治理、通知保留适合任务的专用交互，整合共享目录、记录定位和动作反馈。
4. U7：核对全路由及无独立页面清单，覆盖后删除重复列表/组件，保留受控旧链接；完成 UNIFY-AC-01–10 和三角色、三宽度、异常/撤权/并发/桌面边界验收。历史规划但未实现的产品能力必须明确状态，不能伪造入口或因导航统一自动标成完成。

## U5-A 数据与权限

- 新来源 CUSTOMERS、NEGOTIATIONS、CONTRACTS 直接查询正式表，通过稳定 ID 与 CollabExtension 关联；不复制核心行。空白自定义表和连接正式业务仍明确区分。
- 来源由服务端白名单描述字段、权限码、SQL 表及业务入口。前端不得提交表名/模型名/任意 SQL。未知来源/列/范围结构拒绝。
- 每种来源要求对应 read 动作；读取范围为原领域 scope ∩ 工作区组织范围 ∩ 资源 SELF/ALL。SELF 一律取正式记录 createdBy，不用创建时间或负责人反推。
- 谈案/合同组织直接取 branchId；客户通过 sourceLead.branchId 取组织。无来源线索的客户以创建账号当前有效员工任职组织匹配工作区组织子树；这仅收紧资源入口，不能扩大 CustomerService 的原客户范围。人员调动会改变这些无来源客户的资源可见范围，原客户直链仍按原业务范围授权。来源线索存在但组织不符时不得退回创建人组织绕过。
- 客户电话/微信复用 customer 字段权限、脱敏与明文读取审计；隐藏/脱敏字段不能参与查询、分组或排序推断。金额按 Decimal 原值展示和数据库数值排序，不在前端浮点核算。
- 正式字段保持受控只读；扩展字段要求资源可编辑且对应编辑动作及动作数据范围：客户 customer.update、谈案 negotiation.update、合同 contract.submit（现有权限目录无 contract.update，不虚构权限码；该授权仅允许编辑协作扩展，不触发合同提交或修改正式条款）。同一行领域版本与扩展版本共同组成乐观锁版本，事务锁固定为工作区→正式行，扩展/历史/事件/审计同事务。
- 总表/个人/共享视图、字段设置、筛选/排序/分组、冲突、撤权和附件授权复用既有工作区能力。新建、联系人、转介绍、谈案结论、合同审批/签署/生效/终止保留原领域服务校验，并从统一记录上下文办理或定位。合同生效等跨对象事务不得拆分。
- 原领域详情/命令继续采用原领域授权；资源 SELF 并非旧 API 的全局 ACL。岗位配置需同时收紧原领域范围与资源范围，不能把个人视图当作权限边界。原领域动作回表时回源读取，不声称全部旧动作已广播协作 SSE；扩展编辑继续实时广播。
- `/customers`、`/negotiations`、`/contracts` 接入业务表目录及编辑器；旧详情、新建和案件往返入口保留查询/状态/业务 ID。不能把旧整张列表嵌进新框架作为完成。

## U5-B 实施前契约：案件身份、组织与交付

现状证据：Case 无 createdBy/branchId，旧 CaseService 与任务/沟通/材料服务仅检查动作码；正式写入点为 CaseService.createCase 和 ContractService.effectContract。不能把 lawyerId、客户创建人或合同创建人推断为案件创建人。

- 增量增加可空创建人和组织锚点，保持旧 Case ID、费用、附件和合同唯一关联。新建案件由服务端写当前操作者；合同生效生成案件记录实际执行者。旧记录只从可验证的 CASE_CREATE 审计恢复创建人；组织仅从现有明确合同组织或已校验 intake 部门恢复。无充分依据保持未知，不能默认归管理员或当前用户。
- 普通岗位 SELF 使用实际创建人；负责人 ALL 按授予范围访问。案件主办律师是业务角色，不能替代创建人。原案件 API 也落实对应动作范围，不能仅隐藏表格；案件任务、沟通、文件读取/下载/上传与修改都校验所属案件，直接 URL 无权返回 404。
- 旧创建人未知记录不进入 SELF；原 ALL 领域授权可继续管理和核对旧记录。工作区来源必须匹配组织，未知组织不强行挂入任意工作区。迁移验收报告列出未知数量和处理边界；如需补录，采用有授权、明确选择、理由和审计的修复动作，不静默批量猜测。
- CASES 直接读取正式案件，共同视图/查询/扩展字段复用；案件状态、金额、客户/合同/律师关联通过领域命令，禁止核心字段通用编辑。节点、沟通和材料在同一案件办理上下文展示，结案/归档遵守状态与版本规则。
- /cases 使用共同工作表，/cases/new 与 /cases/:id 复用现有受理表单和交付操作；移除旧列表呈现，保留 caseNo 查询定位和案件↔新建客户草稿往返，不复制整套列表。智慧办案与知识库桥保持根级生命周期和协议。
- 验证增量迁移保留数据、审计回填不误认创建人、未知记录失败关闭；三角色原 API/工作表/材料直接链接、创建/改派/任务/沟通/结案/归档/合同生效链路、冲突与撤权。完成真实 App 冒烟、受影响案例/财务服务回归、构建和文档检查后才可标记 U5-B 完成。
