# OA 案件管理完善

需求依据：用户于 2026-09-14 提出的四项要求；先规格、后实现，验证后提交本地 Git。

## 行为与边界

1. 案件编号下“关联财务”使用 React Router 应用内导航至 `/finance?caseNo=...`，保留当前登录会话和案件编号筛选。
2. OA 各模块的 Modal 弹窗统一支持标题栏指针拖动，限制位置以保证标题/关闭按钮可达；关闭重开恢复初始位置，窗口缩放后保持可达。表单内容、按钮及滚动不触发拖动。大表单内容独立滚动。
3. 新建案件的客户、主办律师前后端均必填，校验真实客户/员工。历史无主办律师记录仍可读取；自动财务流程不强制回填历史字段。
4. 保留标题、案由、优先级、费用、描述；增加以下可选信息并在详情回显。记录创建时间、最近修改时间由服务端维护，新建时只读提示保存后生成。

| 分组 | 字段 |
|---|---|
| 基本信息 | 签约日期、合同编号、地区、客户电话、案件类型、代理程序、所属业务部门 |
| 收费约定 | 代理费收款方式、固定代理费金额、案件基础代理费、风险代理金额、风险代理比例、代理费付款特别约定 |
| 到款退款 | 首次代理费、首次收款日期、二次到款金额及时间、三次到款金额及时间、四次到款金额及时间、总到款金额、退费金额、退款时间、到款次数三次以上金额、最后一次到款时间 |
| 提成 | 律师提成金额、律师提成比例 |
| 附件 | 合同附件、收款凭证、退款凭证，支持图片、PDF、Word、Excel、文本等常见格式；每个文件不超过10MB，总计不超过10MB；按用途分类存储并通过现有受权限控制的文件接口下载 |

案件类型：刑事、民事、执行、商事、行政、涉外、国家赔偿。

代理程序：一审、二审、执行、再审、刑事侦查、审查起诉、行政复议、和解、调解、代书、其他非诉、刑事会见、仲裁代理出庭、仲裁、常年法律顾问、一审与申请执行、咨询、代为申请立案、工伤认定程序、审查起诉与一审、陪同刑事控告、自定义。自定义需填写名称；去除原需求列表重复分隔符产生的空选项。

代理费收款方式：半风险代理、法律援助、分段付款、常规代理、全风险代理。金额为非负两位小数，比例为0–100%。这些字段记录案件建档信息，不自动生成或改变已审批财务流水；总到款等汇总项支持录入，以容纳历史款项，避免重复计数。部门来自启用的业务部门，服务端校验。合同编号是录入信息，财务合同关联仍沿用现有关联操作。

5. 客户选择支持服务端搜索现有客户；输入新名称后明确点击新建，跳转客户管理的新建客户弹窗并预填姓名。保留案件草稿（含已选附件，仅当前会话内存）；客户创建成功写入现有客户表，返回案件弹窗并选中客户。取消创建也能返回草稿。沿用客户模块校验、权限及重复客户约束。
6. 新增数据通过增量数据库迁移保存，原案件数据不清除；附件与案件数据库记录同事务创建，失败清理本次落盘文件；不将文件内容写入日志。维持案件及文件权限。

## 验收

- 应用内跳转保留会话，财务携带案件编号。
- 拖动案件及其他新建弹窗，关闭重开重置位置，输入和滚动正常。
- 缺少客户/主办律师不可提交；所有字段能够保存和读取；非法枚举、金额、比例、日期、部门被拒绝。
- 客户搜索、新建成功返回、取消返回不丢案件草稿；客户名单同步。
- 附件用途、下载内容、大小限制和事务失败处理覆盖回归。
- 执行相关前后端回归、类型检查、lint、构建及项目必需检查；记录环境限制。仅提交本任务文件与相关文档变更，不纳入工作区原有改动。
