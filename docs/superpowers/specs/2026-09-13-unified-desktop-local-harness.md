# 统一桌面客户端、云端业务与本地 Harness

## 1. 确认状态与版本

用户于 2026-09-13 确认本方案，并要求先将边界写入 Spec。首次确认仅更新文档并提交 Git；随后用户授权实施计划和桌面基础验证，现处于实施中。[阶段一记录](../plans/2026-09-13-unified-desktop-local-harness.md)覆盖原生桌面接入、目录读写与会话恢复，完整规格尚未验收。

用户随后授权阶段二，实施边界与结果见[云端 Wiki 与个人视觉 API 记录](../plans/2026-09-13-desktop-cloud-wiki-vision.md)。桌面开发版本为 `1.3.0-dev.2`；已接入同库只读查询、根会话身份绑定及原生图像 API 链路。真实模型识别效果、云端 OCR 部署、安装交付及后续业务功能仍按下表分别验收，不将阶段验证等同整体验收。

目标产品名为 **律师智慧管理系统 V1.3.0**，在实现及验收完成后更新运行界面版本。当前已实施版本仍为 V1.2.1，不能因本规格获批而宣称桌面能力已经交付。

## 2. 替代关系

本规格是后续智能化开发的最新依据。以下历史规格及其验收记录保留原文和历史意义，冲突处以本规格为准：

| 历史方案 | 本次确认的替代边界 |
|---|---|
| V1.2.0 浏览器 OPFS 个人工作区、无需安装客户端 | 安装统一桌面客户端，在 Harness 原生 UI 中选择本机文件夹 |
| V1.2.0 云端临时 Harness 办案进程及浏览器文件传输 | Harness 引擎在律师电脑运行，直接读写本地工作目录 |
| V1.2.1 网页内浮动工作台、原生组件拼装 | 完整复用 Harness 桌面运行方式与原生界面，通过统一客户端打开办案窗口 |
| 历史“零新增 Harness HTTP 端口”约束 | 不开放云端办案引擎；允许原生桌面运行所需的受保护本机回环通信，用户无需手填端口 |
| 曾讨论的办案材料云端同步与备份 | 不纳入本次范围；仅保留用户主动提交选定成果到 OA 的能力 |
| 办案材料使用云端 Wiki OCR | Wiki OCR 与个人办案识别分开，后者配置在线视觉模型 API |

继续保留：OA 右上角相邻的“智慧办案”“知识库”入口、不增加 OA 左侧智慧办案菜单；云端管理员 Wiki；源码隔离；原 C33 项目只读；法律能力通过插件维护；旧数据不得擅自删除。

历史依据：[V1.2.0](2026-09-12-harness-decoupled.md)、[V1.2.1](2026-09-12-smart-case-native-ui.md)。

## 3. 部署与界面

1. 律师使用一套统一桌面客户端，包含 OA 界面和本地 Harness 入口。首期沿用已有 Windows 桌面基础；其他操作系统交付不作为首期验收条件。
2. OA 业务服务、正式业务数据库、身份权限、审批、财务和审计运行在云端。律师无需安装 OA 后端或维护业务数据库。既有 OA Web 访问能力保留。
3. 智慧办案完整复用导入的 Harness 桌面源码、正式 Product Profile、原生工作区、会话、模型配置、工具授权和插件机制，不以重新拼装的聊天页面替代完整接入。
4. 右上角“智慧办案”打开或恢复同一桌面办案窗口，支持原生缩放、最小化、恢复；OA 页面切换不重建办案会话。窗口关闭、托盘驻留及退出遵循可见、可理解的桌面生命周期。
5. 在 Harness 原生工作区界面选择本机实际文件夹，直接处理其中材料，将成果写入本地目录；不要求浏览器上传、下载或 OPFS 导入后才能办案。文件操作和工具执行保留原生授权机制。
6. 本地应用启动与云端授权分开：无法连接 OA 时仍可打开本地工作区和已保存材料；云端模型、Wiki、OA 提交均依赖对应服务连接。是否可运行离线模型不在本次新增承诺内。
7. 交付需包含可安装、可启动的客户端和普通用户操作说明，不能仅以开发命令或已有 Electron 开发壳作为交付。浏览器入口如支持唤起客户端，应提供未安装时的明确引导，不宣称网页自身能操作本机目录。

## 4. 数据归属和交换边界

| 数据 | 权威存储位置 | 交换规则 |
|---|---|---|
| OA 案件、组织、人员、审批、财务等业务记录 | 云端 OA | 按当前身份和数据范围查询、提交，经服务端校验后生效 |
| OA 本地缓存、草稿、待提交业务修改 | 用户电脑，按账号及服务地址隔离 | 缓存刷新向云端读取；待提交修改联网后按规则提交，不把整库缓存上传覆盖云端 |
| Harness 原始材料、会话、提取结果及工作成果 | 用户选择的本地工作区及原生本地状态目录 | 不自动同步、不上传 OA/Wiki、不做云端目录镜像或云端个人会话备份 |
| Wiki raw 原文、SQLite、编译文件和维护记录 | 云端 Wiki 数据目录 | 管理员新增、维护、编译；律师只查询、阅读和引用 |
| 主动归档的选定办案成果 | 本地原文件保留；归档副本进入云端 OA | 用户确认文件和目标案件后单次提交，后续本地修改不自动更新云端 |
| 模型/视觉识别请求内容 | 由本地引擎向配置的在线 API 发送必要内容 | 属于任务处理请求，不等同于 OA/Wiki 文件同步；不能宣称完全离线或服务商不留存 |

云端 OA 和 Wiki 不扫描律师本机目录。统一客户端不等于 OA 页面获得任意本地文件、Shell 或模型密钥访问能力。明确交换渠道仅包括 OA 业务接口、只读 Wiki 查询接口、配置的模型 API 和用户主动归档接口。

## 5. OA 缓存、提交与校验

1. 云端业务状态为准；读取缓存不属于待上传业务修改。在线修改直接提交云端，成功响应后才标记已保存。
2. 普通业务表单断网可保存草稿和待提交内容，恢复网络后自动尝试提交支持离线草稿的操作。界面区分本地草稿、待提交、提交中、云端已保存、校验失败和冲突。
3. 每次提交重新检查当前登录状态、权限、数据范围、字段格式、必填项、业务状态、关联对象和唯一性；不能信任本地缓存的角色或旧校验结果。
4. 审批、付款、权限变更等关键操作必须在线由云端确认，不在断网时记作已完成，也不在重连后未经用户确认自动重放。
5. 校验失败保留输入，显示具体字段或业务原因；发生版本冲突时展示冲突并让用户处理，不采用静默的最后写入覆盖。
6. 支持提交的重试应具备幂等识别；响应丢失先确认结果，避免重复新增、重复付款或重复审批。部分成功须逐项显示结果。
7. 退出、账号切换或权限失效后不得继续用旧身份提交队列或展示其他账号缓存。未提交草稿按账号隔离保留；恢复授权后再处理，不能借切换账号上传旧账号草稿。

## 6. Wiki 与 OCR 分工

1. Wiki 在云端由系统管理员维护、导入、编译和备份；律师无需配置 SQLite 或 OCR 环境。普通律师和办案助手仅可调用授权的已启用知识库查询、阅读、引用接口。
2. Harness 通过适配接口访问同一云端 Wiki，不另建需要律师维护的本地 Wiki，不将个人办案会话写入公共 Wiki。检索使用必要查询信息，不隐式上传整个工作目录或原始卷宗。
3. Wiki OCR 由管理员在云端导入、编译流程中使用，继续按云端配置管理；不是个人 Harness 材料识别的默认中转服务。
4. Harness 可配置在线视觉模型 API 识别本地扫描件、图片或需要识别的页面。沿用并适配原生供应商/模型配置及插件能力，调用前明确服务与发送内容范围，按原生授权策略执行；不要求律师本机部署 OCR，也不自动回退到 Wiki OCR。
5. 识别结果写回本地工作区。无配置、断网、超时、不支持的格式和 API 失败应明确反馈并保留原件，不伪装识别成功。
6. 云端 Wiki 凭据不下发给客户端。个人模型凭据仅供本地引擎使用并按原生安全配置保存，不进入 OA 同步、日志、URL 或 Git。具体供应商协议与凭据存储实现于编码前核对源码后记录，不把未验证兼容性视为已实现。

## 7. 主动“提交至案件档案”

1. 本能力纳入 V1.3.0，入口置于 Harness 的集成操作中，保留原生界面主体。律师选择一个或多个成果文件，再选择有归档权限的 OA 案件；界面显示目标案件编号、名称与文件清单，用户确认后上传。
2. 案件编号是业务关联唯一标识。服务端解析并校验实际案件记录及权限，不能只信任客户端传来的编号、内部 ID 或“可见”状态；可查看案件不自动等于可归档。
3. 仅上传确认的文件内容及归档必要元数据，不自动携带相邻文件、完整目录、会话、模型上下文、密钥或本机绝对路径。
4. 服务端校验文件大小、类型、内容完整性、案件状态及当前权限，并记录上传人、时间、案件关联、文件摘要与归档审计。归档遵循案件材料已有可见范围，不自动共享给全所。
5. 归档不是审核通过或自动结案。已有文书审核和案件状态流程仍生效；同名文件或修改版不得静默覆盖历史，应形成可追溯版本或由用户明确选择处理方式。
6. 返回每个文件的归档结果及档案定位信息；重试不产生重复记录。中断、失败、权限撤回时保留本地文件，不能显示虚假成功。断网时可以保留选择草稿，但不自动后台上传未经重新确认的材料。
7. 本地原文件继续保留。本地后续修改、重命名或删除均不自动改变云端归档；需要更新时再次主动提交。云端文件删除也不删除本地原件。

## 8. 源码维护与安全边界

- `LayerManage/law-firm-system/`：OA 业务、权限、云端接口和界面。
- `third_party/deepseek-harness/`：独立 Harness 源码、锁文件和构建，保留来源清单及许可。原 `D:\2_test\C33_deepseek-harness` 始终只读，运行不依赖该外部目录。
- `integrations/intelligence/`：集中维护桌面组合与打包适配、OA/Wiki 接口和法律插件；避免把 Harness 业务逻辑复制进 OA。优先扩展点，确需修改导入源码时先记录补丁理由、范围和来源指纹变化。
- 桌面主进程管理本地能力，OA 远端内容与本地引擎隔离。深链接或窗口消息不能携带任意命令、任意路径授权或凭据；本地目录由用户在 Harness UI 选择。
- 如使用原生本机 HTTP 服务，仅监听回环地址，并保留原生认证与来源校验，不把它开放到局域网或云端公网。
- 身份过期和权限撤销由云端接口即时校验；本地原有文件不因 OA 退出被删除，但 Wiki、案件查询及归档必须停止使用失效身份。
- 运行资料、数据库、缓存、密钥、会话和用户文件不进入 Git。法律功能通过插件维护，遵循原生工具审批边界。

## 9. 旧数据与非目标

旧浏览器 OPFS 办案资料及备份不得静默清空。实施时提供或保留导出、迁移指引，验证文件和会话可恢复性；不兼容项目须明确说明并保留旧数据，不默认上传云端。旧云端 Wiki 继续使用，迁移不应导致重建或丢失现有知识库。

本次不做：每位律师一套 OA 后端数据库、个人办案目录云同步/云备份、离线执行审批付款、自动把个人材料编译入公共 Wiki、本机 OCR 环境部署、无条件的全离线模型承诺。
