## 已确认要求

1. 原 C33 项目只读。将必要源码和未提交 Wiki 增量的实际快照导入 OA 仓库独立子项目，保留独立依赖、锁文件、构建、许可及来源指纹，不直接融合 OA 代码。不复制 .git、用户数据库、原文、密钥、.env、缓存和运行数据。
2. 右上方“知识库”是独立模块。管理员复用原生 KnowledgeBaseCenter 的导入、原文、Wiki、编译、检索、引用、维护和完整备份；律师界面仅提供查询、浏览与原文引用，不出现维护控件，服务端同步强制权限。
3. 左栏“智慧办案”复用 Harness 引擎、会话、工具审批和法律 Preset/插件，通过明确接口检索同一云端 Wiki。不得再嵌入第二个 Wiki 管理外壳。后续法律能力集中由插件维护。
4. OA、Wiki 和 OCR 在云服务器运行，律师仅使用浏览器，无需安装、配置和维护 Wiki 数据库。OCR 与 Wiki 配置由管理员维护。
5. 只启动 OA，不新增 Harness HTTP 监听端口，不让用户填写端口或手工连接。OA 管理标准 SDK Profile 子进程，以 stdio/IPC 通信，HTTP 统一 OA 原有地址。
6. 原生 React 18 视图使用自身 React/ReactDOM 与样式，OA React 19 只传 DOM 和普通操作接口，不跨框架共享 Context 或 React 元素。
7. 完成验证后本地 Git 提交，作者邮箱 446443267@qq.com，不推送。保留旧个人资料及迁移入口，不删旧库。

## 云端知识库契约

1. OA 管理一个专用 Wiki 服务进程，复用原生 KnowledgeController/KnowledgeBaseStore 和 SQLite schema、FTS5、文件解析、编译、检索、引用、备份语义。由该进程统一持有数据库和编译队列，避免多个进程启动恢复逻辑互相取消任务。
   V1.2 采用单 OA Worker 部署，启动脚本固定 workers=1，运行目录锁阻止重复实例持有同一个 Wiki；未来多实例需要另设共享调度服务。本次不增加该服务及端口。
2. menu.knowledge 允许进入知识库；新增、导入、删除、状态修改、模型设置、编译、审核及备份恢复等维护操作只允许当前有效系统管理员或超级管理员。服务端依据 AuthorizationContext 判定，不能依赖按钮隐藏或客户端传入角色。
3. 普通律师只查询已启用知识库，允许列表、资料目录、检索、Wiki/图谱与有界原文读取；不能访问归档库、编译草稿、后台队列或管理员模型凭据。办案模块引用仍须检查知识库是否启用。
4. 律师的办案问答属于个人案件会话，不写入公共 Wiki 的管理员问答历史，不通过公共知识库接口泄露其他律师的会话。管理员原生编译和问答日志按原生持久化契约保存。
5. PDF/DOCX/XLSX/HTML/Markdown/TXT 按原生限制解析，OCR 复用 PaddleOCR 算法。OCR 由受控 Python 子进程经标准输入输出调用，不监听新 HTTP 端口；图片大小、超时、并发均受限，不在日志记录正文。未配置引擎时明确返回配置错误。
6. 管理员可用原生完整 JSON 备份迁移旧 C33 资料，先验证再恢复，保留原目录不覆盖。定期数据库与原文备份由云端运维负责；界面完整备份入口保留。

## 智慧办案契约

Harness 子进程按 OA 用户隔离，所有操作走 OA 认证和模块权限。法律 Preset 暴露云端 Wiki 检索、原文读取、办案工作区资料读取、Markdown 文书保存和原生询问/审批。不得给普通律师开放服务器任意路径读写、Shell 或任意安装插件。文书写入保留原生单次审批。

用户已确认工作区在**律师电脑本地，通过浏览器保存，不安装额外服务**。办案资料、文书和可恢复会话保存在浏览器 OPFS，按 OA 源、用户 ID 与案件隔离；提供持久化授权、空间信息、备份导入/导出。清除站点数据会删除本机工作区，换电脑须导入备份。云端 Harness 仅临时处理当前请求必要的数据，禁止在服务器持久化个人办案原文和会话日志。原生会话持久化检查点经 IPC/OA 请求浏览器落盘并确认后，才继续模型或工具步骤。断线、超时、写入失败必须停止或拒绝继续；恢复时从浏览器读取已保存会话。文书保存工具通过同一通道写入本机，不能退回云服务器目录。普通律师使用本地工作区与云端 Wiki 两个明确接口，知识库不复制进个人工作区。

模型请求使用明确配置，凭据不写日志、URL 或 Git。默认 DeepSeek 官方端点，额外端点由管理员允许；请求持有独立凭据快照。无实际模型凭据或 OCR 环境时，区分结构验证与实际推理/OCR 效果。

浏览器离开模块时停止该客户端的临时云端会话进程；断线超过两分钟清理闲置客户端，释放内存。关闭与存储失败均不得自动切换成云端保存。未配置模型或 OCR 时提供管理员配置提示，不能展示为空白的“成功”。模型配置由服务器环境注入。

浏览器 PDF 解析使用页面内 PDF.js 与其解析 Worker，SQLite 工作线程通过本机消息调用；原文件和提取文本不因此上传。该分层提供 PDF 所需页面对象，OCR 仍须用户显式勾选。

## 验收

回归基线同步到已实施规格：68 个 OA Prisma 模型、42 个迁移、144 个权限码；审批类型包括既有 CUSTOM/PAYROLL；组织接口保留先前要求的超级管理员门控、允许删除非根且无关联组织，根组织仍禁止删除。更新过期的静态数量/旧路由测试，不放宽生产权限。数据库演练仅在明确指定的测试库与重置保护开关下执行。

成本类别保留已实施的 REIMBURSEMENT 报销同步类别。生产启动从编译后的 server/dist 加载，开发目录和 dist 均定位到同一隔离适配项目及默认数据目录；部署凭据通过环境注入，不复制到 dist。

- 原 C33 工作区指纹保持不变；独立源码可构建且不依赖外部 C33 路径。
- 独立知识库视图无完整会话侧栏、Preset 工作区及重复导航。
- 管理员真实导入、检索、Wiki、备份恢复通过；普通律师可查不可改，直接请求维护 API 也被拒绝，归档与个人会话隔离。
- 智慧办案检索同一云端 Wiki，工作区符合用户确认位置，审批、取消、恢复可用。
- 新增 Harness HTTP 端口数为零；OCR 生命周期、权限和异常路径受控。
- OA 既有检查通过，真实浏览器验证模块切换、操作反馈及品牌版本；最终本地 Git 提交。
