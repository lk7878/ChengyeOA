# SPEC-UI-20260911：全局业务表格列宽与中文显示

状态：已实现并验证。先规格后实现。关联 MOD-001 岗位管理、MOD-002 系统配置中心的表格视图体验；不改变组织、岗位权限及业务标识关系。

## 需求及验收规则

1. 岗位管理及其他使用 Ant Design Table 的业务表格统一采用可调整列宽组件。拖动表头右侧手柄改变整列宽度，触摸/指针可操作；键盘左右键微调，双击恢复默认宽度。最小 72、最大 1200 像素。嵌套表头只调整叶子列。
2. 列宽在当前浏览器按页面和列结构记忆，刷新后恢复；失败/禁用的本地存储不影响操作。只保存界面尺寸，不保存业务数据。拖动不能触发表头排序、筛选或文本选中；行选择、固定列、分页、行展开等原有 Table 属性继续透传。过宽时横向滚动，不裁掉后续操作列。
3. 所有现有业务 Table 使用同一组件。原生 Office 文档编辑表格不替换为业务 Table，以免改变文档内容操作。
4. 岗位编码是稳定标识：默认采用中文可读显示（岗位名称/编号），原值留在提示中，数据库与关联不改写；新增岗位由界面生成稳定编码，用户填写中文岗位名称，表单说明自动分配。岗位分类使用中文选项、保留既有代码值；已知类型给出中文业务名，DEPT 等历史分类仅作“部门岗位＋原序号”的中性说明，不推断为律师/行政等具体类型，未知代码标记“历史自定义分类”，提示中可查原值。
5. 应用根配置简体中文语言包和日期语言，统一确定/取消、分页、日期选择、空状态等系统文字；补齐已发现的账号绑定状态、权限/数据范围/风险/授予状态、治理状态与审核决定、案件节点/沟通类型等英文枚举。接口键、权限代码、账号、原始审计快照等技术标识继续保留，不能静默改写业务数据或用错误译名掩盖未知值。
6. 新增回归：拖动/键盘/恢复/持久化/存储失败、排序不被拖动触发、固定列与横向滚动、岗位分类中文选项提交原值、岗位自动编码、新增编辑不改原编码、全局中文默认控件、主要枚举翻译与未知回退。相关既有页面回归、类型检查、变更 lint、构建；真实浏览器检查列宽实际改变。

## 实施顺序与边界

先完成规格和追溯，再实现共用表格及中文配置，批量接入业务表格，再处理岗位表单及已定位显示点。若用户明确要求编码本身存中文，先补充该契约再调整岗位专用校验；当前按保留稳定编码、中文显示实施。本次默认不做数据库迁移，不翻译自由输入的名称及备注。

## 实施结果（2026-09-11）

- 30 个业务表格文件接入 ResizableTable，覆盖岗位、员工、权限、审批、合同、财务及其他业务列表。表头拖动、键盘调整、恢复、持久化和固定列保持行为已验收。
- 岗位使用中文编号、中文分类选项与自动编码；历史分类保留原值和中性说明。应用配置简体中文控件，账号/权限/管理操作/沟通类型等显示采用中文映射。技术标识和审计快照保留。
- 全量前端回归 283 项：初次 282 项通过，1 项因旧断言查找 ROLE 失败；调整为中文断言后，相关 15 项复测全部通过。类型检查与构建通过；全 src lint 零错误、保留 User/Notification 原有两处 hook 依赖警告，最终变更定向 lint 零错误。
- Edge 真实浏览器检查 1 项通过：实际列宽增加 100 像素、刷新保留、双击恢复、键盘调整不触发排序，行选择/分页/排序/横向滚动/左右固定列兼容；截图人工检查完成。
- 本地 3000 页面可用，7001 健康检查显示数据库可用。本次无数据库迁移或业务数据改写。
