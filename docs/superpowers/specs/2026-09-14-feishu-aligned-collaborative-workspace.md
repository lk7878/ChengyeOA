- 原有审批、权限、事件和业务模块的历史验收保持有效；其历史结果不覆盖本规格。新增的业务自助配置与系统级治理分层，向前修订 MOD-002 的旧管理员配置模式，不重写已完成 SPEC-005 的实现事实。
- 保持现有云端 OA 数据权威性、统一桌面和本地办案目录边界。工作区可用于 Web 和桌面壳，不引入第二份业务真值，不改变 Harness/Wiki 的保存规则。

## 3. 产品对象与数据关系

```text
组织
└─ 工作区（经营协作、案件交付等）
   └─ 多维表格应用 Base（如“线索与客户”）
      ├─ 数据表：线索
      │  ├─ 总表〔团队共享视图〕
      │  ├─ 我负责的〔个人视图或动态当前用户视图〕
      │  ├─ 成员甲〔授权范围内按指定负责人筛选的命名视图〕
      │  └─ 按阶段看板〔同一表的数据〕
      ├─ 数据表：跟进记录〔关联线索，允许一对多〕
      └─ 用户通过“＋”新建的其他数据表
```

1. 左侧每张表有独立 tableId、字段定义与记录集合；视图有 viewId、共享范围与显示配置，不拥有记录副本。
2. “总表”是默认共享表格视图，仍受访问者实际数据权限限制。“总表”不是绕过权限读取全库。
3. 视图的可见范围（个人/共享）和记录筛选（全部/我负责的/指定成员）是两条独立配置轴；共享视图也可以使用“当前用户”动态条件。不能把“个人视图”一律解释为只能包含自己的记录。
4. 同表各视图写入同一 recordId。筛选、分组、排序和列显隐各自保存；基础字段定义、字段值是表级变化。新增字段不自动打乱已有视图列序，由视图配置选择显示；默认总表显示有权查看的新字段。
5. 同表数据编辑导致记录不再满足当前筛选时，保存后从当前视图移出并提示；不能表现为保存丢失。创建记录不满足筛选时同样提示并提供有权限的记录链接。
6. 新增记录的业务默认值来自表/表单配置；“我负责的”视图在允许指定负责人时预填当前员工。复杂筛选不自动变为写入规则，禁止用筛选条件隐式强制业务赋值。
7. 自建表为一等能力，可从空白建立实际业务协作表，不依赖开发者新增路由、Prisma 模型或发版。核心业务表可作为预置数据源；其金额、状态、关联规则仍受领域服务约束。
8. 独立表间使用稳定 ID 关联，不通过姓名或可修改标题拼接；人员字段引用现有员工与账号映射。

### 4.1 全局顶栏和左侧目录

工作区列表提供进入现有工作区和按权限创建工作区/应用的入口；无权限用户使用管理员预置或共享的应用。创建应用后进入空白表目录并突出左下“＋新建”，不要求先创建固定业务模块。

- 全局顶栏保留组织、工作区和应用定位；我的待办、通知、知识库、智慧办案可达。管理员功能归入独立管理入口，日常页面不铺满技术管理菜单。
- 应用左侧目录列出真实数据表，支持名称搜索、选择、重命名、拖动排序及键盘移动、复制结构、归档/恢复。核心业务映射表“移出应用”不删除原业务实体。
- 左下角“＋新建”在目录长列表滚动时仍可见，菜单含“空白数据表”“从模板创建”；从文件导入在 P2 开放。无创建权限时显示禁用及原因。
- 创建弹窗输入表名后，服务端原子创建表、默认标题字段、总表视图并返回新 ID，目录立即出现并选中新表；失败保留名称且重试不重复建表。
- 表重名在同 Base 内不允许；字段显示名在同表内不允许重名。重命名不改变 ID。表复制首版只复制结构和视图，不复制数据、权限、评论及启用中的自动化；副本按应用默认权限创建。
- 归档前显示记录数量和被视图/关联/规则引用的影响；归档可恢复，不物理删除历史数据。受引用核心对象的处理遵循原领域规则。

### 4.2 视图标签栏

- 当前表顶部横向展示可访问的视图：默认“总表”，可创建“我负责的”、成员命名视图及看板等；超长标签通过横向滚动或更多菜单可达。
- 视图菜单支持新建、重命名、复制、排序、设为我的默认、删除；个人视图只删除配置。共享视图管理需管理权限，至少保留一个默认总表视图。
- 新建视图需选择名称、类型和个人/共享范围；复制视图默认生成个人副本，发布共享需相应权限。
- 修改筛选/分组/排序/列布局为本地预览，显示“未保存”；支持保存或放弃。切换或关闭前提示未保存配置；普通浏览者可复制为个人视图，不覆盖共享布局。
- 视图配置按账号保存到服务端，跨设备恢复。记录编辑自动提交与“保存视图配置”是不同操作，按钮文案不能混淆。

### 4.4 抽屉、边界状态与适配

- 抽屉容纳完整字段、关联记录、附件、业务动作和变更历史；P2 加入评论、@提醒和编辑位置提示。权限不足字段不可在抽屉绕过限制。
- 空白表给出“添加字段/新增记录”；筛选无结果给出调整筛选入口；加载、错误、无权限、已归档、字段变更、保存失败、连接断开均有明确状态。
- 桌面窗口宽度 ≥1024px 使用左侧目录＋主体布局；目录建议默认 220px，可收起。小窗口和手机将目录变为抽屉、工具栏折叠，记录以可读列表/详情呈现；网格横向滚动限制在内容区。
- 焦点可见；菜单、拖动的替代操作、弹窗关闭均可用键盘。打开抽屉后焦点进入抽屉，关闭后恢复来源；状态可被辅助技术读取。实际渲染不得裁掉主操作、弹窗或长字段名。
- 界面保持中文、轻背景、紧凑表格和蓝色主操作，与用户截图中的层级一致；使用承业品牌资产。截图对齐验收包含 1440px、1024px 和 390px 三种宽度。

## 5. 字段、关联与视图能力

### 5.1 字段类型

P1：文本、多行文本、数字、金额、布尔、日期、日期时间、单选、多选、人员、组织、电话、链接、附件、单向关联、创建人/创建时间/修改人/修改时间（系统只读）。新增字段使用稳定 fieldId；改名不破坏筛选或引用。

P2：双向关联、查找引用、汇总、受控公式。表格、看板、日历和内部表单为必交类型；画册、甘特纳入后续 P3 扩展，不以 P1 表格交付宣称全量对齐。

### 5.2 变更规则

- 普通空白字段可修改类型，已有值字段改类型必须预览可转换/失败记录数，生成迁移版本并执行适用审核；不能静默截断或丢弃值。修改选项保留选项 ID，停用已使用选项保留历史显示。
- 必填规则发布前扫描存量缺失，先补齐或保留草稿，不得让全表不可编辑。新增必填默认值的回填需预览并作为显式批量变更执行。
- 核心字段的类型和业务语义不能由普通字段配置修改；只读、可编辑、需业务动作三类能力在字段元数据与服务端写入路径中一致。
- 字段归档不删除值；依赖的视图、关联和自动化需显示影响并阻止未处理的破坏性修改。恢复前再次验证权限、依赖和配置版本。
- 日期时间统一保存明确时区语义，默认按组织 Asia/Shanghai 展示；仅日期值不因时区换日。金额使用精确小数，空值与零值区分。

### 5.3 关联和计算

- 自建表间关联从可访问表选择，不仅限于预置业务对象。关系目标需同时具有访问权限；一对多跟进记录不折叠成覆盖式备注。
- 单向关联不反写目标字段；双向关联维护同一关系，防止循环重复写入。移除关联不删除目标记录；归档目标显示受权限约束的失效标记，不泄露无权对象名称。
- 查找/汇总/公式结果只读，显示来源、计算中或错误状态；基础变化触发重算，循环依赖无法发布。
- 首轮公式支持四则运算、比较、IF、空值判断及日期差；按确定类型处理，除零/无效类型返回可解释错误。使用表达式解析器与函数白名单，禁止 eval、任意脚本和 SQL。
- 跨记录汇总先按访问者权限过滤来源，再计算；任何包含不可读字段的表达式返回无权限，不得用空值代替后泄露推断结果。预计算结果不得跨权限上下文复用。
- 批量粘贴单请求首版最多 200 行或 2,000 单元格，任一项无权限、类型错误、冲突则全批失败并定位错误；超限要求拆分。大规模导入另有任务与核对报告，不能暗中拆批后假称全量原子。

## 6. 组织协作与分享权限

1. 复用账号、员工、部门、团队；工作区角色不替代组织角色。应用/表的所有者、管理者、编辑者、阅读者作为资源能力配置。
2. 阅读者读取授权数据并保存自己的视图；编辑者可写授权记录；表管理者可配置授权范围内自建表结构和共享视图；应用管理者可创建/归档表。建表权限可以单独授给业务人员，不要求系统管理员账号。
3. 核心业务适配表访问取现有权限、数据范围与资源授权的交集；通用自建表取组织隔离、资源授权、行级和字段级规则的交集。明确拒绝和已撤销授权优先，无法计算权限时拒绝返回数据。
4. 分享弹窗可选择组织内成员、部门、团队，显示当前能力和来源。只能在授予者的可委派权限范围内授权，不得扩大组织数据范围或提升敏感字段权限；需提权的转现有治理流程。
5. P1 仅组织内登录访问；复制表/视图链接用于定位，不携带授权。外部匿名分享和匿名表单不在当前范围。
6. 个人布局修改直接保存，无系统级审批；授权范围内普通自建表/字段/共享视图配置版本化留痕直接生效。已有数据类型迁移、权限扩大、敏感级别降低、核心业务规则修改仍按高风险治理。判断依据是操作能力与风险，不是“谁是管理员”。
7. 多人在线显示实际有权知晓的应用协作者；心跳到期移除离线状态，不伪造头像。P2 展示记录编辑位置提示，提示不是排他锁。
8. P2 评论与@绑定记录 ID，通知接收者必须仍可访问记录；失去权限后链接不可访问、搜索/通知不暴露敏感摘要。评论历史和业务变更历史分别展示，不能互相替代。
9. 记录读、写、导出、关联、搜索、附件、统计与实时事件均执行授权。撤销权限不承诺收回已合法导出的文件，但必须停止后续接口访问、推送和本应用缓存显示。

## 7. 实时编辑一致性

- 云端服务为权威。普通单元格按字段 PATCH，只发送本次变化；客户端附 expectedRecordVersion、expectedSchemaVersion、idempotencyKey。缺失版本不接受协作写入。
- P1 使用记录级乐观锁。两人改同一记录（包括不同字段）只有满足预期版本者成功；另一方收到冲突，展示有权限的最新值与本地输入，明确“放弃本地/基于最新值重新提交”。禁止静默最后写入覆盖。
- 配置保存使用独立 schemaVersion/viewVersion；记录值、表结构、视图配置的版本互不混用。字段类型变化后拒绝旧编辑器写入，重新加载字段并保留可复核输入。
- 业务事务内完成值、版本、审计和可靠事件写入。发送给客户端的事件由提交后的事件消费生成，不广播未提交结果。
- P1 采用认证 SSE 增量通知＋HTTP 写入：同源安全会话或兼容现有认证的流式客户端，禁止把长期 token 放 URL。连接校验身份及可订阅范围；每次分发重新检查权限。
- 推送优先携带可授权的失效信息，客户端合并刷新表、记录、视图计数与分组；正在编辑的记录标记远端变化，不用后台刷新覆盖未提交输入。事件不含未授权记录 ID 或值。
- 事件支持游标、幂等和记录版本判定；旧版本事件不覆盖新值，游标过期时重新授权后全量重查当前视图。先订阅再取快照或使用快照游标，不能遗漏初始化间隙中的变更。
- 断线显示“连接中断/未保存”，保留当前会话未提交输入；重连先取新版本并复核，再重试。首版不承诺离线自动提交。桌面未来离线草稿同步也必须执行本规则。
- 保存反馈为“编辑中/保存中/已保存/失败/冲突”。只有收到提交成功响应或幂等结果确认后显示已保存；超时结果未知时复用原幂等键查询/重试，不能新建第二次操作。
- 权限撤销事件后立即清除受影响显示与缓存，关闭订阅；即使该通知丢失，下一次读写和分发也拒绝访问，并通过权限版本心跳刷新兜底。
- 不在 P1 引入 CRDT。后续字段级合并须另行证明跨字段业务约束仍成立。

## 8. 工程契约

### 8.1 数据及组件

新增模型为目标模型，迁移尚未执行：Workspace、Base、WorkspaceMembership、TableDefinition、FieldDefinition、ViewDefinition、UserViewPreference、Record、BusinessRecordExtension、RecordRelation、RecordRevision、RecordComment。全部保留组织/资源归属、稳定 ID、版本和必要审计。

- 核心表走 BusinessTableAdapter，调用既有领域查询/命令；通用表 Record 的字段值首版采用 JSONB，按 fieldId 存储，经字段类型校验。稳定系统字段独立保存，JSONB 不存第二份核心业务真值。
- 关联使用独立关系实体，约束表、记录、字段归属和基数；字段名不能成为关联外键。
- ViewDefinition 保存结构化筛选树、排序、分组、可见字段 ID、列序/宽度、冻结列、行高、类型、共享范围及版本；个人默认视图和导航偏好进入 UserViewPreference。
- 前端拆分 WorkspaceShell、TableNavigator、ViewTabs、TableToolbar、GridView、FieldEditor、ViewEditor、RecordDrawer、CollaborationStatus；分别负责对象导航与行为，不能把自建表路由写死。
- 表格组件选型先验证虚拟滚动、键盘、范围粘贴和受控编辑，再决定扩展现有 AntD 或更换网格组件。专业网格不是多维数据与权限引擎的替代品。

### 8.2 API 目标

统一沿用 `{ code, message, data, requestId }`；以下为目标路由，不代表已存在：

| 接口族 | 示例路径 | 合同 |
|---|---|---|
| 工作区与应用 | `GET/POST /api/workspaces`；`GET/POST /api/workspaces/:workspaceId/bases` | 按组织与资源权限列举/创建，创建者权限不超出可委派范围 |
| 表目录 | `GET/POST /api/bases/:baseId/tables` | 按权限列举/建表；创建包含默认总表，幂等且原子 |
| 表操作 | `PATCH /api/tables/:tableId`；`POST .../archive`、`.../restore`、`.../duplicate` | 版本检查、引用影响、按操作授权；结构副本不复制数据 |
| 字段 | `GET/POST /api/tables/:tableId/fields`；`PATCH .../fields/:fieldId` | 元数据版本、类型/依赖检查、受控发布；归档为独立动作 |
| 视图 | `GET/POST /api/tables/:tableId/views`；`PATCH/DELETE .../views/:viewId` | 个人归属与共享管理权限、版本冲突；删除不删记录 |
| 记录查询 | `POST /api/tables/:tableId/records/query` | 校验 viewId 属于 tableId，受控筛选 AST，稳定分页、排序、授权统计 |
| 记录写入 | `POST /api/tables/:tableId/records`；`PATCH .../records/:recordId` | 幂等、字段白名单、权限/数据版本/结构版本及领域校验 |
| 批量写入 | `POST /api/tables/:tableId/records/batch` | 显式容量限制；单批全成功或全失败 |
| 分享与协作 | `/api/bases/:baseId/members`；`GET /api/collaboration/events` | 可委派范围授权；认证 SSE，不返回超范围成员或内容 |

其他偏好、评论及复杂业务动作依相同契约扩展。UI 隐藏操作不能代替服务端授权。过滤器只接受白名单字段和类型适配操作符，不允许任意 SQL；多个资源 ID 必须校验归属关系。

新增冲突错误建议 `COLLAB_RECORD_CONFLICT`、`COLLAB_SCHEMA_CONFLICT`、`COLLAB_VIEW_CONFLICT`（409）；字段类型/批量错误返回可定位的结构化错误（422）；权限错误沿用既有规范；幂等键同键不同内容返回冲突。事务完整性遵循 FTN-004。

### 10.1 负载与非功能验收条件

继承 FTN-007 的 100 人并发在线、常用列表 2 秒内返回及备份恢复目标。新建测试基线：一个应用至少 10 张表，最大表 10,000 条记录、50 个字段；100 个在线会话中 20 个以每人每 5 秒一次操作持续读写 15 分钟，覆盖筛选、分组及 3 类权限范围。

在记录硬件、数据库索引、浏览器、网络 RTT≤100ms 的同一环境中，常用查询与普通保存 P95≤2秒；提交完成至另一在线可访问客户端可见 P95≤2秒；重连到可继续编辑 P95≤5秒；权限撤销后的后续读写立即拒绝，在线显示与订阅清理≤5秒。失败和冲突必须单独统计，不能从延迟统计中静默剔除。指标为待验证目标，不是当前性能承诺。

网格必须服务端分页/筛选/分组并虚拟化，不一次下载全部表；导出和大附件走受控异步/独立上传，不能阻塞网格操作。数据库备份包含新元数据、记录、关系、历史，附件保持一致恢复；视图回滚不能回滚权限或覆盖业务记录。

## 11. 飞书迁移与实施边界

迁移先盘点实际表/字段/视图/关系/公式/规则/权限，建立飞书 ID 到 OA ID 映射，使用合成或获授权测试样本验证；不能从截图推断实际模型。公式、权限、附件和自动化需要单独映射，CSV 导入不代表完整迁移。

进入实现时按 P1→P2→P3 分批建立任务与证据，更新 TRACE 的实施状态；frontmatter implements 只记录实际落地项。不可使用本规格的存在替代代码验收。
