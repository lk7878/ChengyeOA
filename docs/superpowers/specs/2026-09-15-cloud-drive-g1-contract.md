# 云盘 G1 技术契约

日期：2026-09-15。对应 [SPEC-DRIVE-20260915](2026-09-15-feishu-cloud-drive-resource-center.md)。本契约先于实现落盘，实施和验收状态见[计划](../plans/2026-09-15-feishu-cloud-drive-resource-center.md)。第七批负载已通过并提交 172f126d；新增文件夹链的 G1 持续验收单独记录。

## 1. 资源身份及迁移

- 新增统一 `DriveNode` 目录节点，类型首批只开放 `FOLDER` / `BASE`。字段包括稳定 ID、workspaceId、parentId、ownerId、目录元数据版本、创建/目录修改时间，以及 folderName / baseId / accessPolicy 等类型专属字段。
- BASE 节点 ID 与 baseId 相同，baseId 唯一；标题仅来自 `CollabBase.name`，应用权限仅来自 `CollabBase.accessPolicy/accessVersion`。不得在目录节点复制标题、表、视图、记录或业务权限。FOLDER 使用自身名称、版本和策略，不能关联 Base。沿用既有 Base 名称在工作区内唯一的约束；文件夹名称在同一父级下唯一。
- parentId 只能指向同工作区的 FOLDER；数据库保留 FK/类型约束，服务在工作区写锁内校验父节点和深度。首批最大 8 层；移动接口不开放，因此无法通过编辑 parentId 形成环。
- 旧 Base 幂等回填为根目录 BASE 节点，沿用原 ID 和全部 ACL；ownerId 取既有工作区负责人，用于归类，不额外授予权限。历史 Base 没有可信创建时间时保持未知，不伪造原始创建日期。迁移重复执行不得创建重复节点。
- BASE 列表修改时间取目录元数据与当前应用最新协作事件的较晚值，不在每次记录保存时更新同一目录行，避免将多人写入重新串行化。FOLDER 修改时间只代表目录元数据变化。
- 新建 Base、目录节点、默认空白表/标题字段/总表和审计在同一事务建立；旧创建 API 也写入目录节点，防止出现两个资源入口。默认表创建仅用于云盘新建闭环，已有 API 的既有表创建语义保持。
- 迁移不清理开发数据。应用回退首先关闭云盘入口，原 Base ID/内容继续保留；存在文件夹限制的数据不能直接回退到忽略文件夹 ACL 的旧服务。须先由授权管理员检查并转存等价资源限制，再回退访问逻辑。不得通过删除目录表解除授权。

## 2. 权限决策表

所有账号共用云盘和表格界面。普通用户的 SELF 继续以 `createdBy` 判断；ownerId 仅用于目录归属，不替代记录范围。

| 条件 | 结果 |
|---|---|
| 无有效工作区成员资格、离职/停用/会话撤销 | 目录和内容均不可访问，系统管理员身份不自动授予访问 |
| 工作区显式 OWNER | 保留既有资源负责人例外，可管理该工作区的文件夹/Base/表；不是全系统绕过 |
| 普通成员，上级或本级匹配 DENY | 禁止访问，子级授权不能恢复 |
| 本级独立名单开启、没有匹配主体 | 禁止访问 |
| 本级未限制且没有匹配主体 | 继承上级 |
| 有匹配允许项 | 角色取上级与本级有效角色的较小值；SELF 取逻辑或；隐藏/只读字段合并；创建能力取交集 |
| 文件夹或资源 ownerId 等于当前用户 | 用于“我的”归类，不跳过任何上级 ACL，不隐式获得分享管理权限 |
| 修改授权 | 沿用工作区 `canManageAccess` 的显式委派；普通用户可看本人有效权限说明，完整协作者名单与编辑只给授权管理者 |
| 创建文件夹或 Base | G1 沿用应用创建管理级能力，要求工作区及当前文件夹有效管理角色；不是拥有系统管理员身份才可新建 |
| 文件夹下的应用/表直链、查询、附件、关联、历史、SSE | 先通过完整文件夹链，再通过应用/表及业务规则；禁止只保护云盘列表 |

- 有效主体复用 USER、有效任职 POSITION/ORG 和 TEAM；授权名单只接受工作区既有主体及已验证的资源创建者账号。创建者可能通过岗位/部门加入工作区，界面可把该账号列为资源创建者以便设置个人目录规则，但不自动增加工作区 USER 成员或扩大上级权限；离岗失去上级资格后仍不可访问。显式工作区 OWNER 不通过子级名单重复授权。
- G1 文件夹策略管理角色、创建能力及 SELF/ALL，字段限制继续在工作区/Base/表配置；文件夹接口拒绝非空字段 ID 规则，避免空文件夹配置无目标的字段规则。
- 新建根文件夹默认独立名单仅含创建者，工作区 OWNER 保留例外。新建子文件夹默认继承父级；在文件夹内新建 Base 默认继承文件夹。根目录新 Base 默认只授权创建者。分享管理者可按上表调整。
- G1 采用完整祖先链可访问规则：单独授权子文件夹不会赋予父文件夹访问权，父级禁止时子级仍不可访问。页面说明“受上级限制”，不通过展示不可见祖先名称解释原因。
- 降级为只读后不能通过旧按钮或旧幂等结果继续新写入。授权修改与记录/结构修改复用同一工作区锁边界；撤销后新请求立即按当前权限拒绝，已打开页面在 5 秒内清理失效资源。

## 3. API 与事务

统一 `/api/v1` 前缀，错误、版本冲突及 `Idempotency-Key` 复用协作接口契约；所有写接口先预检，再在事务工作区锁内重新校验。

| 接口 | 行为 |
|---|---|
| `GET /workspaces/:workspaceId/drive` | 授权后筛选个人/共享/当前目录及搜索，按名称或修改时间排序；分页和总数均在权限过滤后计算 |
| `GET /workspaces/:workspaceId/drive/folders` | 只返回可访问的文件夹树、稳定 ID 与可见祖先；无权节点不返回名称或子项数量 |
| `POST /workspaces/:workspaceId/drive/folders` | 新建文件夹，校验父级、重名、深度和创建权限 |
| `POST /workspaces/:workspaceId/drive/bases` | 创建一个 Base 及默认表/总表，返回原编辑器使用的 baseId/tableId |
| `PATCH /drive/nodes/:nodeId` | G1 只接受 name/version；FOLDER 修改节点名，BASE 修改唯一 Base 标题；禁止借此修改类型、归属、父级或权限 |
| `GET /drive/nodes/:nodeId` | 返回授权后的类型、路径、版本和有效操作，用于编辑器返回原目录及只读权限解释 |
| `GET/POST /drive/folders/:folderId/access` | 授权管理员读取/修改文件夹策略；复用现有主体、独立名单和版本冲突规则 |

- BASE 分享继续走现有 `/bases/:baseId/access`；表分享继续走 `/tables/:tableId/access`。不引入第二套 Base ACL。
- `scope=mine/shared` 是对目录 ownerId 的个人入口归类，不是业务数据过滤。全局个人/共享入口可定位同一节点；真实 folderId 决定所在位置，不能复制 Base。默认当前目录无 owner 过滤，显示有权访问的子项。
- “我的/共享文件夹”按归属分组，可见祖先用于定位；跨组嵌套仍保持真实 parentId 和完整可见路径，不伪造父级或把工作区当文件夹。
- 请求内可复用一次主体解析和树权限计算；不能跨请求缓存授权。列表获取元数据后按同一策略函数过滤，搜索、计数、分页不提前暴露未授权数据。
- 目录变化记录审计，Base 变化同时使用现有协作事件/outbox；文件夹权限变化必须让已有 Base 订阅在下一次实时鉴权发现。目录页每 2 秒及重新聚焦时重新获取当前授权列表；错误明确提示并提供重试，撤权清理失效选中项。
- 名称冲突返回 409；版本过期返回 409 并保留输入；无权限返回 403；资源不存在返回 404；类型/层级/未知字段非法返回 422。后端不在错误中返回不可见节点标题。

## 4. UI 与开放边界

- 云盘壳独立于大型表格编辑器，复用现有工作区 API、设计变量和授权组件。`/workspaces` 无 base 参数进入云盘；既有 `?base=...&table=...&view=...&record=...` 直链继续使用原编辑器。
- 云盘左侧为工作区切换、搜索和“我的文件夹/共享文件夹”树；主区为面包屑、新建、排序、资源列表/卡片切换，显示资源类型、标题及可信时间。首批不显示无功能的上传、模板、快捷方式、移动或回收站按钮。
- 新建菜单仅开放当前权限允许的文件夹/Base。创建 Base 后进入默认表和总表；返回时保留 workspaceId/folderId、查询与布局状态，路径失效时回到有权根入口并提示。
- 分享面板先解释当前角色、SELF/ALL 和上级限制；拥有授权管理能力者再编辑名单。管理员、负责人和普通成员使用同一组件与路由。
- 桌面 1440、小窗口 1024、手机 390 宽度下有可用导航；按钮和目录可键盘操作，焦点、空态、加载、失败重试与版本冲突可见。

## 5. G1 必须验证的风险

1. 旧 Base 接入重入不重复，内容 ID/视图/记录/ACL 不变；在旧接口新建也有唯一目录节点。
2. 三角色同 UI，创建文件夹→建 Base→默认表编辑→返回路径→共享账号打开同一记录闭环。
3. SELF、隐藏/只读字段、祖先 DENY、独立名单及工作区负责人例外；直链、HTTP、附件/关联和 SSE 同步受控。
4. 文件夹授权撤销时现有编辑器与目录清理、读写失败；仅改变个人/共享入口或视图条件不能提权。
5. 创建、重命名和授权并发、旧版本、幂等重放及中途失败回滚；API 拒绝 parentId/ownerId/type 越权更新。
6. 与现有 OA/表格协作回归一起验证，原 AC-15 维持原规模和门槛。目录页先覆盖 500 个合成资源（含 8 层目录）的分页、授权计数与搜索，目标同机查询 P95 ≤ 2 秒；这不替代原协作 900 秒负载。

移动、快捷方式、回收站、上传、模板、收藏和在线文档协作均留在 G2/G3，另行补充契约后实现。
