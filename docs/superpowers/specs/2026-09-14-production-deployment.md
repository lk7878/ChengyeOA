# ChengyeOA 部署规格

## 1. 范围与判定原则

本规格落实已确认的[统一桌面架构](2026-09-13-unified-desktop-local-harness.md)和[百佑办案助手及唯一 lawyer preset](2026-09-13-baiyou-lawyer-preset.md)。本次交付仅为部署规格、实施计划和追溯，不执行云资源采购、生产部署、数据库迁移、安装包开发或运行代码修改。`approved` 表示部署边界已确认，未决参数仍须在相应阶段记录；不代表已有生产部署或性能验收。

云端管理 OA 和公共 Wiki；律师 Windows 客户端运行个人 Harness。个人材料、会话、提取结果和成果留在本机，不能纳入 OA/Wiki 的自动同步或服务器备份。个人视觉任务向用户配置的在线模型 API 发送必要内容，与管理员云端 Wiki OCR 分开。源码仍分为 OA、导入 Harness、集成适配三部分；原 C33 项目只读。

目标产品为“律师智慧管理系统 V1.3.0”，助手名为“百佑办案助手”。现有 OA 显示 V1.2.1、桌面开发构建 `1.3.0-dev.2`；不得仅因本规格更新而修改运行版本或宣布 V1.3.0 已发布。

## 3. 云端组件与进程边界

| 组件 | 职责与运行约束 |
|---|---|
| HTTPS 入口与静态 OA 页面 | 对外提供同一受控 OA 来源、前端静态资源和 API 代理；生产不使用 Vite 开发服务器 |
| OA Node/Egg 业务服务 | 认证、权限、业务校验、附件接口、审计；当前 `start` 固定一个 OA Worker。受进程管理器监管，明确启动工作目录、优雅停止和故障重启策略 |
| OA 事件 Worker | 当前由 OA `app.ts` 启动与关闭，负责事件、超时扫描等业务任务；不是 Wiki 编译队列。不得为“扩容”重复启动未经验证的消费者 |
| PostgreSQL | 正式业务状态、账号/权限、附件元数据及当前审批附件 Bytes 等权威数据；只允许业务服务和受控运维连接 |
| 附件持久存储 | 当前为混合存储：案件文件字节落本地文件系统，审批附件字节在 PostgreSQL；两者均须覆盖备份。若统一改为对象存储，须另有适配与验收 |
| Wiki Host | OA 内适配服务按需通过原生 CLI Profile 启动独立 Node 子进程，私有 Node IPC 通信；拥有云端 Wiki SQLite、原文和编译状态，不开放独立公网 Harness HTTP 服务 |
| Wiki OCR Python 子进程 | 当前由适配器按请求启动，以 stdio 收发受限图片任务，复用 PaddleOCR worker；不部署为律师电脑服务，也不是已存在的远程 OCR 集群 |
| 运维备份与监测 | 备份存储、恢复演练、日志、证书到期及进程/任务监控；落地工具与调度方式在测试环境阶段确定 |

OA 模块、Harness 源码、适配模块分开维护，并不要求购买三台服务器。初始拓扑可以在同一云端主机中隔离进程和持久卷，PostgreSQL 也可使用独立受管实例；是否独立 OCR 计算节点，应根据真实负载和选定方案决定，当前 stdio OCR 不能直接当作远程服务使用。

当前 Wiki 数据目录使用本机 PID/文件锁，生产基线限定**一个 OA 实例、一个 OA Worker、一个 Wiki 数据目录写入者**。该锁不是跨主机分布式锁；禁止多个副本共用网络目录上的同一 SQLite 并认为已实现高可用。扩展多实例、外部任务队列、远程 OCR 或拆分 Wiki 服务前须另改 Spec 和代码并验收。

普通浏览器的目标能力是 OA 和 Wiki，完整本机办案使用统一客户端。当前仍保留 V1.2.1 浏览器浮动办案和云端临时办案代码；生产候选包必须完成旧入口/API 的受控退役及 OPFS 导出/保留说明，防止继续误走旧云端办案路径。浏览器唤起客户端的协议注册、未安装引导均需实际实现和验证，不能假定现已支持；旧数据不得直接清空。

## 4. 目标环境与资源决策

| 项目 | 候选/约束 | 上线前必须落实 |
|---|---|---|
| 云端 OS | 可评估 Linux x64；目前证据主要来自 Windows 开发机 | 选定发行版、版本、CPU 架构、服务管理/容器方式，完成该 OS 全链路构建与运行；未通过前不标记 Linux 受支持 |
| Node 与包管理 | OA 当前要求 Node 22.x；集成说明基线为 22.20+ 的 22.x，上游锁定 pnpm 11.7.0 | 发布清单固定实际验证的 Node 补丁版本、npm/pnpm 版本和锁文件摘要，不能自动采用未测新版本 |
| 数据库 | 仓库开发基线为 PostgreSQL 16 | 固定目标补丁版本及 pg_dump/pg_restore 工具版本；本地 Compose 含开发账号、默认口令和端口映射，不能直接充当生产配置 |
| Wiki 原生依赖 | Node SQLite、sharp、PDF/canvas、文档解析组件等实际依赖 | 按选定 OS/架构安装与构建，测试 SQLite 读写、中文文件、图片、PDF、DOCX/XLSX；Windows DLL 加载顺序适配不证明 Linux 环境通过 |
| OCR | 当前实现为 Python + PaddleOCR + PP-OCRv5-server，本机云端 stdio 调用 | 固定 Python、Paddle/PaddleOCR、模型文件及摘要；验证模型缓存权限、无临时下载启动、真实样本。GPU 方案另验证驱动、运行库、显存；不先认定必须购买 GPU |
| Windows 客户端 | 首期 Windows 桌面，开发验证使用 Electron 43.4.0 | 指定支持的 Windows 版本、x64/其他架构、普通用户权限和原生依赖矩阵；ARM64、macOS 等未验收不得承诺 |

资源决策单由业务负责人和运维在测试环境前填写：注册人数、峰值在线人数、同时业务请求/附件上传数、同时 Wiki 检索数、每日导入页数、扫描图片比例和分辨率、最大单件材料、编译并发及模型限额、当前数据量和增长量、备份保留周期、预算及可接受停机时间。区分律师电脑的模型调用与云端 Wiki OCR 负载。

测试计划据此填写峰值吞吐、p95 响应时间、任务等待上限、存储余量及失败率目标，再用实测 CPU/RAM/IO/网络/队列等待数据选择资源。未填人数、OCR 方案和恢复目标前，不确认 CPU、内存、GPU、磁盘采购规格或并发容量。

## 5. 域名、HTTPS 与网络范围

- 生产选定固定 OA 域名和 HTTPS 来源；前端、API 与桌面登录页面优先同源。域名、证书申请/续期、告警责任人登记在部署清单；本规格未指定或注册域名。
- 对外开放 HTTPS 入口；如需 HTTP，只用于受控跳转/证书流程。PostgreSQL、OA 内部监听、Wiki IPC、OCR stdio、进程调试端口均不面向公网。SSH/RDP/数据库运维通过受限管理通道。
- 防火墙和反向代理同时约束访问范围。开发的 3000、7001、55432/55433 等端口不是生产公网清单；以实际发布配置记录内网监听并从外部验证不可直接访问。
- 配置准确的 CORS/可信来源、代理头信任、Secure Cookie 和现有 CSRF 机制，使用真实 HTTPS 验证登录、刷新、退出、管理员增强认证及跨源拒绝。不能通过通配来源或关闭校验解决部署问题。
- API、登录响应和知识内容不经共享缓存。静态资源按版本管理缓存及正确 MIME；不得缓存过期的 OA 页面与新的桥接脚本混用。
- 当前智能接口支持专用 octet-stream JSON 请求体最多 32 MiB；普通 JSON 默认上限 1 MiB、multipart 另有 10 MB 配置。代理须按实际路由测试编码后大小和边界，不能只把全站上传限制统一放大。编译调用当前最长 600 秒，代理超时必须与任务生命周期一起验证。
- Windows 本地 Harness 仅监听受认证的 `127.0.0.1` 动态端口，不开放局域网访问，不带生产调试参数。OA 页面不能取得任意本机文件/Shell/API 密钥；沿用精确来源、主框架和固定消息的桌面桥。
- 云端只向配置的模型服务、必要的软件/模型分发源等出站；律师本机向 OA 和个人模型 API 出站。代理/私有 CA 必须正常验证 TLS，不能禁用证书验证。查询关键词可能包含必要案情，不把“无文件同步”描述为“无任何数据出站”。

## 6. 配置与密钥归属

| 配置类别 | 所有者、保存及交付规则 |
|---|---|
| OA `DATABASE_URL`、`JWT_SECRET`、`APP_KEYS` | 云端运维秘密配置，按环境隔离；生产不得复制示例口令、开发数据库或测试身份 |
| `MFA_ENCRYPTION_KEY_V1` 及后续密钥版本 | 云端秘密管理，与对应数据库备份配套可恢复；密钥单独受控保管，不混入数据库导出包、日志和 Git |
| 认证/运维开关 | 生产使用正常权限与 MFA；`LOCAL_PASSWORD_LOGIN` 是受限开发开关，不用它取消云端认证。超管恢复开关只用于受控交互流程，不能作为启动自动操作 |
| 域名、端口、可信来源、日志及事件参数 | 云端发布配置；核对实际消费位置和工作目录，`.env.example` 中出现的变量不自动等于部署时已生效 |
| `CHENGYE_INTELLIGENCE_DATA_DIR` | 云端 Wiki 持久根目录；部署时显式设置绝对路径，不能落在易删除的发布临时目录 |
| `CHENGYE_MODEL_API_KEY/BASE_URL/ORIGINS`、`NODE_EXTRA_CA_CERTS` | 云端 Wiki 编译的模型凭据、受控服务来源及信任证书，不打入前端或律师安装包；记录轮换与撤销步骤 |
| `CHENGYE_OCR_PYTHON/MODEL_CACHE/DEVICE` | 云端 OCR 环境和模型目录，无凭据写入客户端；对所选 Python 环境逐项验证 |
| 桌面 OA 地址、安装运行时位置 | 安装器/管理员提供受控配置；现开发版 `desktop.json` schema 为 1，含机器绝对路径，不能原样复制到其他电脑 |
| 个人模型凭据 | 由律师在本机 Harness 原生设置中配置和保存，不同步 OA；系统管理员云端 Wiki 密钥不能作为安装包默认个人密钥 |
| OA 登录令牌 | 留在 OA 现有认证客户端边界，不交给 Harness/模型或写入 Host 环境；首次 Wiki 查询绑定 OA 账号和来源，换账号须新建不继承旧历史的会话 |

部署、备份和支持日志只记录秘密名称/版本及处理结果，不打印值。最小化继承到子进程的环境变量，验收秘密轮换、失效身份、错误来源和用户切换；恢复时不能把测试密钥反向写入生产。

## 7. 持久数据与目录清单

以下“目标位置”是部署约定，不代表代码已有这些配置项。云端示例以独立数据卷表示；实际路径在选定 OS 后登记。

| 数据 | 当前实现定位 | 目标持久化与权限要求 |
|---|---|---|
| PostgreSQL 数据 | 开发 Compose 命名卷 | 正式独立数据卷或受管实例，含必要备份/日志策略；不随应用删除 |
| OA 业务附件 | 案件文件按服务 `process.cwd()/var/storage/case-files` 写入；审批附件 `ApprovalAttachment.bytes` 存在 PostgreSQL | 发布前形成全量附件清单，分别注明数据库/文件存储；文件目录挂载到独立持久数据目录，不能假设已有统一 `UPLOAD_DIR` 变量。验证 npm/进程管理器的实际工作目录 |
| Wiki | 默认仓库 `LayerManage/law-firm-system/var/intelligence`；显式变量可覆盖；其中 `wiki/home/knowledge.db` 等原生状态 | 持久化整个所需 Wiki 数据集合：原文、BLOB/外部文件、数据库及日志、编译内容/索引、维护配置；不能只取一个 `.db` |
| OCR 模型及缓存 | `CHENGYE_OCR_MODEL_CACHE` | 与业务原件分开；模型版本和摘要可重建，临时图片按明确生命周期清理；不能误删原文 |
| 服务日志、审计、任务状态 | OA 日志/数据库与 Wiki 原生状态，部分请求在内存中 | 区分可丢弃诊断日志与必须保留的审计；制定轮转、空间告警和保留期，不能把进程内 pending 表当持久任务队列 |
| Windows 客户端状态 | 默认 `%LOCALAPPDATA%/ChengyeOA/desktop`：`client/`、`harness/`、`desktop.json`；可用绝对 `CHENGYE_DESKTOP_HOME` | 与安装目录分离；保留会话、工作区关联、原生设置和凭据。换来源会影响身份绑定/浏览器缓存，必须有迁移指引 |
| 律师材料与成果 | 用户选择的真实工作目录 | 不自动上传，不因更新/卸载/退出 OA 删除；由用户自行管理备份，不声称云端备份覆盖此数据 |
| 历史浏览器 OPFS | 原域名/浏览器/账号的本机站点存储 | 提供旧站点可用期间的导出和核验流程；换域名或清除站点数据前完成保留，不能推定桌面已自动迁移 |

安装程序、静态资产和构建产物可替换；持久数据不在发布回滚的删除范围。备份产物、运行目录和凭据均不提交 Git。

## 8. 备份与恢复验收

1. 业务负责人批准 RPO（可接受数据丢失时间）、RTO（可接受恢复耗时）、保留期和恢复负责人后，运维再设计全量/增量频率、异地或独立故障域副本、加密和访问策略。未填这些值时不能宣称达到灾备目标。
2. 备份集合必须包括 PostgreSQL、所有 OA 附件、Wiki 完整状态、必要配置及独立保管的匹配 MFA 密钥版本；另保存对应发布产物、迁移版本、模型版本和备份时间/摘要清单。
3. 一致性备份应有可复现操作顺序：阻止新写入和编译/OCR任务，等待或明确取消在途任务，暂停业务事件写入，取得数据库和文件系统的同一恢复窗口，再恢复服务。若采用在线备份，必须先验证其一致性协议。SQLite 使用受支持的一致性导出/备份或停写快照；不能在写入中仅复制主 `.db` 而遗漏 WAL。
4. 原生 Wiki JSON 导出/恢复可用于经验证的小规模逻辑迁移，不代替全量灾备；现有 32 MiB 入口限制及外部文件覆盖范围须测试，大库要有运维备份路径。恢复产生标识冲突时停下检查，不静默覆盖原库。
5. 在独立空白恢复环境实际执行恢复，隔离模型调用、通知和事件副作用。使用匹配密钥验证 MFA 因子与授权，检查案件、组织、财务、审批等记录和附件关联、文件数量及摘要、抽样文件可读、Wiki 原文及编译引用、索引查询、管理员/律师权限。成功登录或生成备份文件均不足以判定恢复通过。
6. 记录备份开始/完成时间、版本、摘要、恢复耗时、恢复时间点、失败项与 RPO/RTO 对比。至少完成一次“原主机和原数据卷不可用”的独立恢复演练，不能仅在原盘上读取副本。
7. 现有 [PostgreSQL 恢复手册](../runbooks/postgresql-backup-restore.md)仅是本地空基线演练。其 `dropdb` 和空表断言不能原样用于正式业务库恢复；新部署阶段须编写目标环境手册，不在本次执行它。

## 9. 数据库迁移、发布与回退

- 发布包列明 Git 提交、OA/集成/Harness 来源指纹、依赖锁、构建系统、数据库迁移清单、接口版本和安装包摘要。三个源码模块分别维护，交付物要记录一套经过联调的版本组合。
- 当前云端适配通过相对目录发现模块，桌面也依赖本地绝对路径。首个候选交付须选择保留已验证目录结构或实现并验证重定位；不能只复制 OA 的 `dist`/旧单文件 exe 就宣称包含完整 Wiki。
- 在隔离测试数据副本上演练升级。正式迁移由受控一次性步骤执行已提交的 canonical Prisma migrations，使用服务包 `db:deploy`（`prisma migrate deploy`），检查状态与退出码；不运行 `migrate dev`、reset、测试 seed 或空表断言清理已有业务数据。
- 新装空库初始化与已有库升级分开。首次超管只走[交互式 bootstrap](../runbooks/system-bootstrap-and-super-admin-recovery.md)，已有库不得再次初始化，不内置公共默认密码。
- 发布顺序：校验产物和备份 → 进入维护窗口并停止新写/新任务 → 停稳旧写入者 → 单次迁移 → 启动新服务 → 检查业务/权限/Wiki → 恢复流量。数据库就绪、OA 可用、Wiki/OCR 可用分别判定；缺少 OCR 时给出真实不可用状态，不能伪装编译成功。
- 当前单写入限制下禁止新旧 OA 实例同时挂载同一 Wiki 目录进行蓝绿写入。流量切换、服务停止和在途长任务处理必须演练，不能仅切软链接而保留旧进程。
- 仅在旧代码兼容新数据库及 Wiki schema 时允许直接回退应用。破坏性迁移或本地格式升级不支持降级时，保持维护状态，由负责人选择经验证的前向修复或整套一致性恢复；不得只恢复 PostgreSQL 而留下新附件/Wiki 状态，也不能恢复旧备份覆盖发布后新增记录而不评估数据损失。
- Wiki SQLite/原生会话格式版本独立于 OA Prisma 迁移；不能推定安装旧版引擎就能打开新版数据。每次版本组合须测试该方向的升级及允许的回退路径。

## 10. Wiki 编译与 OCR 任务运行

现状是受权限保护的管理员请求 → OA 适配 → Wiki Node Host → 必要时 Python OCR。调用含超时、取消和进程退出处理；OCR 当前限制同一 Node 进程最多 2 个请求、单张图片最多 15,000,000 字节、超时 300 秒，繁忙会拒绝而不是进入持久队列。云端调用上限 600 秒不是“重启后自动续跑”的保证。

上线前必须选择并验收一种任务模式：首期维持受限在线请求、明确不能保证断线续作；或另立实施变更新增可持久化的任务/队列。不得未经实现将编译描述为可靠后台任务服务。任务要能标识操作者、资料版本、开始/结束/失败状态；从原生持久化结果确认成功，超时或断线不能仅由前端认定失败后盲目重复编译。

测试覆盖管理员导入、OCR、编译发布、律师原文与编译引用查询，禁用知识库、撤权和非管理员直接调用维护接口；包括断网、超时、取消、子进程崩溃、OOM、磁盘满、库锁冲突和重复提交。失败保留原文和上一有效发布版本，对部分完成和陈旧状态给出明确结果。进程重启后核验哪些状态已落盘、哪些需要管理员手动重试，记录幂等边界和清理规则。

使用已脱敏或授权样本，覆盖中文扫描件、旋转/模糊页、表格、长材料。由业务人员确定准确率/错误容忍标准，并复核法条、数值和来源；夹具测试不能代替真实模型/OCR 验收。查询不得自动触发维护、OCR或把个人会话写进公共 Wiki。

## 11. Windows 安装、更新与兼容

### 11.1 安装包交付要求

独立安装包须包含匹配的 Electron、Node 22.x Host 运行时、正式 Base → Web → Product Profile 所需插件、唯一 lawyer、集成适配、原生 Web 静态资源、品牌构建产物、必要 native 二进制/运行库、许可及来源清单。按真实依赖图闭合检查，包括 SQLite、sharp/PDF 相关组件和 Windows Shell/目录选择能力；不把服务器数据库、云端模型秘密或 Wiki 数据库打入安装包。

开发版 setup 使用 CLI `link:` 安装本仓库插件并引用 `nodePath/vendorPath`，正式包须消除开发机路径、符号链接目标和原 C33 目录依赖，在安装目录内重定位并验证。用户无需预装 Git、Node、pnpm、Python、PostgreSQL、编译工具或完整仓库。既有 `build-installer`/Inno Setup 脚本需按新交付范围重新适配，尚无统一安装交付通过记录。

干净 Windows 普通用户账号完成：可信来源安装 → 启动统一客户端 → 确认 OA 地址 → 首次登录及所需改密/MFA → 打开百佑助手并接受适用的首次声明 → 选择中文/含空格的本机目录 → 配置个人模型 → 使用唯一 lawyer → 本地成果保存 → 在线 Wiki 查询 → 退出重启恢复。登录账号由云端初始化/员工账号流程提供，不能分发开发机临时密码。

### 11.2 应用更新与数据保留

首期至少交付可验证的人工更新/修复安装流程；**自动更新目前不存在**，更新源、签名、信任链、通知、下载校验、失败回退及更新窗口另行设计与验收。不能把远端 Wiki 内容当更新脚本或 Cordis 插件自动执行。

更新前检查运行中的模型/工具任务与未发送草稿，允许保存并延后更新；新包验证成功后才切换，不能在工作目录执行中替换运行时。安装目录与 `%LOCALAPPDATA%`/用户工作目录分开，更新、修复安装和卸载默认保留数据；清除数据必须是独立、明确的用户操作。验证个人设置、凭据、历史会话、Wiki 账号绑定、工作目录路径及未知旧 preset 的错误提示。

安装失败、下载中断、磁盘不足、权限不足、杀毒软件拦截、旧版本仍在运行和升级中断均须验证。回退不允许用旧引擎损坏新格式数据；提供可恢复的本地备份/兼容说明。个人电脑备份不自动变成云端同步。

### 11.3 接口与版本兼容

建立发布兼容表：云端 API、远端 OA 前端、preload 桥版本、本地插件、Harness 引擎/数据格式和客户端版本分别列出。当前 `window.chengyeDesktop.version === 1`、固定只读接口及参数白名单只是现状；版本协商、最低客户端版本检查和升级提示须后续实现。

每次云端更新测试当前客户端和明确承诺支持的上一发布客户端，含在线查询、权限撤回及错误反馈；不能让远端 OA 新页面调用旧 preload 不存在的方法后无提示失败。非兼容组合应禁用受影响的云端功能、提示升级，继续保留本机原件和可读历史；不能静默扩大桥权限。尚未确定兼容窗口时，不承诺长期兼容所有旧版。

## 12. 日志、故障定位和运行验收

部署清单记录进程/服务名、启动目录、日志落点、配置来源、健康检查和负责人。诊断按层定位：HTTPS/证书与反向代理 → OA 登录/授权/数据库 → Wiki 子进程/目录锁/SQLite → OCR Python/模型 → Windows 桌面入口/插件 → 本机 Host/个人模型。记录时间、组件/版本、脱敏错误码、任务或关联标识、退出码和必要性能指标。

不记录密码、令牌、完整请求正文、模型密钥、卷宗内容和不必要的本机路径。支持包由用户预览脱敏后主动导出，不能自动上传整个工作区。设置日志轮转、磁盘/进程退出/证书到期/备份失败/任务失败告警；现有局部诊断不等于已有统一生产监控。

故障手册至少覆盖：入口不能启动、OA 未登录/失效、跨账号 Wiki 拒绝、非管理员维护被拒、Wiki 锁冲突、OCR 未配置/繁忙/超时、模型接口不可用、上传被代理拒绝、磁盘满及恢复失败。不能用关闭认证、删除状态目录或杀掉全部 Node 进程作为通用修复步骤。

## 13. 阶段交付与未决事项

分阶段任务、验收用例和证据模板见[实施计划](../plans/2026-09-14-production-deployment.md)。顺序为文档 → 云端测试环境和真实权限 → 干净 Windows 安装验收 → 小范围试用和正式上线。跨阶段前确认交付证据与未解决阻断项，不以“代码存在”代替实测。

| 决策 | 责任角色 | 最晚解决节点 |
|---|---|---|
| 人数、峰值并发、材料量、性能目标、预算 | 业务负责人 + 运维 | 选择测试资源前 |
| 云服务商/地域、OS、域名、网络、数据库托管方式 | 系统负责人 + 运维 | 云测试环境建立前 |
| OCR CPU/GPU、真实模型、任务在线/队列方式、准确率标准 | 管理员 + 技术/业务负责人 | 云端任务验收前 |
| RPO/RTO、保留期、故障域、恢复责任人 | 业务负责人 + 运维 | 备份方案验收前 |
| Windows 支持矩阵、安装权限、签名/分发、人工更新与兼容窗口 | 客户端维护者 + 管理员 | 安装包候选交付前 |
| Wiki 本地快照及离线撤权边界 | 用户/系统负责人 | 独立同步功能立项前；不阻塞当前在线查询部署 |
| 主动归档、离线草稿、旧 OPFS 迁移等的试用范围与完整 V1.3.0 发布条件 | 产品负责人 | 试用和正式发布评审前 |

本规格不取消原 V1.3.0 尚未完成的功能验收。可对明确列出限制的开发/试用版本开展试点，但完整 V1.3.0 正式发布必须达到原规格要求，或先取得明确的范围与版本调整决定。
