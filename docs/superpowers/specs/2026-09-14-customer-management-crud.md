# 客户管理查询、修改与删除

根据用户要求，先补充规格，再实施和验证，完成后提交本地 Git。本规格增量替代历史客户接口不提供删除的限制。

1. 客户列表操作列明确提供查询、修改、删除。查询打开完整详情；保留姓名/编号模糊搜索、完整电话号码精确搜索及状态/类型筛选、重置与分页。
2. 修改从列表直接进入该客户的档案编辑弹窗，复用现有可拖动弹窗。回填普通字段，允许清空可选字段；电话必填规则保持有效，脱敏电话/微信不作为实际值回填，留空表示保持原值，输入新值才修改。每次打开重置表单，取消不保存。提交界面读取的 version，过期版本拒绝覆盖并提示刷新；旧接口调用不传 version 时保持兼容。
3. 新增 customer.delete 高风险动作权限，通过增量迁移供给，不自动授权普通角色。查询和修改沿用 customer.read/customer.update；列表和详情按权限显示相应动作，后端独立验证动作与客户数据范围。
4. 删除确认显示客户编号和姓名，携带 version；采用 Customer 已有 deletedAt 软删除，保留原档案与审计。同一事务校验版本和业务关联，软删客户及其联系人并记录 CUSTOMER_DELETE 审计；审计失败全部回滚。不存在、已删除或范围外客户不泄露存在性。删除后客户列表、查询、案件客户选择不再提供该客户，分页最后一条删除后回到有效页。失败保留记录并反馈原因。
5. 已有关联来源线索、转介绍线索、案件、合同、付款、谈案、案情分析、开票或退款申请的客户拒绝删除，避免影响现有业务追踪；不连带删除业务记录。联系人不阻止删除。审计只记录客户编号等安全字段，沿用电话/微信的字段脱敏和访问控制。

## 验收

- 列表查询/重置和操作入口；编辑跳转、回填、取消、可选字段清空、脱敏字段保护、提交版本、电话校验及无权限隐藏。
- 删除确认、成功刷新及页码回退、失败保留；服务/API验证权限、数据范围、版本冲突、关联保护、软删联系人与审计事务回滚。
- 完成相关回归、类型检查、lint、权限迁移和基线检查、构建，记录验证结果；本地业务库仅应用增量权限迁移，不在真实客户数据上执行删除测试。
