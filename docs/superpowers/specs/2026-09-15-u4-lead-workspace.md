# U4：线索与跟进统一业务工作区

日期：2026-09-15；实施前工程契约。承接 SPEC-UNIFIED-OA U4、MOD-004 与 FTN-003/004/005。

## 目标与产品依据

复用已经存在的 LEADS/FOLLOWS 适配器、CollabView/Extension、网格及 BusinessRecord，正式 Lead/LeadFollow 是唯一业务事实。参考[飞书数据表和视图说明](https://www.feishu.cn/hc/zh-CN/articles/472603853615-多维表格的数据表和视图)：左侧数据表、同一数据表多视图共享记录；以下路由与权限规则是承业 OA 自建契约。

## 入口与布局

- /leads 改为线索工作表入口，/leads/follows 为跟进工作表入口。先展示有权访问的已连接业务表，选择后在该业务路由内使用与云盘同一个 WorkspaceEditor（base/table/view/record 参数）。不把旧列表嵌进新框架。左侧只保留全局窄栏和表目录；进入 Base 后仍可切换其中的自定义表，自定义表不会因入口变化被当作正式 CRM 数据。
- 无连接显示真实空态、进入云盘建立工作区的路径；已有可创建业务表的 Base 提供连接业务数据操作，只有有效资源 OWNER 且 canCreate 与 lead.read 满足才允许创建连接，不给普通员工自动授予资源权限。连接只增加表/字段/视图元数据，不复制 CRM 记录。
- /leads/pool 的既有专用领取列表及 /leads/calendar 邀约日历继续保留；在统一表格内补齐领取、回收，员工不必跳转才能完成常规池操作。/leads/:id 保留正式业务详情及转换客户/邀约流程，增加有权业务表定位入口。跨入口始终保留同一 Lead.id。专用邀约/客户转换本批不重写。
- 跟进表关联线索按钮继续进入同一业务详情；线索表记录抽屉包含跟进、历史、分配、状态、领取与回收。额外资源限制可以收紧业务记录范围，旧详情仍按原 CRM 规则授权，不通过资源入口扩权。
- 总表、个人/共享视图、字段展示/扩展、筛选、排序、分组、记录抽屉及并发冲突均复用现有实现。提供一键创建“我负责的”或“我的跟进”个人视图；个人视图按员工负责人或跟进创建账号筛选，不能改变权限。

## 数据与授权

- 有效读取范围 = 原 CRM lead.read 数据范围 ∩ 工作区组织子树 ∩ 资源行范围。协作 SELF 严格是 createdBy=当前账号；CRM SELF 仍是 assignedTo=当前员工，并保留原公海规则。二者取交集，负责人配置 ALL 仍不能绕过原 CRM 业务范围。
- 跟进表的关联字段显示线索编号与名称，原值仍为 Lead.id；标签仅由已授权结果生成，隐藏关联字段时不附带标签。业务状态、池状态及跟进方式显示中文。
- 必填姓名/电话字段隐藏或资源只读时禁用创建；可选微信/意向字段依资源字段限制显示，服务端再次校验。
- 手机/微信按现有字段权限投影；隐藏列不能通过筛选/分组/排序猜测原值，保留敏感查询拒绝和读取审计。
- GET /api/v1/collaboration/business-tables?source=LEADS|FOLLOWS[&recordId=...] 返回当前可访问连接及可连接的 Base；来源与参数严格校验。复用工作区/Base/表 ACL，回收资源和无权表不返回名称；最多展示 200 项，不返回无权资源总数。recordId 仅 LEADS 支持，逐表校验该记录有效范围，用于旧详情的跨入口选择。
- POST /api/v1/tables/:tableId/business-records 创建线索，只有 LEADS、资源可编辑、lead.create 及 lead.read 有效才允许。新记录 branchId 固定当前工作区组织，创建范围必须匹配组织范围、SELF 范围内的本人有效组织身份或 ALL 创建授权；还须拥有新 PUBLIC 记录的组织/ALL 读取范围（仅 CRM SELF 负责人读取无法读取未分配记录，入口因此禁用创建），客户端不能伪造负责人/创建人/组织/状态。姓名、电话、微信、意向、来源类型/说明、标签经过 LeadService 原验证；创建后 PUBLIC/NEW，createdBy 为当前账号。
- 创建使用既有幂等存储、工作区事务锁与 CRM 领域事务；Lead、审计、outbox、业务刷新事件同事务。新入口不使用原电话+创建人近似幂等代替请求幂等；重复提示只返回当前有效范围内的数量，不泄露其他线索 ID。网络重试复用 key，表单变更后新 key。
- CLAIM/RECYCLE 扩展既有记录 business 动作；分别要求 lead.pool.claim/lead.recycle、各动作原数据范围、可写 assignedTo/poolStatus（NEW 领取也要求 status 可写）；CLAIM 要求有效绑定在职员工，RECYCLE 只允许 PRIVATE。事务内锁 Lead，再验证资源/字段/版本，调用原领域服务，不能直接更新状态字段。原 HTTP 调用保持兼容。
- 只读资源不能创建/跟进/领取/回收；通用单元格与批量粘贴不能写正式业务字段。FOLLOWS 为追加业务事实，新增跟进从有权线索动作进入，不伪造未授权 leadId。

## 生命周期、兼容与回退

本批不改 schema，不重置数据库；已有连接继续可用，视图/字段扩展及 ID 不迁移。路由 query 保留定位，入口切换复用编辑器行为；保存草稿、冲突与撤权清理复用现有防护。旧详情、日历、公海继续可达。回退本批代码即可恢复旧线索列表，新创建的真实业务及视图数据不删除。知识库、桌面桥、Harness/Wiki 内部不改动。

## 实施顺序与验收

1. 先本契约，再目录发现/创建/池动作后端及服务测试；再统一业务入口、共享编辑器适配、创建表单和旧详情定位。
2. 真实库验证普通岗位 SELF 与经理 ALL、原业务范围、跨组织/回收/隐藏列、创建幂等、领域事件回滚、领取竞争/过期版本、撤权拒绝；原 CRM 服务回归。
3. Edge 真实 App：管理员连接线索/跟进表；员工从业务入口新建、跟进；经理同源查看；云盘/业务/旧链接同 ID；个人视图保存恢复、扩展字段编辑与双会话冲突；三宽度截图；动作与接口无权测试。
4. 两端 lint/类型/构建、baseline/bootstrap、文档检查；涉及协作业务写路径，按既有 100 会话/900 秒负载契约回归。记录全部结果和限制后本地提交。

## 人工验收路径

1. 管理员在云盘选择已有工作区/Base，配置普通岗位 SELF、负责人 ALL 及各岗位业务动作权限；从业务应用的线索/跟进工作表连接正式数据。连接者需资源 OWNER 权限。
2. 普通员工进入线索工作表新建，检查字段配置、总表、个人视图及记录抽屉。新建需满足本契约的创建及新 PUBLIC 记录读取范围；未授权时按钮禁用，不能靠个人视图扩大范围。
3. 两个员工账号分别录入，检查各自仅见授权记录；负责人检查完整授权范围。领取、分配、跟进、状态、回收按实际岗位能力验证，并用旧记录地址复核接口拒绝。
4. 同时打开云盘与业务入口，修改扩展字段、添加跟进，检查同一 ID 的同步；两人修改同一版本时应提示冲突，不能静默覆盖。刷新后个人视图仍保留。
5. 检查旧详情、公海和日历仍可用；管理员收回资源权限后，列表与已打开记录应失效。开发数据按实际业务使用，不将测试库演练记录导入开发库。
