# SPEC-MD-DELETE-20260911：岗位/员工删除与离职工号复用

状态：已实现并验证，先规格后实现。关联 MOD-001。

## 功能契约

1. 岗位列表提供删除。仅超级管理员可执行，携带 version，确认后删除无任职关联的岗位；存在当前或历史任职时拒绝删除并用中文说明，不能级联删除任职历史。外键约束兜底并发新增任职。
2. 员工列表提供删除档案。仅超级管理员可执行，携带 version 和明确确认；采用逻辑删除（deletedAt），从员工列表和档案入口移除，保留不可变员工 ID、原工号及历史业务关联，不级联删除业务记录。
3. 删除在职员工时结束当前任职、团队成员和本人汇报关系，停用其绑定账号，并释放工号；使用与办理离职一致的交接保护。存在未结束案件、未完成线索、在任下属、组织负责人或团队负责人责任时必须先移交。初始超级管理员和当前操作者绑定的员工不得删除。删除确认明确展示账号停用、任职结束、工号释放及历史保留的结果。已离职员工可删除，无需重复办理离职。
4. 工号唯一性调整为在职员工（status != LEAVED）唯一。办理离职成功即释放工号，原档案仍显示原工号，新员工使用新的员工 ID，历史案件、业绩、审批等关联不能转移给新员工。迁移后已有离职员工工号同样可复用。身份证、执业证等现有独立唯一约束保持不变。
5. PostgreSQL 条件唯一索引保证并发注册同一工号至多一个在职员工成功；失败离职/删除事务不释放工号；权限、版本、关联保护及审计在服务端执行。旧工号全局唯一索引替换为在职条件唯一索引，并保留普通检索索引。
6. 删除档案不可通过普通编辑或调岗恢复。主数据可选员工保持仅在职语义，历史查询继续通过员工 ID 追溯。离职/删除均写入安全审计，不记录身份证/电话等敏感明文。
7. 界面权限同步隐藏非超级管理员的删除按钮；成功后刷新列表，失败保留当前列表并显示明确原因。新增员工工号提示说明在职唯一、离职可复用。
