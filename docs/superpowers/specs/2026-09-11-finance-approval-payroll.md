# SPEC-FIN-APPR-PAYROLL-20260911：团队中文分类、财务案件关联、审批同步和工资表

状态：已实现并验证；先规格后实现。关联 MOD-001、MOD-006、MOD-007、MOD-008、MOD-011、MOD-013。

## 1. 专业团队

团队分类支持 1–100 字符中文文本，去除首尾空白；新增、编辑及分类筛选使用同一规则。保留既有分类值，团队编码仍为稳定编码，不修改其他主数据编码规则。

## 2. 财务管理与案件

- 收款、开票、退款减免归并“财务管理”统一导航及工作区，保留子功能权限、财务状态机、现有单据和旧链接。
- 案件编号为统一业务关联号，精确对应唯一案件；财务显示案件编号/名称，可按案件查询及进入案件详情，案件页提供对应财务入口。内部保留稳定 ID 外键及各单据编号，不用客户名称等模糊信息推断关联。
- 利用已有案件与合同的一对一关系串联收款/开票/退款。默认允许尚未立案的合同先登记财务数据，标记“待关联案件”，立案后自动显示案件编号。不存在/不匹配的指定案件不得误关联；用户若选择必须先立案，再更新该契约。
- 不更改既有财务审批、退款执行和余额约束，不把“审批通过”直接当作已经付款/开票完成。

## 3. 审批结果同步

- 只在最终审批 APPROVED 后同步，多级审批中间节点、驳回及撤回不生成已通过业务数据。实例 ID 是同步去重键，目标记录保留来源审批。
- 报销审批写入成本列表：金额精确到分，原申请类别/事由与来源保留。未知报销类别使用明确的“报销成本”分类，不误归为办公或人工；案件费用使用经校验的案件关联。
- 请假、用印、合同变更、自定义审批进入对应可查询的管理台账，保留审批表单快照和材料关联。调动资料完整且目标经过校验时更新主职；旧表单仅有目标团队文字时标记待补充，不能猜测人员或岗位。
- 工资审批同步工资台账状态。其他自定义审批由管理员配置目标管理台账；未配置时保留可见的待配置记录。不得从任意 JSON 直接执行数据库写入。
- 审批决议和同步状态分别可见。同步失败保留错误原因和可授权重试入口，重试不能重复入账；已有已通过审批可执行幂等补同步。已有审批不擅自修改内容，不静默执行缺少必要参数的合同/人事变更。
- 同步配置、查询及重试实行权限校验，记录安全审计；敏感附件仍按所有者/审批参与人规则读取。

## 4. 工资 Excel

- 绩效管理增加工资表台账：上传 XLSX、保存草稿、重新打开预览/基本编辑、保存修改版、下载当前版本。
- 复用现有 Excel 编辑器，明确保留其已有公式/合并单元格编辑边界；旧 XLS 提示另存为 XLSX，不假装支持无法可靠保存的格式。
- 草稿保存周期、标题、文件及版本，不依赖浏览器临时状态；不同用户不能读取或改动他人的工资文件。
- 从工资表发起审批，选择工资审批流程，提交当前已保存版本；保存与提交期间禁用冲突操作。审批中心可查看同一份材料；提交后该版本冻结，拒绝/撤回后通过副本再申请，保留前次记录。
- 工资审批通过只记为通过/待发放，不自动标记实际发薪或产生真实支付。

## 5. 验证与迁移

先追溯和规格，再分模块实现并补充契约；复用现有服务和文档编辑组件。独立测试库验证中文分类、案件关联/权限、审批终态同步/去重/失败/重试、工资权限及附件冻结；前端验证入口、上传编辑保存下载和发起审批。执行相关类型、lint、构建和真实浏览器文档交互检查。迁移通过后备份并更新本地开发库，保留真实记录。

## 6. 补充落地约束

未关联合同的已有案件增加“关联财务合同”操作：仅 case.update 且可读取目标合同的用户可操作，同一客户、合同未删除且未被其他案件占用，版本校验；已关联后不允许直接改绑。案件编号及合同的一对一关系不变。工资上传复用审批附件权限，要求绩效创建/更新及 approval.apply；工资流程动态表单按配置补填后提交。自定义同步配置只影响尚未成功同步的记录，已入账记录不得改道重复入账。

## 7. 使用入口与边界

- 财务管理：保留 `/payments`、`/invoices`、`/refunds`，统一工作区 `/finance`；案件编号精确查询，各子功能维持原权限。案件未关联合同时通过案件列表的“关联财务合同”补关联，不改案件编号。
- 审批业务台账：`/approval-ledger`，按报销、请假、用印、合同变更、调动、工资及自定义业务筛选；员工页和合同页提供对应入口。所有已通过记录可见，历史无同步记录可由管理员逐项补同步。通用管理台账保留原表单和材料，不自动改写缺少结构化业务指令的合同。
- 工资表：绩效管理 → 工资表。仅 XLSX，单文件不超过 10 MB。编辑保留原件并生成新文件版本，草稿数据库保存，提交锁定文件与批次版本。工资流程其他必填字段按流程配置补填。审批参与人/授权审批管理员可读已提交材料。
- 预置 PAYROLL 流程按 FINANCE 角色分配；本地该角色尚无成员，需指定实际审批人；不擅自选择申请人自审。
- 旧调动申请只有 targetTeam 文字时保留待处理说明。自动变更主职需申请人的已绑定员工及 organizationId、positionId、employeeVersion，且同步操作人具有任职管理权限和相应数据范围。
