## 26 份失败资料

全部位于“法律法规库”（原生名称“医疗法律知识库”），错误相同：`UNIQUE constraint failed: chunks.seq_id`。

SQLite 单连接只能串行执行单条 SQL，原逻辑先读取最大编号、再插入分块，两步之间可被其他解析任务插入。修复为在同一事务内分配编号并插入，保持单连接占用至提交。

源代码在提供时已有大量未提交改动的独立 WeKnora 仓库中，因此没有整体提交该仓库。主仓库保存精确补丁：`deploy/integration/weknora-patches/sqlite-chunk-allocation.patch`，含 26 路并发回归测试。补丁已在本次修改前的源码副本上应用验证。后续重建 WeKnora 必须保留此补丁。

本次已完成：

1. 使用 SQLite backup API 备份在线数据库，保留旧可执行文件。
2. 构建修复后的 WeKnora，仅重启 `oa-smart-knowledge.service`；没有重启承载 AI 会话的 `oa-smart-case.service`。
3. 使用 `deploy/integration/retry-failed-knowledge.mjs` 串行重试预先识别的 26 份编号冲突资料。脚本默认只检查，执行必须显式指定预期数量和私有审计报告路径。
4. 26/26 解析完成，有分块，修复前后原文 SHA-256 一致，没有删除、重新上传或发布这些历史资料。
