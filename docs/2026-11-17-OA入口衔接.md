# OA 入口衔接优化

`GET /api/auth/start?response=json` 新增 JSON 准备模式，返回 challenge；verifier 仍只存于 120 秒 HttpOnly、SameSite=Lax Cookie，案件入口参数仍通过 oa_case 保存。该响应禁止缓存并禁止携带来源页面信息。普通请求仍按原方式重定向至白名单 OA 地址。一次性 code 交换、verifier 检查和后续用户/权限验证不变。

OA 入口先验证当前 OA 身份和权限，再核对 `/api/me` 的 oaUserId，仅同一有效账号复用现有会话。首次登录或身份不匹配时申请准备信息和一次性凭证；新版 JSON 模式无需再次请求 OA HTML。旧服务兼容路径通过 fetch 跟随重定向，读取经过白名单及路径校验的 challenge，不执行返回页面。

验证：`node --test case-service/test/entry-handoff.test.js case-service/test/harness-experience.test.js` 共 3 项通过，覆盖返回地址白名单、HttpOnly verifier、JSON challenge、案件参数、原跳转模式以及缺少 verifier 的回调拒绝。

为了不影响线上 AI 任务，本轮没有重启智慧办案后端。因此该 JSON 模式尚未加载到线上进程；OA 已启用并验证兼容路径，同账号再次进入不签发新会话。完整 OA 验证说明位于 ChengyeOA 仓库 `docs/2026-11-17-智慧办案入口优化.md`。本轮仅本地提交，不推送 GitHub。
