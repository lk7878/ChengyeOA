# 智慧办案自身会话退出修复

排查 OA 退出问题时，发现智慧办案也会在进入注销逻辑之前验证业务权限；失去授权或过期的会话无法清除，前端还会忽略失败而显示已退出。

调整为：可信 Origin 下的两个 POST 退出入口直接读取当前 oa_sid 对应记录，调用 OA token 自身撤销接口，再删除本地会话记录并过期所有衔接 Cookie。不依赖 `/smart-case/me` 或菜单权限。其他业务请求仍按原有身份/权限校验执行。远端撤销或本地存储失败不返回成功、不清除 Cookie，允许重试。无会话退出幂等成功。

前端仅在服务端成功后清空用户状态；失败显示“退出未完成”，并提供原入口重试，执行期间禁用重复点击。

`node --test case-service/test/logout.test.js case-service/test/entry-handoff.test.js case-service/test/harness-experience.test.js` 4 项通过；工作台构建通过，产物位于 `/opt/oa-system/releases/20261117-logout/work-ui`。

本轮用户确认的实际报错发生在 OA，OA 修复已生效。此处补充修复仅完成本地提交及构建，未重启智慧办案服务或发布工作台包，避免影响运行中的 AI 任务；后续正常发布时与已提交的 JSON 身份衔接接口一起启用。未推送 GitHub。
