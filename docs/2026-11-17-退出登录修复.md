# OA 自身会话退出修复

用户确认报错入口为 OA 右上角账号菜单的“退出登录”。

## 原因与处理

前端原来优先使用模块内缓存的 CSRF 值。其他标签页 bootstrap/刷新登录会轮换共享 Cookie，原标签页仍发旧值，退出接口返回 `CSRF_INVALID` 403；通用错误映射又显示成“没有权限执行此操作”。隔离 HTTP 测试已复现此响应。现在每次请求优先读取当前 Cookie，401 刷新后的重试也更新 CSRF 头；明确区分 CSRF 提示与业务权限不足。

退出原来依赖有效访问凭证和完整授权上下文。现在自身退出接口自行验证凭证，仅允许撤销该凭证所属会话：签名、类型、用户与会话归属仍校验；只有退出验证允许已过期 JWT，普通访问仍严格检查有效期。没有访问凭证时可通过当前 HttpOnly refresh 凭证定位自身会话。其他账号的 sessionId 请求参数不能指定退出对象。

若当前访问凭证与共享 refresh Cookie 属于不同会话，返回 `LOGOUT_SESSION_CHANGED`，不撤销任何一方，也不清除 Cookie；提示刷新确认账号。退出请求不再自动刷新成另一个账号后重试。服务端撤销成功后才清除浏览器凭证，失败保留重试。已无任何 Cookie 的退出仍要求可信 Origin，只能凭明确提供的签名凭证撤销自身会话，或幂等结束。

智慧办案自身 token 注销同样不再依赖 `menu.smart_case`；只有持有合法格式的强随机 token 才可撤销对应 token，其他业务接口的权限和有效期检查不变。

## 验证

- Web 4 个测试文件，25 项通过：多标签 CSRF、刷新后重试、退出失败保留状态、错误处理等。
- OA 聚焦 HTTP/CSRF/身份测试 8 项通过；原有登录及 session-service 回归 24 项、token-service 5 项通过。
- 智慧办案退出、入口衔接与角色代理回归 4 项通过。合计 66 项。
- 覆盖普通用户成功注销及 refresh 不可复用，过期/停用/无业务权限退出，重复退出，伪造凭证、恶意来源、跨账号混合凭证拒绝，以及退出后重新登录。
- 两项目相关类型检查、lint 和构建通过；OA Web 保留原有大包提示。
- 线上 OA 源码已提供 Cookie 优先逻辑；不携带任何账号凭证的幂等退出探针返回 200。未注销真实账号，未停止 AI 任务。
