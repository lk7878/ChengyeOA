# 员工离职交接与删除

入口：员工管理列表的“离职交接 / 删除”；超级管理员在员工详情点击“办理离职”也进入同一流程。

## 操作流程

1. **暂停账号使用**：立即停用绑定账号、撤销现有会话并更新凭证版本。员工任职、业务责任、档案和材料保持原状；没有绑定账号的员工无需执行此步。
2. **核对交接清单**：显示未结案件的编号、名称、状态及入口；未完成线索；在任下属；组织和专业团队负责人职责。处理后点击“刷新交接清单”。已删除及已转化/流失的线索不再误拦截。
3. **登记离职完成**：选择日期并确认离职手续已完成。绑定账号须已暂停，交接清单须为空。这里是人事确认步骤，不自动代替外部审批流程。
4. **转交材料并删除**：优先选择主职组织配置的部门负责人账号；负责人缺失、为员工本人、已离职或账号不可用时提示人工指定接收人。移交包含未分享和回收站内的自有文档及其他已有资源移交范围。
5. **同时删除登录账号**：默认勾选有账号的员工；仅已离职、账号已暂停且资源移交成功时可完成。账号从管理列表移除且不能再启用；底层以 `DELETED` 状态保留账号标识，避免破坏历史业务和审计引用。用户名仍保留，避免误关联历史记录。

案件、线索、汇报关系和负责人职责须在各自模块完成移交；不能通过勾选确认跳过后端校验。材料移交和档案/账号删除处于同一事务，失败整体回滚。保留原先仅删除员工档案、停用绑定账号的选项。

## 权限与记录

交接总览、暂停及员工删除沿用超级管理员管理边界。普通业务角色无法通过新增接口获取跨模块关联明细。本人、系统信任根及系统管理员账号保护仍生效，受保护管理员须通过既有治理流程处理。

暂停、离职、删除及材料移交结果记录审计，不写入材料内容。实际员工只做只读核对，没有自动处理其关联事项。

## 验证

- 隔离数据库：员工服务、主数据接口、授权接口以及总分所 16 身份矩阵，共 36 项通过。
- 前端验证涵盖阻塞案件明细、处理链接、删除禁用、暂停账号、负责人默认接收和阶段控制。
- 实际网页只读验收确认关联案件可见、存在阻塞时无法删除，以及普通角色被拒绝访问交接总览。
- 前后端类型检查、相关代码检查和前端生产构建通过。生产构建仍有原有大文件体积提示。
