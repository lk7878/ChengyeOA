# 可视化审批（2026-10-30）

入口：审批中心 → 可视化审批，或 `/approvals/visual`。多维表格工具栏的“发起审批”可带入当前表和选中的一条记录。

## 配置与使用

1. 在“流程设计”中新建流程，按“基础信息—表单设计—流程设计—更多设置”配置。基础信息包含名称、分组、申请说明和提交范围；指定成员与角色取并集，仍须拥有申请权限。设置不允许提交后，流程不出现在申请目录中，直接调用提交接口也会被拒绝。
2. 表单设计器支持拖入或点击控件、排序、复制和删除。画布显示实际控件效果，属性提供提示文字、字段说明、条件显示/必填和打印开关。明细支持横向/纵向排列。预览可试填，附件不上传、关联记录不发请求。
3. 默认使用竖向流程图。连接处“＋”可插入审批、抄送和条件分支，自动接上原路径。分支的条件路径、默认路径可分别配置。“高级连线编辑”保留自由拖动和手工连线，用于复杂结构修正。
4. 点击节点，分别配置人员、表单权限和操作权限。人工审批支持指定成员、角色、部门负责人、连续主管、发起人自选、表单联系人和发起人本人，以及会签/或签/依次审批。节点可显式设置自动同意或自动驳回，执行记录会进入审计日志。
5. 表单权限支持节点默认、角色覆盖和批量设置，多角色冲突时隐藏优先于只读、只读优先于可编辑，计算字段始终只读。操作权限可限制转办、加签、退回，或要求同意时填写意见。服务端同步校验，驳回/退回原因始终必填。
6. “更多设置”配置撤回、更正、打印、最多6个摘要字段，以及多维表格回写和自动化接口。预览检查后保存草稿或校验发布；未保存修改会提示。草稿不能发起，停用不取消已有申请。
7. 用户从“发起审批”选择流程并按说明填写；待办中可处理、查看摘要与审计历史。详情按当前账号可见字段生成打印预览，支持浏览器打印或保存PDF，不打印隐藏字段及关闭打印的字段。

流程的每次发布产生一个新版本。申请保存发布版本的完整快照，后续修改不改变运行中实例。页面采用手动刷新，避免覆盖正在编辑的内容。

## 权限与业务数据

沿用现有角色权限，不自动给任何账号授权：

| 权限 | 用途 |
| --- | --- |
| `approval.read` | 进入页面、查看本人参与的申请与可见附件 |
| `approval.apply` | 发起、重新提交、撤回本人申请 |
| `approval.process` | 处理分配给自己的当前待办 |
| `approval.manage` | 配置发布流程、监控全部实例、查看完整审计内容 |

人工处理人必须是启用账号，且具备查看和处理审批的权限。角色处理人按有效角色任期解析；部门负责人依赖发起人的有效任职组织负责人，连续主管依赖员工汇报关系。缺少有效处理人时返回明确错误，不跳过必需审批。选择发起人本人作为审批人时，该账号也须有处理审批的权限。

通过后回写使用**回写时重新加载的发起人有效表格及业务权限**。审批权限不代替表格读写权限；只读字段、数据范围及业务状态约束仍生效。普通自建表支持新增记录，正式业务表使用已有记录更新，新增正式业务仍从对应业务模块办理。

回写会校验记录版本和表结构版本。原记录被别人修改、权限撤销或字段调整时，显示“审批通过、同步失败”，保留审批记录，不静默覆盖数据。发起人或审批管理员核对后可重试；更新已有记录的重试需要确认当前记录版本。表结构版本变更需要按新配置重新发起，不自动绕过校验。

## 控件及流程范围

- 基础控件、人员、业务记录关联、单层明细、金额大写、公式。附件支持经服务端验证的 PDF、PNG、JPEG、WebP、DOCX、XLSX，单文件不超过 10MB。
- 条件支持等于、不等于、大小比较、包含、不为空；可控制显示、必填和分支。
- 公式支持数字加减乘除、求和和明细数字列合计，不运行任意脚本。基础正则支持字符集、锚点和单次量词，不支持分组、交替和回溯引用。
- 单流程最多80字段、80节点、160连线；明细最多200行；连续主管最多10层。流程连线不能成环，回退使用“退回”。分支按优先级从小到大匹配，同优先级按连线顺序；每个分支必须有唯一默认路径。组内条件为“并且”，组间为“或者”；支持明细数字列合计。每条路径最多20组，每组最多20个条件。
- 超时需管理员显式配置，默认不自动同意。每分钟扫描；提醒按任务和日期去重。权限失效或必填项未满足时，自动同意失败并通知发起人，不放行。
- 同意意见必填的节点不能配置超时自动同意。退回或修改表单后，本次申请不再沿用“同人跳过”，避免对变更内容复用旧审批结果。

## 已通过申请的更正

按本轮确认，已通过的原单保持只读，不直接撤销或覆盖。发起人可在详情点击“提交更正申请”，沿用原单表单、流程及版本重新审批，原单与更正单分别记录历史。更正只能由原发起人提交，并受当前及原流程提交范围、流程启用状态约束。

更正通过前，表格保持原值；通过后更新同一条原记录。原流程即使使用“新增记录”，更正时也改为更新其生成的那条记录。提交时捕获当前表格版本，审批期间别人修改过记录会触发回写冲突。原单有回写异常时须先解决异常再更正。

同一原单仅能有一条处理中或已通过的后继更正，重复点击使用幂等校验、并发提交受锁保护。更正被驳回或撤回后可重新申请；更正已通过后，应从最新更正单继续更正。每次通过均重新检查发起人业务权限，不绕过字段或业务规则。

## 与参考截图的范围区别

本轮参照四步配置、控件画布、节点插入、提交范围、条件组合、操作权限、摘要、打印和更正流程进行优化。现有人员来源、明细、会签和数据回写继续使用OA自己的权限体系。并行分支、办理人独立节点、审批组、手写签名、代他人提交、批量审批和自定义打印模板未作为可选功能开放；明细权限目前按整块控制。不会展示未接入执行逻辑的按钮。

## 自动化接口

服务端可选环境变量 `WORKFLOW_WEBHOOKS` 是 JSON 对象，键为接口名称，值包含 `url`（HTTPS且不含用户名密码）和 `secret`（至少32字符）。密钥只存服务端；界面仅显示配置名称。未配置时不发送任何外部请求。

审批通过、驳回或撤回时生成持久投递任务。只发送 `event=workflow.completed`、实例ID、流程ID、流程版本、最终状态、同步状态和结束时间，不发送表单内容或附件。接收方必须按最终状态决定后续动作，按投递ID幂等处理；需要业务内容时应通过另行授权的OA接口读取。

请求头：`X-Workflow-Delivery`、`X-Workflow-Timestamp`、`X-Workflow-Signature`。签名为共享密钥对 `timestamp.deliveryId.rawBody` 的 HMAC-SHA256 十六进制结果。接收方需验证签名、时间窗口并去重。请求超时10秒，不跟随重定向，失败最多重试8次并记录状态。投递采用至少一次语义，接收方不能依赖只收到一次。

邮件发送、外部账号开通等由实际接收服务实现和授权，本轮没有配置或调用真实第三方系统，也没有自动新增账号。

## 部署与验收

首次部署使用迁移 `20261029090000_visual_workflows`，只增加6张工作流表。2026-10-30优化使用兼容的JSON配置扩展，无新数据库迁移；保留已有审批快照、业务数据、账号、权限和字段配置。更新代码后重启后端即可。

服务层测试覆盖表单校验、发布版本、条件分支、多人并发、会签/或签/顺序流转、转办加签退回、字段和附件权限、表格回写冲突、权限撤销、附件映射、超时、接口重试及主管关系。前端测试覆盖设计器保存、非法流程拦截、条件显示、只读字段、明细和公式。所有数据库测试必须使用隔离测试库；浏览器界面验收使用模拟表单，不向正式业务库录入示例申请。

人工测试建议先由管理员创建一个普通测试表及小额申请流程，给两个测试角色分别分配发起、审批和对应表格权限；确认通过后回写，再分别验证无权账号、退回补充、版本修改和回写冲突。
