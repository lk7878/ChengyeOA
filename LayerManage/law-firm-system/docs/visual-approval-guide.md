# 可视化审批（2026-10-29）

入口：审批中心 → 可视化审批，或 `/approvals/visual`。多维表格工具栏的“发起审批”可带入当前表和选中的一条记录。

## 配置与使用

1. 在“流程设计”中新建流程。表单设计器支持拖入或点击控件、拖动排序、上下移动和字段属性设置。
2. 在流程画布添加审批、抄送、条件分支和结束节点，拖动位置；点击节点右侧连接点再点击目标左侧连接点，或使用上方起点/终点选择框连线。
3. 配置审批人、会签/或签/依次审批、超时规则，以及各节点和角色的字段权限。多角色权限冲突时，隐藏优先于只读，只读优先于可编辑。计算字段只读。
4. 按需设置数据联动目标表和字段映射。在表单预览中检查效果，再“校验并发布”。草稿不可发起；停用阻止新的申请，但不取消已经运行的申请。
5. 用户发起后，在“待我审批”处理，同意、驳回、退回、转办或加签；发起人可以撤回或在退回后重新提交。任务中心提供我发起的、我已审批、抄送我的；管理人员可查看全部审批、日志、节点耗时、超时和回写失败数量。

流程的每次发布产生一个新版本。申请保存发布版本的完整快照，后续修改不改变运行中实例。页面采用手动刷新，避免覆盖正在编辑的内容。

## 权限与业务数据

沿用现有角色权限，不自动给任何账号授权：

| 权限 | 用途 |
| --- | --- |
| `approval.read` | 进入页面、查看本人参与的申请与可见附件 |
| `approval.apply` | 发起、重新提交、撤回本人申请 |
| `approval.process` | 处理分配给自己的当前待办 |
| `approval.manage` | 配置发布流程、监控全部实例、查看完整审计内容 |

处理人必须是启用账号，且具备查看和处理审批的权限。角色处理人按有效角色任期解析；部门负责人依赖发起人的当前主职及组织负责人，连续主管依赖员工汇报关系。缺少有效处理人时返回明确错误，不跳过必需审批。

通过后回写使用**发起人当时的有效表格及业务权限**。审批权限不代替表格读写权限；只读字段、数据范围及业务状态约束仍生效。普通自建表支持新增记录，正式业务表使用已有记录更新，新增正式业务仍从对应业务模块办理。

回写会校验记录版本和表结构版本。原记录被别人修改、权限撤销或字段调整时，显示“审批通过、同步失败”，保留审批记录，不静默覆盖数据。发起人或审批管理员核对后可重试；更新已有记录的重试需要确认当前记录版本。表结构版本变更需要按新配置重新发起，不自动绕过校验。

## 控件及流程范围

- 基础控件、人员、业务记录关联、单层明细、金额大写、公式。附件支持经服务端验证的 PDF、PNG、JPEG、WebP、DOCX、XLSX，单文件不超过 10MB。
- 条件支持等于、不等于、大小比较、包含、不为空；可控制显示、必填和分支。
- 公式支持数字加减乘除、求和和明细数字列合计，不运行任意脚本。基础正则支持字符集、锚点和单次量词，不支持分组、交替和回溯引用。
- 单流程最多80字段、80节点、160连线；明细最多200行；连续主管最多10层。流程连线不能成环，回退使用“退回”。分支按条件连线顺序匹配，必须有唯一默认路径。
- 超时需管理员显式配置，默认不自动同意。每分钟扫描；提醒按任务和日期去重。权限失效或必填项未满足时，自动同意失败并通知发起人，不放行。

## 自动化接口

服务端可选环境变量 `WORKFLOW_WEBHOOKS` 是 JSON 对象，键为接口名称，值包含 `url`（HTTPS且不含用户名密码）和 `secret`（至少32字符）。密钥只存服务端；界面仅显示配置名称。未配置时不发送任何外部请求。

审批通过、驳回或撤回时生成持久投递任务。只发送 `event=workflow.completed`、实例ID、流程ID、流程版本、最终状态、同步状态和结束时间，不发送表单内容或附件。接收方必须按最终状态决定后续动作，按投递ID幂等处理；需要业务内容时应通过另行授权的OA接口读取。

请求头：`X-Workflow-Delivery`、`X-Workflow-Timestamp`、`X-Workflow-Signature`。签名为共享密钥对 `timestamp.deliveryId.rawBody` 的 HMAC-SHA256 十六进制结果。接收方需验证签名、时间窗口并去重。请求超时10秒，不跟随重定向，失败最多重试8次并记录状态。投递采用至少一次语义，接收方不能依赖只收到一次。

邮件发送、外部账号开通等由实际接收服务实现和授权，本轮没有配置或调用真实第三方系统，也没有自动新增账号。

## 部署与验收

新增迁移 `20261029090000_visual_workflows` 只增加6张工作流表；保留既有审批、业务记录、账号、权限和字段配置。部署前备份数据库，然后运行 `prisma migrate deploy`、生成 Prisma 客户端并重启后端。

服务层测试覆盖表单校验、发布版本、条件分支、多人并发、会签/或签/顺序流转、转办加签退回、字段和附件权限、表格回写冲突、权限撤销、附件映射、超时、接口重试及主管关系。前端测试覆盖设计器保存、非法流程拦截、条件显示、只读字段、明细和公式。所有数据库测试必须使用隔离测试库；浏览器界面验收使用模拟表单，不向正式业务库录入示例申请。

人工测试建议先由管理员创建一个普通测试表及小额申请流程，给两个测试角色分别分配发起、审批和对应表格权限；确认通过后回写，再分别验证无权账号、退回补充、版本修改和回写冲突。
