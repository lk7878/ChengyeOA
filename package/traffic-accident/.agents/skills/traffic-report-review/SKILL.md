# 交通事故鉴定意见审核

已出现本文件的 `<skill_content>` 后禁止再加载。一份意见书出一份审核意见。同一事故有多份意见书、用户没指定审哪一份时，先 `ask_user`。

## 步骤

1. 读被审文书。扫描件走 `parse_records`，可复制文本走 `convert_file`。记下它自己写的委托事项、引用标准和结论句。
2. 用 `traffic-appraisal-plan` 里的对照表，看它选的主标准是否对应该委托事项。标准名称和编号互相矛盾时，写入审核结论。
3. 同一轮 `weknora_search` 检索它引用的那一部标准，query 写标准全称加它引用的条款号或方法名称。未命中的条款写「条款未能核实」。页面图片、英文摘要和乱码不能用来支持或否定条款。不要用别的标准补一条相反结论。
4. 写入 `reports/交通事故鉴定审核意见.md`，然后 `present`。

## 只审这些

- 委托事项与主标准是否匹配。速度、痕迹、图像重建、信号灯、设施、火灾、行为方式是否被混在一个结论里。
- 方法前提是否写了：记录仪或 EDR 的数据来源、视频的帧率与参照物、痕迹的种类、设施状况与设计规范是否被当成同一件事。
- 结论是否超出检索到的条款。行为方式意见如果写成了事故责任比例，记为超出标准。
- 数值是否能从文书给出的原始数据按所引公式得到。公式或原始数据缺失时，指出不能复核，不要另算一个速度。
- 论证是否跳步、把「不能认定」写成「可以排除」、或把范例数值抄进本案。写法对照 `traffic-report-writing` 的 `references/review-checklist.md`，不要为此再加载该技能，也不要把范例结论写进审核结论。

错别字、明显的 OCR 断行，写入「潜在风险提示」，并注明「可能为 OCR 识别问题，请人工审查」。这些不单独构成审核结论。

## 章节

审核结论先写符合或不符合，再写理由。正文不用表格。

1. 被审文书：文件名、委托事项、文书自述的标准。
2. 标准是否用对。
3. 方法与条款复核。每条末尾【出处：《标准名》条款号】；没检索到则写条款未能核实。
4. 审核结论。只评价该文书是否符合它所依据的标准，不另作事故责任认定。
5. 潜在风险提示。没有则写「无。」
